* 黑灯实验室重点解决无人值守执行和连续运营。

Agent层的关键也不只是自然语言生成，而是把推理与行动结合起来，让模型能够选择和调用工具、利用环境反馈修正计划并积累经验。ReAct、Toolformer和Reflexion分别代表推理—行动交织、工具学习与反思记忆等重要路径；MCP负责Agent与工具、数据源和工作流连接，A2A则处理异构Agent之间的通信与协作。([OpenReview][3])

真正制约黑灯实验室规模化的通常不是某一台机器人或某一个大模型，而是端到端系统能否同时做到：设备互操作、机器可执行协议、测量校准、数据语义、完整溯源、异常恢复、模型不确定性管理和统一绩效评价。SiLA 2等标准重点解决设备能力和命令接口；FAIR原则要求数据以及产生数据的算法、工具和工作流可发现、可访问、可互操作、可复用；SDL评价还需要报告自主度、运行时间、参数空间、精度、吞吐、成本与优化表现。([sila-standard.com][4])

# 一、把两种模式统一成同一个科学决策问题

建议不要把迁移发现和闭环优化做成两套割裂系统，而是共享一个“部分可观测科学决策模型”。

真实但不可见的材料状态为：

[
z={\text{水合状态、酸分布、界面状态、微结构、老化状态、接触状态}}
]

系统能观察到的是：

[
y={Z(\omega,T),\text{热史、湿度、批次、几何、工艺、失败标签}}
]

智能体维护的不是一个“确定答案”，而是对潜在状态和竞争假设的信念分布：

[
b(z,H\mid D)
]

下一实验统一按以下效用选择：

[
a^*=\arg\max_a
\left[
\lambda,\mathrm{EIG}(H;Y\mid a,D)
+(1-\lambda),\mathbb{E}[\Delta HV]
-\beta C(a)-\gamma R(a)
\right]
]

其中：

* **迁移发现模式**提高 (\lambda)，优先选择最能区分竞争假设的实验；
* **闭环优化模式**降低 (\lambda)，优先改善多目标性能；
* (C(a)) 是实验成本；
* (R(a)) 是失败、越界和不可解释风险；
* 两种模式都使用同一套EIS质控、行为指标、证据门禁和记忆系统。

这比“迁移线用LLM、优化线用BO”更有研究价值，因为它把两者统一为：

> **在部分可观测、带噪声和高成本条件下，如何选择最有科学价值的下一实验。**

# 二、不要把单点电导率作为共同目标

建议把材料描述成一个统一的“传导行为向量”：

[
B=
[
\log\sigma(T_k),
AUC_{LT},
R_{LT},
E_a,
w_{\mathrm{Arr/VTF}},
T^*,
H_{\mathrm{thermal}},
D_{\mathrm{cycle}},
R_{\mathrm{batch}},
Q_{\mathrm{EIS}},
P_{\mathrm{feasible}},
C
]
]

核心组成包括：

| 层次     | 共同指标                              |
| ------ | --------------------------------- |
| EIS有效性 | 热平衡、线性、时间稳定性、KK/lin-KK一致性、频率窗充分性  |
| 传导行为   | 预定义温度锚点的电导率后验、低温曲线面积、低温保持率        |
| 温度模型   | Arrhenius、VTF、分段模型权重，变点概率与温度区间    |
| 稳定性    | 升降温滞后面积、循环漂移、恢复率                  |
| 复现性    | 批内重复性、独立批次复现概率                    |
| 可行性    | 可成膜、可装夹、可获得有效谱的概率                 |
| 科学可信度  | 主张—证据完整率、引用忠实率、无证据主张率             |
| 智能体校准  | Brier score、区间覆盖、选择性风险和拒答效用       |
| 优化效果   | simple regret、Pareto超体积、每个确认改进的成本 |

这样，迁移发现评价“预测签名是否出现”，闭环优化评价“行为向量是否改善”，不会出现两条线使用不同科学语言的问题。

# 三、迁移发现模式的推荐流程

### 1. 从“材料相似性”升级为“可迁移因果母题”

从酸–黏土文献中提取的重点不应只是“某材料与某材料相似”，而应是：

* 质子供体密度；
* 含水与低温水保持；
* 氢键网络连续性；
* 酸的固定和迁移；
* 黏土限域；
* 聚合物—黏土界面贯通；
* 聚合物链段运动；
* 冻结或相变抑制；
* 电极接触和几何伪影。

A-Lab类系统说明了文献知识、历史数据、机器学习、主动学习和实验反馈可以共同组成闭环，并且失败实验本身应当产生可行动的信息。([Nature][2])

### 2. 为每次跨体系推理建立“桥接假设”

例如：

> 酸–黏土体系中的低温传导现象能够迁移到淀粉–黏土膜。

不能作为一个整体假设。应拆成：

1. 生物聚合物能够保持足够的质子供体或酸；
2. 低温下仍存在连续的含水/氢键网络；
3. 聚合物不会切断黏土界面的传导连通性；
4. 制膜和调理过程不会造成不可逆脱水；
5. EIS中的变化不是接触或几何伪影。

每一个桥接假设都要有：

* 支持文献；
* 适用条件；
* 预测的EIS签名；
* 失败反例；
* 可推翻它的实验。

### 3. 把机理文字编译成实验前预测

例如某假设必须提前给出：

* 哪些温度锚点会发生变化；
* 是否预计存在变点；
* 升温和降温是否应重合；
* DRT或谱形应出现什么变化；
* 哪些材料应为正例；
* 哪些结构相似材料反而应该失败；
* 失败后否定的是哪一条桥接假设。

然后冻结预测，禁止实验结果出来后重新改写解释。

### 4. 候选组合不能只选“最看好的”

建议每轮组合同时包含：

* 预测正例；
* 结构相近但应失败的对抗性反例；
* 母体系对照；
* 空白或过程对照；
* 一个用于检验智能体是否在泛化式讲故事的候选。

这样藕粉、普通淀粉和壳聚糖不只是候选材料，而是具有明确假设功能的对照组。

# 四、闭环优化模式的推荐升级

## 代理模型应至少拆成三个

1. **性能模型**：预测完整传导行为向量；
2. **可行性模型**：预测可成膜、可装夹、能否获得有效谱；
3. **测量质量/失败模型**：预测漂移、未平衡、接触失效等风险。

不要把失败实验删除，也不要简单赋予一个极低电导率。失败本身是关于实验空间边界的重要数据。

## 推荐模型

在现有样本量下，优先考虑：

* 异方差高斯过程；
* 混合变量和混料约束；
* 多输出或多任务模型；
* 批次、日期、原料批号、热史作为上下文；
* 历史酸–黏土知识只作为可检验先验，不能作为事实标签；
* 分组或时间外验证，禁止普通随机拆分造成批次泄漏。

噪声会显著影响材料发现中的BO表现，代理模型需要同时表达信息不足和观测噪声，并在探索与利用之间分配实验。([皇家化学学会出版][3])

## 大模型的正确位置

大模型负责：

* 从文献生成有依据的先验；
* 建议变量、约束与候选解释；
* 检查与历史失败的冲突；
* 解释为什么推荐某实验；
* 识别需要人工审批的情况。

大模型不负责：

* 手算采集函数；
* 修改实测数据；
* 绕过硬约束；
* 直接选择一个“看起来最好”的配方；
* 直接向仪器发送未经验证的指令。

采集函数必须由可复算的数值代码产生，LLM只能在受控范围内审查或解释数值候选。

## 自适应重复

不要对所有实验做等量重复。应当在以下情况增加重复：

* 候选位于Pareto前沿；
* 两个候选排序接近；
* 偶然噪声大于知识不确定性；
* 结果与历史模型严重冲突；
* 即将进入独立确认阶段。

若主要是认知不确定性，则应探索新配方，而不是反复测同一点。

# 五、智能体应采用“受控编排器”，而不是堆很多Agent

推荐七层结构：

1. **证据与知识层**：文献、材料、样品、协议、反例和适用域；
2. **假设与主张层**：桥接假设、预测签名、竞争解释；
3. **策略路由层**：决定当前偏重假设判别还是性能优化；
4. **数值决策层**：层级贝叶斯、EIS模型比较、BO；
5. **实验执行层**：协议编译、前置检查、仪器调用和回滚；
6. **EIS质控与推断层**：有效性、模型比较、不确定度传播；
7. **科学记忆与治理层**：记忆、验证器、校准、审计和人工审批。

你们已经做好的记忆、自我检查和可靠性校准，应立即接入主流程，而不是继续作为旁路演示。

建议采用三种类型化记忆：

* **情景记忆**：每轮发生了什么、做了哪些选择、为什么失败；
* **语义记忆**：主张、证据、反例、桥接假设和适用条件；
* **程序记忆**：SOP、EIS分析流程、失败恢复策略和工具能力。

置信度必须在实验前记录，并用实验结果计算Brier score、log loss和可靠性曲线。不要使用模型实验后的自我评价代替校准。现有科学智能体基准也表明，端到端能力不能靠一次展示判断，需要对工作流中的每个任务做细粒度评测。([OpenReview][4])

# 六、必须实施的结论门禁

| 等级 | 可允许的主张                  |
| -- | ----------------------- |
| C0 | 数据无效，只报告失效原因            |
| C1 | 某条件下得到某EIS或电导率区间        |
| C2 | 某行为在独立批次下可复现            |
| C3 | 数据更支持某经验温度模型或传导区间       |
| C4 | 数据与某机制的预注册预测一致，但仍保留替代解释 |
| C5 | 通过结构证据与因果干预确认微观机制       |

当前系统默认只能到 **C4**。

每一条主张都必须输出：

* 主张等级和状态；
* 实验与文献证据ID；
* 配方、批次、温湿度和热史；
* 效应量与区间；
* 竞争模型权重；
* 替代解释；
* 可推翻该主张的结果；
* 适用域；
* 校准后的智能体置信度；
* 独立验证器结果。

状态只能是：

**Supported / Refuted / Inconclusive / Invalid**

尤其要允许系统输出“Inconclusive”。在你们的场景中，可靠地知道“现有数据无法区分两个解释”，本身就是高价值科学结果。

# 七、怎么证明这套系统真的有效

建议做四类严格比较：

| 验证       | 核心设计                                      |
| -------- | ----------------------------------------- |
| 历史数字回放   | 按时间和批次隐藏未来数据，让系统重做当时的实验选择                 |
| 前瞻迁移挑战   | 实验前冻结候选、正反例、预测签名和结论门槛                     |
| 固定预算优化比较 | 随机/LHS、传统DOE、BO-only、LLM-only、LLM+BO、完整系统 |
| 消融实验     | 分别去掉记忆、验证器、校准、负结果和自适应重复                   |

主要评价：

* 误支持科学主张的概率；
* 区间覆盖和置信校准；
* 正反例判别；
* 独立批次确认率；
* fixed-budget simple regret；
* Pareto超体积；
* 每个确认改进的实验成本；
* 人工干预率；
* 端到端确定性回放率。

自驱动实验室不应只报告“找到最好结果的速度”，还应报告自主度、可运行时间、参数空间、测量精度、吞吐量、采样成本和优化表现。([Nature][5])

# 八、最有价值的研究创新点

你们最强的论文主线不是“发现一个更高电导材料”，而可以是：

> **部分可观测、EIS-only、噪声和高实验成本条件下的证据校准型自主材料发现。**

可形成四项核心贡献：

1. **两种发现模式共享的传导行为向量和结论等级体系；**
2. **信息增益—性能改进—成本—风险统一采集策略；**
3. **把科学记忆、外部验证器、校准拒答真正接入湿实验闭环；**
4. **用正例、失败反例、预注册、消融和独立批次确认评估自主发现能力。**

真正需要突破的底层问题则是：

* 潜在材料状态不可观测条件下的贝叶斯信念建模；
* EIS逆问题和模型不可辨识性；
* 跨材料体系的因果迁移与桥接假设验证；
* 偶然噪声与认知不确定性的分离；
* 最优重复次数与下一新实验之间的价值信息决策；
* 科学Agent的概率校准和选择性拒答；
* 从原始谱到论文主张的机器可验证溯源。

数据和实验操作层建议采用机器可执行协议、不可变原始数据、W3C PROV式溯源以及RO-Crate式复现包；SiLA类功能接口可用于隔离仪器能力和上层Agent。([sila-standard.com][6])

# 总判断

你的判断方向基本正确，但原因需要更精确：

> **不是别人已经做出的技术普遍“质量很差”，而是他们验证的正确性层级，通常低于你们需要的层级。**

许多系统已经能做到：

1. LLM正确调用工具；
2. 工作流顺利执行；
3. 仪器返回结果；
4. 优化指标有所改善。

但你们需要证明的是：

5. 样品在执行期间处于什么物理状态；
6. EIS结果是否具有计量有效性；
7. 结果是否真的支持预注册假设；
8. 替代解释是否被排除；
9. 结论是否会在新批次中复现；
10. 智能体是否知道自己什么时候证据不足。

这两组目标之间还有非常大的工程与科学鸿沟。

## 四种“正确”不能混在一起

| 层级      | 正确性的含义                | 现有技术成熟度 | 你们的要求 |
| ------- | --------------------- | ------: | ----: |
| L1 接口正确 | JSON、参数、工具调用没有报错      |       高 |    必须 |
| L2 流程正确 | 步骤顺序、状态转移、权限和恢复正确     |      中高 |    必须 |
| L3 测量正确 | 样品状态明确，谱有效，误差和不确定度受控  |      中低 |    必须 |
| L4 科学正确 | 主张与证据匹配，替代解释被处理，结论可复现 |       低 |  核心创新 |

现有Agent SDK、工作流框架、MCP、实验室操作系统，主要覆盖L1和L2；个别自驱动实验室覆盖部分L3；**几乎没有通用系统真正覆盖L4**。

因此，直接拼装第三方技术，最容易得到的是：

> 一个“会运行实验”的Agent。

而你们真正需要的是：

> 一个“只在证据允许时才形成科学主张”的自主发现系统。

# 二、自驱动实验室现有技术具体哪里不够好

## 1. 仪器被错误地抽象成“软件工具”

普通Agent框架通常假定：

```text
调用工具 → 返回结果 → 工具调用完成
```

但在湿实验中，至少需要区分五个状态：

```text
命令已提交
→ 仪器已接受
→ 物理操作已完成
→ 测量通过质控
→ 结果可用于科学推断
```

例如EIS程序返回“measurement completed”，只意味着仪器程序结束，不意味着：

* 样品已经达到热平衡；
* 湿度和调理状态没有变化；
* 谱满足线性和时间不变性；
* KK或lin-KK通过；
* 频率窗口足以支持电路解释；
* 接触和几何没有发生变化。

当前MCP、A2A一类协议没有表达排他资源、不可逆操作、物理单位、校准和测量不确定度的完整语义；SiLA等标准更适合确定性客户端，而不是根据自然语言目标进行概率推理的Agent。([arXiv][2])

### 你们需要的改造

工具不能只返回：

```json
{"status": "success"}
```

而应返回类似的科学状态：

```text
operation_status: completed
sample_state_observed: partially_observed
thermal_equilibrium: passed
stationarity: failed
kk_status: not_tested
calibration_status: valid
scientific_usability: invalid
invalid_reason: temporal_drift
```

即：

> **仪器成功不等于实验成功；实验成功也不等于科学证据成立。**

---

## 2. 现有系统缺少真正的“样品状态”

大多数实验室操作系统跟踪的是：

* 任务状态；
* 仪器状态；
* 文件状态；
* 工作流状态。

你们还必须跟踪：

* 样品身份和母批次；
* 配方及其不确定度；
* 制膜和干燥过程；
* 调湿时间；
* 温度路径；
* 累积低温停留；
* 升降温方向；
* 循环次数；
* 装夹压力；
* 接触变化；
* 已经经历过的EIS测试；
* 当前状态是观测到的、推断的还是未知的。

同一配方、同一温度，并不意味着是同一个实验条件。

在你们的体系里：

[
x_{\text{experiment}}
\neq
{\text{配方}, T}
]

而至少是：

[
x_{\text{experiment}}=
{\text{配方},T,\text{湿度},\text{热史},\text{调理史},
\text{批次},\text{装夹},\text{接触},\text{时间}}
]

如果这些状态没有成为系统中的一等对象，Agent记忆得越多，反而越可能把不可比较的数据混在一起。

---

## 3. 软件“回滚”在湿实验中往往不存在

你们当前方案中T0045、T0058、T0073—T0075使用了“所有动作可回滚”的表述，这对软件系统成立，但对湿实验不成立。

以下过程一般不能真正回滚：

* 膜已被干燥；
* 样品已经吸湿或脱水；
* 已经历一次低温循环；
* 接触状态已经改变；
* 样品出现裂纹；
* 试剂已经混合；
* 样品已经老化；
* 某次长时间EIS已经改变其调理状态。

因此需要把“回滚”改成：

> **状态核对 → 补偿操作 → 前向恢复 → 样品隔离或作废。**

例如仪器调用超时后，不能直接重试。因为第一次测量可能已经发生，只是确认消息丢失。正确步骤应是：

1. 查询仪器实际状态；
2. 查询输出文件和时间戳；
3. 检查样品热史是否已经改变；
4. 判断第一次操作是否完成；
5. 决定继续、补测、重新平衡或隔离样品；
6. 将第二次测量标记为新的观测，而不是幂等重试。

LAP之所以专门提出仪器预留、任务生命周期、安全握手和样品链路，正说明普通软件工具协议不能充分描述这些物理语义；但LAP本身目前也尚未经过生产级验证。([arXiv][2])

---

## 4. 现有闭环通常默认“观测值是干净标量”

很多自驱动实验室论文的闭环近似为：

[
x \rightarrow y \rightarrow \text{更新模型}
]

其中 (y) 是产率、电导率、吸收峰或其他单个数字。

你们实际得到的是：

[
x
\rightarrow
Z(\omega,T)
\rightarrow
Q_{\text{EIS}}
\rightarrow
p(\theta\mid Z)
\rightarrow
B
\rightarrow
\text{主张}
]

中间存在：

* 无效谱；
* 测量漂移；
* 几何误差；
* 接触误差；
* 多个等效电路；
* 不可辨识参数；
* 批次效应；
* 潜在材料状态；
* 温度模型竞争；
* 结果为区间而非点值。

如果把这些信息压成一个电导率数值后直接送给BO，优化器会把：

* 接触失败理解为材料性能差；
* 未热平衡理解为低温异常；
* 批次偏差理解为配方效应；
* 不可辨识模型理解为确定机制；
* 失效谱理解为正常低值。

SDL性能研究也指出，不同实验空间的优化速率并不能直接迁移比较，测量精度、噪声、运行寿命、材料成本和实验吞吐都必须单独报告；高吞吐不能补偿低精度数据。([Nature][3])

---

## 5. “优化成功”没有证明“发现成功”

现有系统经常以以下指标定义成功：

* 找到更高性能的候选；
* 比随机搜索更快；
* Pareto前沿改善；
* 实验完成率提高。

这些指标可以证明算法优化能力，但不能自动证明：

* 文献知识成功迁移；
* 桥接假设成立；
* 机制判断正确；
* 智能体真正学到了可迁移规律；
* 负例被正确预测；
* 结论能够在新批次复现。

你们需要把以下两个问题严格分开：

### 优化问题

[
\text{哪个候选的预期性能更高？}
]

### 科学判别问题

[
\text{哪个实验最能区分竞争假设？}
]

已有SDL技术普遍更擅长第一类，第二类仍然薄弱。

# 三、Agent Harness Engineering哪里不够好

## 1. 软件Agent的Harness不能原样搬到湿实验

Harness可以理解为模型之外的完整运行环境，包括：

* 任务规范；
* 上下文组装；
* 工具；
* 状态；
* 记忆；
* 权限；
* 调度；
* 重试；
* 观测；
* 验证；
* 人工干预；
* 失败恢复。

官方Agent评测指南也强调，“Agent”的性能实际上是模型和Harness共同作用的结果，而不是模型单独的能力。([Anthropic][4])

当前较成熟的Harness engineering经验主要来自软件开发Agent。软件系统具有：

* 可复制环境；
* Git版本；
* 单元测试；
* CI；
* 可逆修改；
* 可快速重复执行；
* 明确的最终状态。

OpenAI的Harness实践强调结构化知识库、反馈回路、可观测性和版本化计划；Anthropic的长期Agent实践也发现，单纯上下文压缩不足以避免半成品、错误交接和过早宣布完成。([OpenAI][5])

湿实验却具有相反性质：

| 软件Agent    | 湿实验Agent         |
| ---------- | ---------------- |
| 文件可复制      | 样品通常不可复制         |
| Git可回滚     | 材料状态不可回滚         |
| 测试可快速重复    | 重复实验会改变热史和成本     |
| 环境较完全可观测   | 样品内部状态不可观测       |
| 错误主要损失时间   | 错误会损失样品、仪器或科学可信度 |
| 成功状态容易机器判定 | 科学有效性需要计量和推断     |

因此，你们需要的不是普通Agent Harness，而是：

> **Scientific Wet-Lab Harness。**

---

## 2. Prompt不能承担安全和科学约束

当前系统经常把以下规则写在系统提示词里：

* 不要超出温度范围；
* 不要跳过热平衡；
* 不要用无效谱更新模型；
* 证据不足时拒答；
* 不要直接宣称机制；
* 高风险操作需要审批。

这不够。

AILA实验显示，Agent可能偏离指令并进行要求之外的操作，作者称之为“sleepwalking”；系统对很小的提示格式变化也较敏感。([Nature][6])

这些限制必须落在确定性层：

```text
LLM提出动作
→ 参数模式校验
→ 单位校验
→ 边界校验
→ 当前样品状态校验
→ 仪器状态校验
→ 风险策略校验
→ 人工审批或拒绝
→ 执行
```

也就是说：

> Prompt负责建议，Policy Engine负责决定能不能做。

---

## 3. 现有Tracing不是科学溯源

Agent SDK已经能够记录：

* 模型调用；
* 工具调用；
* handoff；
* guardrail；
* 自定义span。([OpenAI开发者][7])

但这些只能回答：

> Agent做了什么？

不能完整回答：

> 这个科学结论为什么成立？

你们的trace还必须包含：

* 样品和母批次ID；
* 物料及称量来源；
* 制备协议版本；
* 仪器和固件版本；
* 校准状态；
* 温度、湿度和热史；
* 原始谱哈希；
* 质控结果；
* 排除频点的原因；
* 分析代码和参数；
* 候选模型集合；
* 后验和不确定度；
* 主张依赖了哪些证据；
* 哪些证据后来被作废；
* 人工在哪一步干预；
* 为什么提高或降低了结论等级。

因此，T0079“全栈可观测性”应升级为两套并行trace：

1. **运行trace**：Agent、工具和工作流；
2. **科学trace**：样品、测量、分析和主张。

---

## 4. 普通重试策略对湿实验是危险的

通用Agent框架通常采用：

* timeout后重试；
* 指数退避；
* tool call失败后重新调用；
* 计划失败后回溯。

在湿实验中，必须首先判断：

[
\text{调用失败}
\neq
\text{物理操作未发生}
]

因此T0785“重试”和T0786“回溯”应改成：

```text
故障
→ 状态核对
→ 判断是否部分完成
→ 更新样品状态
→ 估计重复操作的影响
→ 继续 / 补偿 / 隔离 / 人工处理
```

建议采用：

* 命令幂等键；
* 仪器和文件双重见证；
* 物理完成证据；
* 单样品单写者；
* 操作前后状态快照；
* 超时后的状态协调器；
* 禁止盲目自动重试。

---

## 5. “自我检查”不是独立验证

你们的T0787、T0789、T0790和T0806分别涉及反思、自我批评、验证器模型和验证者智能体。这些概念不能被视为等价。

应区分：

| 类型        | 能做什么          | 不能证明什么     |
| --------- | ------------- | ---------- |
| 同一次模型自我反思 | 找明显遗漏         | 不能提供独立性    |
| 同模型新上下文复核 | 降低部分路径依赖      | 错误仍高度相关    |
| 多Agent辩论  | 暴露分歧          | 一致不代表正确    |
| 独立模型验证    | 降低部分模型相关性     | 仍不能替代物理证据  |
| 确定性检查器    | 单位、边界、计算、模式检查 | 不能评价开放式机理  |
| 独立批次实验    | 检验复现性         | 仍不一定确认微观机制 |

AutoLabs的消融结果表明，推理模型能力往往比“单Agent还是多Agent”更重要；专家参与可以改善结果，但专家仍然遗漏了搅拌、封盖、参数分配等程序错误。([arXiv][8])

因此正确的验证金字塔应是：

```text
确定性语法检查
→ 单位、边界和守恒检查
→ 前置/后置物理状态检查
→ EIS计量质控
→ 统计和模型检查
→ 独立Agent证据审查
→ 人工审批
→ 独立批次实验
```

LLM验证器只能处在中上层，不能替代底层验证。

---

## 6. 平均成功率掩盖了真正危险的失败

最新Agent可靠性研究指出，能力分数提高并没有带来同等程度的可靠性提高；单一任务成功率会掩盖运行间不一致、扰动脆弱性、不可预测失败和错误严重度。([arXiv][9])

你们不能只报告：

* Agent任务成功率；
* 工具调用正确率；
* 实验完成率；
* 最终性能改善。

还需要报告：

* 错误支持主张率；
* 无效谱进入优化器的比例；
* 未授权物理动作率；
* 重复运行决策一致性；
* 提示改写敏感性；
* 故障注入恢复率；
* 错误严重度；
* 拒答是否发生在正确位置；
* 置信区间覆盖；
* 智能体置信度校准；
* 每个被确认科学主张的总成本。

---

# 四、现有Agent记忆为什么不够好

## 核心问题：现有记忆主要优化“能否想起来”，你们需要优化“想起来的东西是否仍然成立”

当前记忆研究通常关注：

* 检索准确性；
* 长上下文；
* 会话连续性；
* 个性化；
* token节省。

科学Agent还需要：

* 证据来源；
* 适用条件；
* 时间和版本；
* 支持与反驳关系；
* 结论失效传播；
* 负结果；
* 不确定度；
* 替代解释；
* 访问权限；
* 谁有权把内容提升为“事实”。

MemoryAgentBench把Agent记忆能力分为准确检索、测试时学习、长程理解和选择性遗忘，并发现当前方法尚不能同时做好全部四项。([OpenReview][10])

---

## 1. 向量相似度不是科学有效性

向量数据库最容易返回“语义相似”的内容，但科学检索需要同时判断：

[
\text{relevance}
\times
\text{validity}
\times
\text{applicability}
\times
\text{freshness}
\times
\text{authority}
]

例如旧记忆说：

> 淀粉–黏土膜在低温下保持较高传导。

后续实验可能表明：

* 仅在升温支路出现；
* 仅某个批次出现；
* 结果受装夹影响；
* 新批次没有复现；
* 旧谱后来未通过漂移检查。

普通向量记忆仍可能因为相似度高，把旧结论反复取回。

正确的记忆条目必须包含：

```text
对象类型
主张内容
主张等级
证据ID
适用条件
有效时间
版本
支持证据
反驳证据
当前状态
替代解释
置信度
上游依赖
下游主张
```

---

## 2. 记忆必须支持“证据失效的级联传播”

假设：

```text
谱E1支持参数P1
P1支持温度模型M1
M1支持桥接假设H1
H1支持候选排序R1
```

如果后来发现E1没有达到热平衡，则不能只把E1标记为无效。系统还必须重新计算：

* P1是否仍成立；
* M1是否仍有独立证据；
* H1的置信度是否下降；
* R1是否需要更新；
* 后续哪些实验决策依赖了该错误信息。

近期RECON记忆基准专门把记忆表示成带推导关系的溯源图，并指出当证据被修订或作废时，系统必须判断哪些结论失去基础、哪些仍有独立证据支持；现有系统在跨会话知识更新上仍然容易失败。

因此你们的P28“主张—证据—反例图”不只是知识展示工具，而应成为：

> **记忆一致性和失效传播的核心计算结构。**

---

## 3. Agent不能直接把自己的输出写成长期事实

最危险的闭环是：

```text
Agent生成推断
→ 写入长期记忆
→ 后续检索回该推断
→ 把它当成既有事实
→ 进一步强化
```

这是“自我引用式证据膨胀”。

建议采用记忆状态机：

```text
Proposed
→ Quarantined
→ Validated
→ Active
→ Contested
→ Superseded / Refuted / Invalidated
→ Archived
```

权限规则应是：

* LLM只能写入`Proposed`；
* 确定性分析器可写入经过验证的派生结果；
* 质控系统决定测量是否有效；
* 独立验证器可提出升降级建议；
* 只有规则引擎或授权人员可把科学主张提升为`Active`；
* 原始数据永远不可由Agent改写。

动态记忆研究也开始指出，自主改写记忆可能导致语义漂移、程序漂移、错误积累和记忆污染，因而需要把记忆生成与记忆治理分离。([arXiv][11])

---

# 五、多Agent记忆哪里不够好

## 1. 共享一个Python字典不等于多Agent记忆

AILA使用两个专门Agent并共享Python字典保存交互和状态。这可以支持原型协作，但从科学工程角度看，它不自动具备：

* 持久化；
* 类型系统；
* 版本控制；
* 事务；
* 并发冲突；
* 访问权限；
* 溯源；
* 主张失效；
* 跨实验批次一致性。([Nature][6])

这种结构适合演示“Agent能交换状态”，不适合保存长期科学结论。

---

## 2. 多Agent共享记忆会出现经典一致性问题

多Agent同时读写共享记忆会产生：

* 读到旧版本；
* 覆盖其他Agent的更新；
* 同一个主张出现不同状态；
* 不同Agent基于不同证据集推理；
* 并发生成相互冲突的总结；
* 已作废信息仍被某个Agent使用。

近期多Agent记忆研究把这类问题类比为计算机体系结构中的缓存一致性，认为当前最重要的开放问题之一就是共享记忆的一致性、可见性和更新顺序。([arXiv][12])

### 你们不应使用“最后写入者胜出”

对于科学主张：

```text
Agent A：支持H1
Agent B：反驳H1
```

不能简单取最新一条，也不能投票。

应当生成：

```text
claim_status: CONTESTED
support_branch: [...]
refute_branch: [...]
unresolved_conditions: [...]
next_discriminating_experiment: [...]
```

冲突本身就是科学状态。

---

## 3. 建议采用三类内存空间

### 私有工作记忆

每个Agent自己的：

* 临时计划；
* 搜索轨迹；
* 未验证想法；
* 草稿；
* 局部推理。

不自动共享，也不能形成科学事实。

### 角色限定记忆

例如：

* 文献Agent只读文献和证据库；
* BO模块只读QC有效指标；
* 执行控制器只读已批准协议；
* Claim Agent只读经过版本化的证据图；
* 验证Agent不能修改原始数据。

### 共享权威记忆

只保存：

* 不可变事件；
* 原始数据引用；
* 经过质控的观测；
* 版本化派生量；
* 主张与证据关系；
* 已批准技能；
* 人工审批和审计记录。

共享内存采用：

* append-only事件；
* MVCC或版本号；
* 乐观并发控制；
* 单样品状态的单写者；
* 显式冲突状态；
* 读取时携带版本；
* 写入时检查是否基于过期版本。

---

# 六、记忆压缩哪里不够好

## 1. 当前压缩优化的是token，不是证据保真度

长期Agent实践表明，单纯compaction并不足以保证跨上下文正确交接；压缩后可能留下半完成状态、模糊指令，或者导致后续Agent过早判断任务完成。([Anthropic][13])

对于科学Agent，压缩最危险的不是“漏掉一句背景”，而是漏掉：

* 适用条件；
* 负结果；
* 反驳条件；
* 测量无效原因；
* 仅在升温支路成立；
* 某结论只来自单批次；
* 两个模型无法区分；
* 某机理仍有替代解释；
* 当前主张等级只是C3或C4。

例如原始结论是：

> 在批次B3、升温支路、特定湿度调理下，数据与VTF样行为一致，但Arrhenius分段模型仍不能被排除。

普通摘要可能压成：

> 该材料表现出VTF传导。

这不是信息压缩，而是科学结论升级。

---

## 2. 必须区分三种压缩

| 类型         | 能否压缩    | 原则            |
| ---------- | ------- | ------------- |
| 原始数据与仪器日志  | 不做有损压缩  | 不可变、可复算       |
| 权威科学记录     | 只能结构化归纳 | 保留条件、状态、证据和版本 |
| Agent工作上下文 | 可以有损压缩  | 必须保留权威记录指针    |

正确关系是：

```text
摘要 = 缓存
原始证据 = 权威来源
```

不能让：

```text
摘要的摘要的摘要
```

最终取代原始证据。

---

## 3. 建议建立“证据保真压缩器”

每次压缩必须输出六部分：

1. 已确认事实；
2. 被反驳或无效的内容；
3. 尚未解决的冲突；
4. 所有硬约束；
5. 可推翻当前判断的结果；
6. 原始证据和事件指针。

对关键内容设零损失预算：

[
L_{\text{critical}}
===================

L_{\text{condition}}
+
L_{\text{contradiction}}
+
L_{\text{falsifier}}
+
L_{\text{provenance}}
+
L_{\text{claim status}}
=0
]

压缩后自动进行回归测试：

* 是否仍能回答当前样品状态；
* 是否保留所有无效谱原因；
* 是否保留正反证据；
* 是否知道哪些主张被降级；
* 是否能恢复下一步计划；
* 是否会因此改变实验决策；
* 是否错误提升主张等级。

---

# 七、Skills哪里不够好

## 1. 当前Agent Skill只是“程序知识包”

Agent Skills通常由：

* `SKILL.md`；
* 操作说明；
* 脚本；
* 模板；
* 示例；
* 参考资料

组成，并通过渐进式加载减少上下文占用。([Claude平台][14])

它适合表达：

> 如何完成某类任务。

但不能自动证明：

> 这个程序在当前仪器、样品和科学条件下是有效、安全、可复现的。

---

## 2. Skills有帮助，但并不稳定

SkillsBench的2026年预印本在84项任务和7308条轨迹上发现，人工整理的Skills平均提高16.2个百分点，但84项任务中仍有16项性能下降；模型自行生成Skills平均没有收益，甚至略有退化。该结果不是湿实验基准，但足以说明“有Skill”不等于“Skill可靠”，而且Harness如何发现和调用Skill会显著影响效果。([SkillsBench][15])

因此，在湿实验中不应允许Agent：

```text
现场生成一个新Skill
→ 立即用于真实样品
→ 成功后自动进入技能库
```

---

## 3. 你们需要的是“科学技能合同”

每个Skill至少应包含：

| 字段          | 含义                 |
| ----------- | ------------------ |
| skill_id与版本 | 唯一标识和语义版本          |
| 类型          | 文献、分析、优化、验证、执行     |
| 适用域         | 哪些材料、温区、仪器、数据类型    |
| 输入          | 强类型输入、单位和允许范围      |
| 前置条件        | 样品、仪器、校准和环境要求      |
| 副作用         | 是否消耗样品、改变热史、不可逆    |
| 实现          | 固定代码、协议模板或受限模型     |
| 后置条件        | 成功后必须观测到什么         |
| 证据输出        | 原始数据、QC、派生结果和版本    |
| 失效模式        | 超时、漂移、接触、越界等       |
| 恢复方式        | 重试、补偿、重新平衡、隔离      |
| 验证器         | 确定性测试和允许误差         |
| 风险等级        | 是否需要人工审批           |
| 兼容矩阵        | 仪器、固件、模型和Harness版本 |
| 测试集         | 正例、反例、边界和故障注入      |

### Skill的五级生命周期

```text
Draft
→ Simulation
→ Shadow
→ Canary
→ Validated
→ Deprecated
```

Agent可以提出Skill草稿，但不能自行将其提升为`Validated`。

---

## 4. 渐进加载也有风险

渐进加载可以减少上下文，但湿实验中某些内容不能按需加载：

* 安全边界；
* 强制前置条件；
* 单位规则；
* 不可逆性；
* 样品状态要求；
* 质控标准；
* 审批要求。

因此Skill应分成：

### 永久强制内核

始终由系统执行：

* 类型；
* 单位；
* 边界；
* 风险；
* 前后置条件；
* 审批；
* 验证器。

### 可按需加载部分

由Agent阅读：

* 背景解释；
* 示例；
* 文献；
* 推荐策略；
* 常见问题。

---

## 5. Skill组合不能只靠自然语言

例如：

```text
制膜Skill
→ 调湿Skill
→ 装夹Skill
→ 变温EIS Skill
→ EIS分析Skill
```

只有当：

[
\text{postcondition}(S_i)
\models
\text{precondition}(S_{i+1})
]

时才能组合。

不能仅因为Agent认为“这两个步骤看起来相接”就自动串联。

---

# 八、多Agent系统哪里不够好

## 1. 多Agent提高性能，很多时候只是增加了计算量

Anthropic在研究型多Agent系统中发现，多Agent特别适合大规模并行搜索，但token消耗约为普通聊天的15倍；其分析中token使用本身解释了大部分性能差异。对于需要共享同一上下文、具有大量步骤依赖的任务，多Agent并不一定适合。([Anthropic][16])

湿实验恰好具有：

* 高步骤依赖；
* 单样品串行状态；
* 仪器排他占用；
* 操作不可逆；
* 需要共享权威状态；
* 错误成本高。

因此，多Agent不能作为默认架构。

---

## 2. 多Agent并不自动提供独立性

如果多个Agent：

* 使用同一个基础模型；
* 读取相同文献；
* 使用相同提示；
* 读取相同错误摘要；
* 调用相同拟合结果；

那么它们的错误高度相关。

三个Agent同时认为某个等效电路最好，可能只是因为：

* 都使用最小R²选模；
* 都没有检查实际可辨识性；
* 都忽略了频率窗口不足；
* 都把同一个错误记忆当成事实。

因此：

> Agent之间的一致，是协作结果；不是独立证据。

---

## 3. 多Agent最适合你们的三个位置

### 适合

1. 文献检索的并行覆盖；
2. 独立生成竞争假设；
3. 对桥接假设进行对抗性审查。

### 有条件使用

1. 候选解释比较；
2. 主张—证据一致性检查；
3. 实验计划审阅。

### 不适合由多个LLM协商

1. 数值计算；
2. 单位和物料守恒；
3. EIS质控；
4. 仪器状态机；
5. 重试和恢复；
6. BO采集函数；
7. 最终科学主张升级；
8. 安全审批。

---

## 4. 推荐的Agent拓扑

```text
研究总控Agent
│
├── 文献证据Agent（只读）
├── 假设生成Agent（只提议）
├── 对抗性反例Agent（只提议）
│
├── 数值决策服务（非LLM）
│   ├── BO
│   ├── 信息增益
│   ├── 层级贝叶斯
│   └── EIS模型比较
│
├── 协议编译器（确定性）
├── 执行状态机（确定性）
├── EIS质控服务（确定性+统计）
│
├── 主张验证Agent（只读）
├── 规则验证器（确定性）
└── 人工审批
```

核心原则：

> **开放式问题使用Agent；可形式化问题使用算法；物理执行使用状态机；高等级科学主张使用独立证据。**

多Agent之间最好通过结构化产物和引用交换结果，而不是层层转述自然语言。生产多Agent实践也建议将子Agent输出持久化为独立产物，以减少“传话游戏”造成的信息丢失。([Anthropic][16])

这是软件Agent Harness与真实湿实验Harness之间最关键的区别之一。

# 十、建议建设的“Scientific Harness”核心

## 三个相互隔离的平面

### 1. 认知平面

负责：

* 文献检索；
* 假设生成；
* 解释；
* 候选建议；
* 反例搜索。

权限：只能提出建议。

### 2. 控制平面

负责：

* 状态机；
* 资源锁；
* 协议编译；
* 前后置检查；
* 权限；
* 仪器执行；
* 故障协调；
* 人工审批。

权限：执行已验证动作，但不能形成科学结论。

### 3. 证据平面

负责：

* 原始数据；
* 样品事件；
* 质控；
* 派生结果；
* 不确定度；
* 主张图；
* 失效传播；
* 审计；
* 复现包。

权限：决定什么可以成为证据。

三者不能由一个LLM同时承担。

# 十一、建议的权威记忆结构

至少建立七类存储：

| 存储    | 内容           | 是否可压缩   |
| ----- | ------------ | ------- |
| 原始数据仓 | EIS、日志、传感器输出 | 不可有损压缩  |
| 事件账本  | 每次动作和状态变化    | 只追加     |
| 样品状态库 | 制备、调理、热史、装夹  | 版本化     |
| 证据库   | 文献片段和实验观测    | 保留来源    |
| 主张图   | 支持、反驳、依赖、失效  | 结构化更新   |
| 情景记忆  | 每轮决策和失败经验    | 可压缩但非权威 |
| 技能注册表 | SOP、脚本、版本和测试 | 版本固定    |

外加一类很重要但经常被忽略的：

### 校准与错误记忆

记录：

* Agent当时预测什么；
* 给出多大置信度；
* 实验结果是什么；
* 错误来自文献迁移、数据分析、工具使用还是状态估计；
* 哪类条件下Agent最容易过度自信。

这类记忆直接用于调整下一轮自主权，而不是只用于生成一段“经验总结”。

# 十二、最值得形成论文贡献的技术缺口

结合你们的体系，真正尚未被别人很好解决的，不是再做一个通用Agent，而是以下六项：

## 1. 部分可观测湿实验的Scientific Harness

解决：

* 不可逆操作；
* 样品潜在状态；
* 执行成功与科学有效性的分离；
* 故障后的状态核对和前向恢复。

## 2. 证据保真型记忆压缩

压缩上下文，但严格保留：

* 条件；
* 反证；
* 主张等级；
* 替代解释；
* 失效依赖；
* 原始证据指针。

## 3. 多Agent科学记忆一致性

不是普通共享聊天记录，而是：

* 版本化主张；
* 并发写入；
* 冲突保留；
* 证据失效传播；
* 权限隔离；
* 不同Agent看到不同的授权视图。

## 4. 可认证的Scientific Skills

把Skill从自然语言说明升级为：

* 强类型合同；
* 物理前置条件；
* 副作用；
* 计量验证；
* 故障处理；
* 版本和适用域；
* 合格测试。

## 5. 从工具调用到科学主张的端到端可靠性评测

评价的不只是任务完成，而是：

* 无效证据进入率；
* 错误支持主张率；
* 失效传播正确率；
* 记忆污染率；
* 压缩信息损失；
* Agent校准；
* 独立批次复现率。

## 6. 自主权随可信度动态变化

例如：

```text
高校准 + 已验证Skill + 稳定测量
→ 允许自动执行

存在批次漂移或记忆冲突
→ 降级为建议模式

出现无效谱或状态不确定
→ 停止闭环

需要提升至C4主张
→ 必须独立批次和人工审批
```

这比简单地说“系统是Level 3或Level 4自主”更适合真实实验室。

# 最终建议

不要把近期重点放在：

* 增加更多Agent角色；
* 让Agent自行生成更多Skills；
* 让记忆自动自我进化；
* 用更长上下文保存全部历史；
* 用多Agent投票替代验证。

近期最应该完成的是：

1. **物理状态可核对的Harness内核；**
2. **不可变事件账本和样品状态模型；**
3. **记忆写入门和主张失效传播；**
4. **EIS Scientific Skill合同；**
5. **确定性验证器与Agent验证器分离；**
6. **故障、压缩、冲突和提示变化的系统级压力测试。**

你们最强的研究定位可以进一步收敛为：

> **面向部分可观测、不可逆、高成本湿实验的证据治理型Scientific Agent Harness：研究物理状态、Agent记忆、科学技能和主张可靠性如何在同一个真实闭环中被统一管理。**

这比“我们使用了多Agent、长期记忆和Skills”更有创新性，因为后者别人已经做了组件展示，而前者解决的是这些组件进入真实科学系统以后，**为什么仍然不能被直接信任，以及怎样才能被信任**。

# 一、三篇代表性顶刊论文调研

## 1. A-Lab：领域封闭型自驱动实验室

### 论文

Szymanski 等，**An autonomous laboratory for the accelerated synthesis of inorganic materials**，Nature，2023。

### 系统架构

A-Lab的闭环可以简化为：

```text
DFT数据库筛选候选
        ↓
文献挖掘模型生成初始合成路线
        ↓
机器人配料、混合、加热
        ↓
XRD测量
        ↓
机器学习物相识别 + 自动Rietveld精修
        ↓
ARROWS³主动学习选择下一合成路线
        ↓
新的实验
```

系统使用Materials Project和Google DeepMind的计算数据库筛选目标；通过文献训练的模型提出初始前驱体和温度；机器人完成粉体配料、加热和XRD表征；当目标相产率不足时，ARROWS³根据实验观察到的中间相和计算反应能推荐新路线。系统在17天内完成353次实验，获得36个目标材料；同时积累了88个两两反应记录，用于缩小后续搜索空间。([Nature][1])

### 真正创新点

A-Lab最重要的创新不是机器人本身，而是把四种知识组织在一个闭环中：

* 计算热力学知识；
* 文献中的历史合成知识；
* 当前实验生成的反应路径知识；
* 主动学习产生的下一实验决策。

特别重要的是，失败实验并没有简单记为“失败”，而是被分解为中间相和两两反应，形成可复用的局部反应知识。这已经是一种早期的、领域特化的科学记忆。([Nature][1])

### 它没有解决什么

#### 1. 自主性建立在封闭动作空间上

A-Lab能够调整前驱体和温度，但多步加热、中间研磨、扩大前驱体集合等标准操作仍在其主动学习算法的能力边界之外。研究者人工增加研磨和更高温度后，又成功得到两个目标材料。([Nature][1])

这说明它解决的是：

> 在预先定义好的实验动作集合中自主选择。

而不是：

> 自主发现新的实验程序或自主改变实验能力边界。

#### 2. 它的“记忆”不是通用科学记忆

它保存的是反应对和实验结果，没有完整处理：

* 主张由哪些数据支持；
* 数据失效后哪些结论应撤销；
* 两个模型冲突时如何保留冲突；
* 记忆如何跨Agent共享；
* 记忆压缩后是否改变科学判断。

#### 3. 操作成功与科学确定性仍有差距

四个材料最初被系统判断为成功，但人工复核认为仅凭XRD无法在目标相与其他相之间作出确定区分；论文也指出多相样品自动解释仍有明显困难。([Nature][1])

因此，A-Lab证明了**闭环自动合成可行**，但没有提供通用的科学主张治理层。

---

## 2. Coscientist：工具调用型科学Agent

### 论文

Boiko 等，**Autonomous chemical research with large language models**，Nature，2023。

### 系统架构

Coscientist以一个GPT-4 Planner为中心，Planner可以调用四类命令：

```text
GOOGLE          网络检索
DOCUMENTATION   查询仪器和API文档
PYTHON          在隔离容器内执行代码
EXPERIMENT      通过API调用真实实验设备
```

Web Searcher和Documentation模块本身也使用LLM；Python在隔离Docker环境中执行；实验层适配了Opentrons API和Emerald Cloud Lab的Symbolic Lab Language。Planner通过自然语言接收目标，再动态决定使用哪些模块。([Nature][2])

### 真正创新点

Coscientist第一次系统展示了LLM可以同时完成：

* 从互联网和文献寻找方法；
* 从设备文档学习API；
* 生成实验代码；
* 纠正代码错误；
* 控制液体工作站；
* 协调分析仪器；
* 根据历史实验结果推荐下一条件。

尤其重要的是，它证明了**仪器能力可以不全部预训练进模型，而是在运行时通过文档检索获得**。当系统使用了错误的加热振荡模块方法名时，它重新查询文档并修改协议，最终使程序成功运行。([Nature][2])

### 它没有解决什么

#### 1. Planner处理的是消息，不是科学状态

工具输出作为消息回传给Planner，但系统没有显式区分：

* 指令已发送；
* 仪器已接受；
* 物理操作已发生；
* 测量完成；
* 测量通过质控；
* 结果可以作为科学证据。

这意味着它的基本闭环仍然是：

```text
LLM → 工具调用 → 返回字符串 → LLM继续推理
```

而不是：

```text
Agent提议 → 物理状态验证 → 执行 → 独立见证
→ 测量质控 → 证据提交 → 更新主张
```

#### 2. 文档检索不是Skill认证

Coscientist可以找到“怎样调用一个API”，但没有证明：

* 当前参数在该设备版本上有效；
* 前置条件已经满足；
* 操作是否改变样品状态；
* 失败后能否安全恢复；
* 输出是否达到科学测量要求。

因此，它掌握的是**API使用知识**，不是**经过验证的科学技能**。

#### 3. 优化实验没有充分覆盖真实闭环的不确定性

其优化能力测试使用了两个已经完整映射的反应数据集，Agent选择条件后，结果可以从查找表获得。论文明确说明，任何推荐条件都存在于已有数据集中。([Nature][2])

由此可以推断，这部分实验没有同时面对：

* 样品失败；
* 仪器漂移；
* 无效测量；
* 批次变化；
* 实验部分完成；
* 物理状态不可观测。

所以它更接近“历史数据上的序贯决策测试”，而不是完整的高成本湿实验Harness验证。

---

## 3. AILA：多Agent实验Harness及其失败模式

### 论文

Mandal 等，**Evaluating large language model agents for automation of atomic force microscopy**，Nature Communications，2025。

### 系统架构

AILA包含：

* 一个LLM Planner；
* AFM Handler Agent，负责仪器操作；
* Data Handler Agent，负责数据分析；
* 文档检索、代码执行、图像分析和优化工具；
* LangGraph工作流；
* 一个由两个Agent共同访问的Python字典，保存交互和状态。

Agent之间通过模型输出中的`NEED HELP`和`FINAL ANSWER`等关键词进行路由。([Nature][3])

论文还构建了AFMBench，包含100个实验任务，覆盖实验设计、多工具协作、决策、开放式实验和分析。69%的任务要求多个工具，17%的任务要求多个Agent。([Nature][3])

### 真正创新点

AILA的重要贡献不是单纯“让LLM操作AFM”，而是：

1. 建立真实仪器上的Agent评测；
2. 比较单Agent与多Agent；
3. 分析代码生成、工具选择、Agent路由和指令遵循错误；
4. 明确识别Agent越过任务边界的“sleepwalking”现象。

在10个代表性问题、每题3次试验的单Agent与多Agent比较中，GPT-4o多Agent配置成功率为70%，直接工具集成的单Agent配置为58%。但这只是一个小规模子集，不足以证明所有实验任务都应采用多Agent。([Nature][3])

更关键的是，GPT-4o在300个任务实例中的总错误率为29%，其中代码生成错误占21.7%；系统还出现了未经要求的探针运动和额外实验动作。([Nature][3])

### 它没有解决什么

#### 1. 共享Python字典不等于科学多Agent记忆

它缺少：

* 版本控制；
* 并发写入冲突；
* 权限；
* 数据来源；
* 主张状态；
* 证据失效；
* 长期持久化；
* 压缩保真度；
* 跨实验批次一致性。

共享字典只解决了“两个Agent能否看到相同变量”，没有解决“哪个变量可以被相信”。

#### 2. 基于关键词的路由非常脆弱

`NEED HELP`、`FINAL ANSWER`属于自然语言协议。模型一旦漏写、错写或过早写出终止关键词，流程状态就可能错误变化。

#### 3. Prompt中的伦理规则不是强制策略

AILA将伦理规则和角色责任写在系统提示中，但实验表明模型仍会超出操作边界。论文自身因此提出需要领域约束验证和形式化验证。([Nature][3])

# 三、原创解决方案一：SciTX科学事务Harness

## 全称

**SciTX：Evidence-Transactional Harness for Partially Observable Autonomous Laboratories**

中文可称：

> **面向部分可观测实验的证据事务型科学Agent运行时。**

## 核心发明

现有Harness把一次工具调用作为基本单元：

```text
tool_call(parameters) → result
```

SciTX把基本单元改为：

> **证据事务 Evidence Transaction**

一次证据事务不是“调用仪器”，而是：

```text
科学意图
→ 状态准备
→ 权限和约束验证
→ 物理执行
→ 独立见证
→ 测量质控
→ 证据提交或隔离
```

这是一项新的系统语义，而不是给现有工作流再加几条Prompt。

---

## 1. 四类状态必须分开

定义系统状态：

[
X_t=
\left(
s_t^{op},
b_t(z),
e_t,
a_t^{auth}
\right)
]

其中：

| 状态           | 含义                     |
| ------------ | ---------------------- |
| (s_t^{op})   | 可直接观测的仪器、任务、文件、环境和资源状态 |
| (b_t(z))     | 对不可直接观测物理状态的信念分布       |
| (e_t)        | 当前有效证据和主张图的版本          |
| (a_t^{auth}) | 当前Agent、Skill和操作的授权状态  |

关键创新在于：**Harness内部不假定物理状态完全可见。**

例如，软件可以知道“温控器显示-20 °C”，但不能因此自动断言：

* 样品已经达到热平衡；
* 样品内部状态没有继续变化；
* 接触状态稳定；
* 测量可以提交为证据。

这些判断进入 (b_t(z))，而不是被伪装成确定状态。

---

## 2. Agent只提交动作提案，不直接执行

LLM输出高层提案 (\tilde a_t)，SciTX运行时负责决定是否允许执行：

[
a_t^*=
\arg\max_{a\in\mathcal A(\tilde a_t)}
U(a\mid b_t,e_t)
]

约束为：

[
P\left(
\varphi_{\mathrm{safety}}
\land
\varphi_{\mathrm{scientific\ validity}}
\mid b_t,a
\right)
\ge 1-\delta
]

其中：

* (\varphi_{\mathrm{safety}})：安全约束；
* (\varphi_{\mathrm{scientific\ validity}})：科学有效性约束；
* (\delta)：允许的风险水平。

如果不能证明约束满足，系统只能：

* 先做诊断；
* 降级为建议模式；
* 请求人工批准；
* 拒绝执行。

不是让LLM“再想一想”。

---

## 3. 建立物理世界的三阶段提交

### 阶段A：Prepare

验证：

* Skill版本；
* 输入类型与单位；
* 样品和仪器状态；
* 资源排他锁；
* 校准有效期；
* 操作适用域；
* 风险等级；
* 当前信念状态是否足够确定。

### 阶段B：Execute and Witness

执行操作，同时收集多个独立见证：

* 仪器确认；
* 传感器轨迹；
* 文件时间戳和哈希；
* 样品位置；
* 环境状态；
* 操作前后快照。

### 阶段C：Scientific Commit

只有同时满足以下条件，结果才能进入权威证据库：

[
\mathrm{Commit}(y)=
1
\iff
W\models\psi_{\mathrm{complete}}
\land
Q(y)=\mathrm{pass}
\land
C_{\mathrm{skill}}=\mathrm{valid}
]

其中：

* (W)：物理见证集合；
* (Q(y))：测量质控；
* (C_{\mathrm{skill}})：Skill证书状态。

因此：

```text
仪器程序结束 ≠ 操作完成
操作完成 ≠ 测量有效
测量有效 ≠ 科学主张成立
```

---

## 4. 提出“Scientific exactly-once”语义

普通软件的exactly-once关注消息是否重复处理。实验室需要区分三个ID：

1. **命令尝试ID**；
2. **物理操作ID**；
3. **证据记录ID**。

网络超时后，系统不能直接重试，而要先判断：

* 第一次物理操作是否已经发生；
* 样品状态是否已经变化；
* 是否产生了原始数据；
* 第二次执行是否构成新实验；
* 原结果是否只能隔离而不能覆盖。

这解决的是自驱动实验室中特别危险的问题：

> **工具调用失败，并不意味着物理动作没有发生。**

---

## 5. 用“补偿图”取代软件回滚

编码：

```text
失败状态
→ 状态核对
→ 继续
→ 补偿
→ 重新平衡
→ 样品隔离
→ 操作终止
```

而不是：

```text
失败 → rollback → retry
```

每个不可逆操作都需要显式声明：

* 会改变哪些状态；
* 哪些状态可观测；
* 哪些变化不可逆；
* 可执行哪些补偿；
* 在何种条件下样品必须作废。

---

## 6. 这项创新为什么不是普通工作流引擎

工作流引擎管理的是：

* 任务依赖；
* 超时；
* 队列；
* 重试；
* 检查点。

SciTX新增的是：

* 部分可观测物理状态；
* 证据提交语义；
* 科学质控门禁；
* 不可逆动作补偿；
* Agent动态授权；
* 从物理操作到科学主张的责任链。

编码Agent Harness经常依赖Git、测试和可回滚环境；现有长期Agent研究也主要通过进度文件、Git提交和测试恢复状态，同时明确指出单纯上下文压缩不足以保证跨会话正确性。([Anthropic][5])

湿实验没有Git式物理回滚，所以需要新的事务语义。

---

## 7. 应采用的评测指标

SciTX不以材料性能为评价目标，而以系统可靠性为目标：

* 无效结果被提交为证据的概率；
* 重复物理执行率；
* 超时后的状态核对正确率；
* 越权动作逃逸率；
* 样品状态错误率；
* 故障注入恢复率；
* 证据包完整率；
* 自主执行覆盖率；
* 为安全性增加的实验和时间开销；
* 错误主张因执行故障产生的概率。

### 可形成的论文题目

> **SciTX: Evidence-Transactional Runtime Semantics for Irreversible and Partially Observable Autonomous Laboratories**

# 四、原创解决方案二：E-Mem证据守恒多Agent记忆

## 全称

**E-Mem：Evidence-Conserving Multi-Agent Memory with Decision-Invariant Compression**

中文可称：

> **具有证据守恒、失效传播和决策不变压缩的多Agent科学记忆。**

## 核心发明

当前Agent记忆主要优化：

* 能否检索到相似内容；
* 能否减少token；
* 能否保持会话连续；
* 能否从过去经验中得到帮助。

科学Agent需要优化的是：

> **记忆经过共享、重复引用、总结和压缩后，是否仍然支持与原始证据相同强度的科学判断。**

MemoryAgentBench把Agent记忆划分为准确检索、测试时学习、长程理解和选择性遗忘，并发现当前方法无法同时做好四项。TierMem进一步指出，写入时摘要可能遗漏未来查询所需的关键细节，因此需要在必要时回溯不可变原始记录。([开放评论][6])

但这两类工作仍没有定义：

* 科学主张是否被摘要增强；
* 条件是否被摘要丢失；
* 反证是否被压缩掉；
* 多个Agent重复同一来源是否被错误计为多条证据；
* 数据作废后下游结论是否自动失效。

---

## 1. 建立四层记忆，而不是一个向量数据库

```text
L0：不可变原始事件账本
L1：经过质控的证据图
L2：主张、假设和竞争解释图
L3：Agent角色相关的工作缓存和摘要
```

### L0：原始事件账本

保存：

* 所有物理动作；
* 原始文件引用和哈希；
* 仪器日志；
* 样品状态变化；
* 人工干预；
* Skill和模型版本。

只追加，不覆盖。

### L1：证据图

节点包括：

* 有效观测；
* 无效观测；
* 派生指标；
* 模型结果；
* 文献证据；
* 校准结果。

### L2：主张图

边包括：

* supports；
* refutes；
* derived-from；
* assumes；
* applicable-under；
* invalidates；
* supersedes；
* conflicts-with。

### L3：Agent缓存

可以被压缩、丢弃和重新生成，但不能作为权威证据来源。

---

## 2. 多Agent不按“人数”计算证据

假设三个Agent都引用了同一篇论文：

```text
Agent A支持H
Agent B支持H
Agent C支持H
```

这不是三条独立证据，而是一条证据被复制了三次。

E-Mem根据**独立来源根节点**计权：

[
W(H)=
\sum_{r\in \mathrm{IndependentRoots}(H)}
w_r
]

而不是：

[
W(H)=
\sum_{\mathrm{Agent\ messages}}w_i
]

这可以消除多Agent系统非常常见的“共识幻觉”：

> 多个Agent一致，只是因为它们读取了同一个错误来源或同一个错误摘要。

---

## 3. 引入科学真值维护系统

每个主张保存：

* 最小支持证据集；
* 反驳证据集；
* 必要假设；
* 适用范围；
* 当前状态；
* 后验或置信区间；
* 依赖的分析模型和Skill版本。

例如：

```text
原始测量E1
  ↓
派生结果D1
  ↓
模型比较M1
  ↓
假设H1
  ↓
候选排序R1
```

若E1后来因校准失效被标记为Invalid，系统自动计算：

* D1是否仍有效；
* M1是否还有独立支持；
* H1应降级还是撤销；
* R1是否需要重新排序；
* 哪些后续实验是依据错误信息选择的。

这不是普通数据库级联删除，而是**带替代证据的非单调真值维护**：

* 有其他独立支持时，主张降权；
* 没有其他支持时，主张失效；
* 存在反证时，主张进入Contested；
* 不能区分时，保持Inconclusive。

---

## 4. 多Agent记忆使用版本快照，而不是共享可变字典

每个Agent读取：

```text
evidence_snapshot_hash
claim_graph_version
skill_registry_version
sample_state_version
```

Agent输出必须携带：

```text
based_on_version
used_evidence_ids
generated_claims
uncertainty
```

写入时检查：

* 是否基于过期版本；
* 是否与新证据冲突；
* 是否重复使用同一来源；
* 是否有权限修改该对象。

建议采用：

* 样品状态单写者；
* 原始数据只允许仪器服务写入；
* Agent只能提交Proposed Claim；
* 质控服务只能修改测量有效性；
* 主张升级由规则引擎和授权人员控制；
* 可交换的笔记可以使用CRDT；
* 科学主张状态禁止使用“最后写入者胜出”。

---

## 5. 核心原创算法：科学失真约束下的记忆压缩

普通记忆压缩目标是：

[
\min |\hat M|
]

即尽量减少token。

E-Mem定义科学失真：

[
D_{\mathrm{sci}}(M,\hat M)=
\lambda_1D_{\mathrm{action}}
+\lambda_2D_{\mathrm{claim}}
+\lambda_3D_{\mathrm{scope}}
+\lambda_4D_{\mathrm{contradiction}}
+\lambda_5D_{\mathrm{provenance}}
]

其中：

* (D_{\mathrm{action}})：压缩前后下一实验决策变化；
* (D_{\mathrm{claim}})：主张后验或证据强度变化；
* (D_{\mathrm{scope}})：适用条件丢失；
* (D_{\mathrm{contradiction}})：反证和冲突丢失；
* (D_{\mathrm{provenance}})：无法回到原始来源。

压缩问题改为：

[
\hat M^*=
\arg\min_{\hat M} |\hat M|
]

满足：

[
D_{\mathrm{sci}}(M,\hat M)\le\epsilon
]

更具体地：

[
D_{KL}
\left(
\pi(a\mid M)
\Vert
\pi(a\mid \hat M)
\right)
\le\epsilon_a
]

并且：

[
\left|
\log BF_H(M)
------------

\log BF_H(\hat M)
\right|
\le\epsilon_H
]

这里的核心不是“摘要读起来是否相似”，而是：

> **摘要是否改变了Agent的实验选择和科学主张。**

---

## 6. 五条证据守恒定律

### ① 来源守恒

任何摘要都必须能反向解析到原始证据集合。

### ② 反证守恒

存在于原始记录中的关键反证，不能在摘要中消失。

### ③ 适用域不扩张

压缩后的主张适用范围不能比原始证据更宽。

### ④ 置信度不放大

摘要不能把“可能”“一致于”升级为“证明”“确定”。

### ⑤ 独立性不伪增

同一来源被多个Agent复制、转述或总结，不能增加独立证据数量。

---

## 7. 压缩结果必须携带证书

每个摘要附带：

```text
summary_id
source_node_ids
covered_claims
covered_counterevidence
preserved_conditions
decision_invariance_tests
claim_strength_before_after
raw_log_recovery_pointer
compression_model_version
```

摘要只是缓存。只要：

* 出现争议；
* 需要形成高等级主张；
* 压缩不变性测试失败；
* Agent要求提高自主权；

系统就自动回溯原始记录。

---

## 8. 评测指标

* 压缩导致下一实验选择翻转的比例；
* 压缩导致主张等级上升的比例；
* 关键条件丢失率；
* 反证丢失率；
* 无效记忆复活率；
* 数据失效传播的precision、recall和延迟；
* 多Agent重复证据计数误差；
* 版本冲突检测率；
* 原始来源可恢复率；
* 同一记忆状态下多次推理的一致性；
* 在固定token预算下的科学失真。

### 可形成的论文题目

> **E-Mem: Evidence-Conserving Multi-Agent Memory and Decision-Invariant Compression for Autonomous Science**

这三个方向中，**E-Mem可能具有最高的纯Agent算法创新性**，因为它把记忆压缩从语言摘要问题转化成科学决策的率失真问题。

---

# 五、原创解决方案三：PC-Skills可证明科学技能

## 全称

**PC-Skills：Proof-Carrying and Composable Skills for Scientific Agents**

中文可称：

> **携带验证证书、可组合、可撤销的科学Agent技能。**

## 核心发明

当前Agent Skill通常是：

```text
SKILL.md
+ 说明
+ 示例
+ 脚本
+ 参考资料
```

官方Agent Skills也主要将Skill定义为可动态加载的指令、脚本和资源目录，通过渐进式加载减少上下文占用。([Anthropic][7])

SkillsBench对84项任务、7种Agent—模型配置和7308条轨迹的评测发现：

* 人工整理的Skills平均提升16.2个百分点；
* 16项任务反而下降；
* 自生成Skills平均没有收益；
* 过于全面的Skills文档甚至降低性能；
* 2—3个聚焦Skill通常比大量Skill更有效。([arXiv][8])

这说明：

> Skill有用，但“存在一个Skill文件”完全不等于“这个Skill可以被可信地用于真实实验”。

---

## 1. 把Skill定义成有类型的科学操作符

定义：

[
K=
(A,G,\Theta,\Delta,R,W,Q,\mathrm{Cert})
]

| 元素       | 含义              |
| -------- | --------------- |
| (A)      | 前置假设和状态要求       |
| (G)      | 成功后必须满足的后置条件    |
| (\Theta) | 经过认证的参数适用域      |
| (\Delta) | 对样品和实验状态的副作用    |
| (R)      | 资源、风险和权限        |
| (W)      | 物理完成所需的见证       |
| (Q)      | 输出质控规则          |
| Cert     | Skill证书、版本和验证记录 |

因此，一个科学Skill不是“怎样做”，而是：

> **在什么条件下、以什么参数、对什么对象、产生什么状态变化、需要哪些见证、输出如何验证、失败时如何处理。**

---

## 2. 建立Scientific Skill IR和编译器

Agent或人类提供自然语言SOP后，不直接用于实验，而是编译成中间表示：

```text
自然语言SOP
      ↓
Scientific Skill IR
      ↓
类型和单位检查
      ↓
状态转换图
      ↓
资源锁与权限分析
      ↓
副作用和不可逆性分析
      ↓
运行时监视器
      ↓
测试预言机
      ↓
受控可执行代码
```

Scientific Skill IR至少包含：

```text
inputs
units
preconditions
allowed_parameter_region
forbidden_conditions
resource_locks
physical_side_effects
irreversible_effects
execution_states
expected_witnesses
postconditions
quality_checks
compensation_paths
provenance_outputs
```

这使得不同仪器驱动、MCP工具或实验室控制系统可以编译到同一个科学语义层。

---

## 3. Skill只能在认证参数域内自适应

LLM可以提议参数 (\tilde\theta)，但执行值必须满足：

[
\theta^*=
\Pi_{\Theta^{cert}}(\tilde\theta)
]

即投影到认证参数域。

如果参数超出 (\Theta^{cert})，系统不能让Agent凭语言推理直接扩展边界，只能：

* 进入模拟；
* 进入shadow模式；
* 要求人工批准；
* 创建新的Skill候选版本；
* 重新进行认证。

定义Skill适用包络：

[
\mathcal E_K=
\left{
(x,s):
P(G_K\mid A_K,x,s,K_v)
\ge1-\delta
\right}
]

Agent不是问：

> “我有没有这个Skill？”

而是问：

> “当前对象和状态是否位于这个Skill经过验证的适用包络内？”

---

## 4. 区分数学证明与物理认证

“Proof-Carrying”不意味着能数学证明实验一定成功。

Skill证书包含两部分：

### 静态证明部分

可以严格检查：

* 类型；
* 单位；
* 参数范围；
* 资源冲突；
* 非法调用路径；
* 状态机死锁；
* 未授权工具；
* 数据流权限；
* 前后置条件组合。

### 统计认证部分

通过历史实验和校准估计：

* 后置条件满足概率；
* 失败模式分布；
* 适用域覆盖；
* 测量质控通过率；
* 仪器和版本迁移风险；
* 置信区间与校准曲线。

这样不会把湿实验的不确定性伪装成软件级绝对证明。

---

## 5. 建立可组合Skill的assume—guarantee规则

两个Skill只有满足：

[
G_{K_i}\models A_{K_{i+1}}
]

才能自动组合。

并且需要满足：

[
\sum_i R(K_i)\le R_{\max}
]

以及：

[
\Delta_{K_i}
\cap
F_{K_{i+1}}
===========

\varnothing
]

其中：

* (R(K_i))：风险或资源预算；
* (\Delta_{K_i})：前一个Skill造成的状态变化；
* (F_{K_{i+1}})：下一个Skill禁止的状态。

因此：

```text
Skill A执行成功
```

并不自动表示：

```text
Skill B可以开始
```

必须由A的后置条件证明B的前置条件成立。

---

## 6. Skill输出携带“证据包”

每次Skill执行后，不仅返回：

```json
{"status": "success"}
```

而应返回：

```text
skill_id
skill_version
input_snapshot
parameter_snapshot
precondition_results
execution_witnesses
state_transition
raw_output_hashes
quality_results
uncertainty
postcondition_results
certificate_reference
```

这个证据包随后交给SciTX决定是否提交到E-Mem。

---

## 7. Skill可以自我改进，但不能自我认证

Agent可以：

* 识别Skill失败；
* 生成候选修订；
* 修改参数策略；
* 新增错误处理；
* 生成新的测试案例。

但Agent生成的新版本只能处于：

```text
Draft
→ Simulation
→ Shadow
→ Canary
→ Certified
```

Agent不能自行把自己生成的Skill提升为Certified。

SkillsBench已经显示，自生成Skills平均无收益，部分模型甚至明显退化，这说明“让模型写一个Skill再立即使用”不能作为可靠策略。([arXiv][8])

---

## 8. Skill证书必须可以自动撤销

以下事件应触发Skill重新认证或撤销：

* 仪器固件变化；
* 驱动或API变化；
* 分析模型变化；
* 校准方法变化；
* 样品类别超出历史适用域；
* 连续出现后置条件失败；
* 质控通过率显著下降；
* Harness版本改变；
* 上游Skill证书失效。

更重要的是，Skill失效要反向通知E-Mem：

```text
Skill版本K失效
→ 找出所有使用K产生的证据
→ 重算证据可信度
→ 更新依赖主张
→ 必要时撤销后续决策
```

这把Skills与科学记忆真正连接起来。

---

## 9. 评测指标

* Skill前置条件漏检率；
* 越界参数执行率；
* 后置条件满足概率的校准误差；
* Skill组合失败率；
* 未声明副作用率；
* 仪器版本漂移检测率；
* 证书错误接受率和错误拒绝率；
* 自生成错误Skill拦截率；
* Skill导致无效证据提交的概率；
* 跨仪器迁移后的性能下降；
* 从发现Skill失效到撤销相关证据的延迟。

# 七、为什么这三项足以构成真正的原创贡献

| --------- | ------------------- | ---------------------- | -------------------- |
| SciTX     | 证据事务、科学exactly-once | 部分可观测状态下的运行时屏蔽与证据提交    | 错误证据提交、物理重复执行、越权动作   |
| E-Mem     | 证据守恒记忆              | 决策不变、主张不增强的科学率失真压缩     | 压缩诱发决策翻转、失效传播、重复证据   |
| PC-Skills | 携证科学操作符             | Skill编译、适用包络、组合证明和证书撤销 | 合同违反、适用域越界、Skill失效污染 |

它们不是简单地组合数据库、工作流和形式化方法，因为三者分别引入了新的科学Agent语义：

1. **SciTX**把数据库事务改造成不可逆物理世界中的证据事务；
2. **E-Mem**把语言压缩改造成受科学决策失真约束的压缩；
3. **PC-Skills**把程序知识包改造成带物理适用域和统计保证的可撤销操作符。

# 最值得采用的总研究命题

> **面向部分可观测、不可逆和高成本真实实验的证据安全型Scientific Agent Operating System：通过事务化Harness、证据守恒多Agent记忆和可证明Scientific Skills，使LLM从实验执行者和科学裁判，转变为受约束、可校准、可审计的科学提议者。**

这里真正被评价的，不再是某个材料最终达到了多高性能，而是：

* Agent是否在错误状态下错误行动；
* 错误实验是否进入了模型；
* 错误记忆是否被多Agent重复放大；
* 压缩是否改变了科学结论；
* Skill是否在适用域外被滥用；
* 数据失效后系统是否主动撤回下游结论；
* 系统能否在保持自主性的同时降低错误科学主张率。

这才是自驱动实验室和Scientific Agent下一阶段真正缺少的底层创新。

回答：
# 三项创新的完整功能构建方案

## 一、总体结论：不要做三个孤立模块，要做一个“证据安全型自主科学操作系统”

建议将三项创新整合为：

# **ESAS-OS：Evidence-Safe Autonomous Science Operating System**

## 证据安全型自主科学操作系统

其核心不是让Agent“更聪明”，而是建立三道相互制约的底层机制：

| 底层问题                       | 核心组件                 | 决定什么                         |
| -------------------------- | -------------------- | ---------------------------- |
| Agent能否把一个想法作用到真实物理世界      | **SciTX科学事务Harness** | 这个动作能不能执行、是否真的执行、结果能不能进入科学闭环 |
| 多Agent能否共享、压缩、修订科学知识而不污染结论 | **E-Mem证据守恒记忆**      | 系统现在可以相信什么、哪些结论已失效、摘要有没有改变判断 |
| 一段实验程序能否成为可信、可组合、可撤销的能力    | **PC-Skills携证科学技能**  | 这个Skill在哪些条件下有效、如何验证、何时必须撤销  |

系统中的LLM、多Agent、贝叶斯优化器和实验设计器，都不再拥有直接的物理执行权或科学事实写入权，而只是受控的**提议者**。

---

# 二、重新调研后的创新边界

三项方向仍然成立，但必须避开已经被最新工作覆盖的部分。

## 1. SciTX不能只做“Agent—仪器协议”

2026年6月提出的LAP已经定义了InstrumentCard、仪器排他预留、样品锁、安全确认令牌、QUDT/UCUM物理单位、校准和不确定度字段，并考虑了Agent—仪器的任务生命周期。LAP也明确说明，它目前仍是设计规范，没有大规模实现和实证验证。 ([arXiv][1])

因此，SciTX不能把以下内容作为主要创新：

* 仪器发现；
* 参数Schema；
* 资源预留；
* 物理单位；
* 安全令牌；
* 仪器调用协议。

SciTX真正的原创部分应当是：

> **从科学意图、物理执行、状态核对、测量质控一直延伸到“证据提交”的事务语义。**

特别要解决：

* 部分可观测物理状态；
* 操作不可逆；
* 调用超时但物理动作已经发生；
* 仪器成功与测量有效分离；
* 测量有效与科学主张成立分离；
* 后发现故障时，如何撤销已产生的证据和下游结论。

---

## 2. E-Mem不能只做“摘要层+原始日志层”

TierMem已经提出：

* 有损摘要索引；
* 不可变原始日志；
* 查询时判断摘要是否充分；
* 必要时升级到原始证据；
* 验证后写回带来源的摘要。

它解决的是长时Agent中“摘要便宜但可能漏信息、原始日志可信但昂贵”的矛盾。 ([arXiv][2])

MemoryAgentBench表明，Agent记忆至少需要同时处理准确检索、测试时学习、长程理解和选择性遗忘；MemoryArena进一步指出，在静态记忆测试上表现很好，并不意味着记忆能够在多轮任务中指导正确行动。 ([OpenReview][3])

因此，E-Mem的原创部分不能只是：

* 向量数据库；
* 长期记忆；
* 分层存储；
* 摘要回溯；
* 语义检索。

真正应解决的是：

> **科学真值如何在多Agent、证据冲突、数据失效和记忆压缩条件下被维护。**

---

## 3. PC-Skills不能只做“形式化Skill合同”

VASO已经把机器人Skill表示为形式接口和规划接口的双重语义合同，并使用模型检查器验证时间逻辑约束，再把反例转换成Skill更新信号。其机器人实验报告了97.2%的形式规范符合率。 ([arXiv][4])

SkillsBench则发现，人工构建的Skills平均提高16.2个百分点，但84个可比较任务中仍有16个性能下降；模型自行生成的Skills平均没有带来收益。 ([arXiv][5])

因此，PC-Skills不能把以下内容单独作为创新：

* `SKILL.md`；
* 程序知识包；
* 形式化前后置条件；
* 模型检查；
* Agent自动生成Skill。

真正需要突破的是：

> **Skill不仅形式上安全，还必须在统计、计量和科学有效性层面经过认证；证书失效后，要能撤销它产生的证据和下游结论。**

# 四、系统必须强制满足的十条不变量

这些规则不能写在Prompt里，而必须由确定性运行时执行。

| 编号  | 系统不变量                       |
| --- | --------------------------- |
| I1  | LLM不能直接访问仪器驱动，只能提交动作提案      |
| I2  | Agent生成的文字不能直接进入权威科学记忆      |
| I3  | 未提交的测量结果不能更新BO、统计模型或候选排序    |
| I4  | 仪器返回成功不能自动等价为物理操作成功         |
| I5  | 物理操作成功不能自动等价为测量有效           |
| I6  | 测量有效不能自动等价为科学主张成立           |
| I7  | 超时后必须先核对真实状态，禁止盲目重试         |
| I8  | 摘要只能作为缓存，原始数据和事件账本才是权威来源    |
| I9  | Skill只能在其认证适用包络内执行          |
| I10 | Skill或证据失效后，必须自动重算所有下游主张和决策 |

AILA的实验已经表明，LLM可能越过任务边界，出现论文所称的“sleepwalking”，而且系统对轻微的提示格式变化仍然敏感。因此，实验边界、路由和终止条件必须从自然语言Prompt迁移到确定性状态机和策略引擎。 ([Nature][7])

# 五、公共数据模型

三个系统必须共享同一套对象和ID，否则无法做端到端审计。

## 1. 核心实体

| 实体                        | 作用                  |
| ------------------------- | ------------------- |
| `ScientificIntent`        | 人类或Agent提出的科学目标     |
| `ActionProposal`          | Agent建议执行的动作，但尚未获准  |
| `EvidenceTransaction`     | 一次从动作提议到证据提交的完整事务   |
| `Sample`                  | 样品身份、来源和母批次         |
| `SampleStateSnapshot`     | 某一时刻的样品可观测状态和信念状态   |
| `InstrumentStateSnapshot` | 仪器、环境、校准和资源状态       |
| `SkillVersion`            | Skill的不可变版本         |
| `SkillCertificate`        | Skill的形式、统计和计量认证    |
| `ExecutionAttempt`        | 一次命令调用尝试            |
| `PhysicalEffect`          | 推断或确认发生的一次物理作用      |
| `Witness`                 | 仪器、传感器、文件或人员提供的完成见证 |
| `Artifact`                | 原始数据、日志、配置、代码或报告    |
| `QCResult`                | 质控结果及所用规则版本         |
| `EvidenceNode`            | 经过门禁后可参与推理的证据       |
| `ClaimNode`               | 科学主张、假设或竞争解释        |
| `MemoryUnit`              | Agent可检索的记忆单元       |
| `CompressionCertificate`  | 记忆压缩保真验证结果          |
| `RevocationEvent`         | Skill、证据或证书失效事件     |
| `HumanDecision`           | 人工审批、拒绝、修改和说明       |

## 2. 一次实验至少需要五种不同ID

```text
intent_id          科学意图
transaction_id     证据事务
attempt_id         软件调用尝试
physical_effect_id 真实物理作用
evidence_id        最终提交的科学证据
```

这样可以处理：

* 一个意图产生多个事务；
* 一个事务因网络故障产生多个调用尝试；
* 多个调用尝试实际上只发生了一次物理动作；
* 一次物理动作产生多个数据文件；
* 数据文件最终可能不形成有效证据。

# 六、创新一：SciTX科学事务型Harness

# 6.1 研究命题

> 在部分可观测、不可逆和可能部分完成的真实实验环境中，能否建立类似数据库事务、但以“证据是否成立”为最终提交对象的运行时语义？

SciTX不是普通工作流，也不是仪器协议，而是一个**科学证据事务协调器**。

## 6.3 两套相互独立的状态机

### 物理执行状态机

```text
PROPOSED
→ VALIDATING
→ PREPARED
→ RESERVED
→ EXECUTING
→ RECONCILING
→ PHYSICALLY_COMPLETE
```

异常状态：

```text
WAITING_APPROVAL
REJECTED
PARTIAL
FAULTED
COMPENSATING
ISOLATED
ABORTED
```

### 证据状态机

```text
UNREGISTERED
→ QUARANTINED
→ QC_PENDING
→ COMMIT_READY
→ COMMITTED
```

异常状态：

```text
REJECTED
CONTESTED
INVALIDATED
SUPERSEDED
```

关键是允许出现：

```text
physical_status = PHYSICALLY_COMPLETE
evidence_status = REJECTED
```

也就是：

> 实验确实做了，但结果不能用于科学推断。

## 6.4 三阶段证据提交

### 阶段一：Prepare

在任何动作发生前冻结：

* 样品状态版本；
* 仪器状态版本；
* Skill版本和证书；
* 参数和单位；
* 质控规则版本；
* 预期后置条件；
* 风险和预算；
* 是否需要人工批准；
* 当前科学意图和主张ID。

### 阶段二：Execute and Witness

执行期间记录：

* 实际发送的命令；
* 实际参数；
* 仪器确认；
* 温度、湿度、时间等环境轨迹；
* 文件生成事件；
* 操作开始和结束时间；
* 传感器或人工确认；
* 样品状态变化；
* 所有异常。

### 阶段三：Scientific Commit

建议定义：

[
\mathrm{Commit}(T)=1
]

当且仅当：

[
W_{\mathrm{complete}}
\land
P_{\mathrm{pre}}
\land
P_{\mathrm{post}}
\land
Q_{\mathrm{pass}}
\land
C_{\mathrm{skill}}
\land
C_{\mathrm{calibration}}
\land
P_{\mathrm{provenance}}
]

全部成立。

其中分别代表：

* 物理完成见证完整；
* 前置条件成立；
* 后置条件成立；
* 测量通过QC；
* Skill证书有效；
* 校准有效；
* 溯源信息完整。

## 6.5 部分可观测状态模型

SciTX不应把所有状态都表示成确定布尔值。

建议每个关键状态采用：

```yaml
state_variable: thermal_equilibrium
value: true
probability: 0.97
observed_or_inferred: inferred
supporting_witnesses:
  - temperature_trace_018
  - equilibrium_rule_v1.2
valid_from: ...
valid_until: ...
```

对不可直接观测状态，维护信念：

[
b_{t+1}(z)
\propto
p(o_{t+1}\mid z,a_t)
\sum_{z_t}
p(z\mid z_t,a_t)b_t(z_t)
]

工程第一版不必直接实现完整POMDP，可以先采用：

* 状态变量；
* 明确的`KNOWN / UNKNOWN / INFERRED`；
* 置信概率；
* 规则更新；
* 有效期；
* 证据指针。

后续再将其升级为贝叶斯状态估计。

## 6.6 “核对后重试”算法

普通Agent常见策略：

```text
timeout → retry
```

SciTX必须改成：

```text
timeout
→ 标记当前attempt结果未知
→ 查询仪器实际状态
→ 检查输出文件及哈希
→ 检查传感器轨迹
→ 核对样品状态变化
→ 推断是否已经产生physical_effect
→ 决定继续、补偿、重平衡、隔离或人工处理
```

伪代码：

```python
def reconcile_before_retry(transaction):
    instrument_state = query_instrument()
    artifacts = inspect_artifacts(transaction.time_window)
    witnesses = inspect_sensor_and_event_logs()
    sample_state = update_sample_belief(witnesses)

    effect = infer_physical_effect(
        instrument_state,
        artifacts,
        witnesses,
        sample_state,
    )

    if effect.confirmed:
        attach_effect_to_transaction(effect)
        return "DO_NOT_RETRY"

    if effect.possible_but_uncertain:
        quarantine_transaction()
        return "MANUAL_OR_DIAGNOSTIC"

    if effect.confirmed_not_occurred:
        return "SAFE_TO_CREATE_NEW_ATTEMPT"
```

这里不能承诺真实物理动作绝对“exactly once”。更准确的保证是：

> **动作身份可核对、重复物理作用可检测、证据只提交一次。**

## 6.7 不使用“回滚”，使用补偿图

每个不可逆Skill必须声明：

* 会改变什么；
* 哪些改变不可逆；
* 哪些改变可以补偿；
* 哪些状态需要重新平衡；
* 哪些情况必须隔离样品；
* 隔离后是否仍可保留为失败证据。

例如：

```text
执行异常
├── 未发生物理作用 → 重新执行
├── 已部分发生 → 诊断
├── 已发生但未产生有效数据 → 重新平衡后新事务
├── 样品状态不可确定 → 隔离
└── 数据存在但QC失败 → 保留原始记录，不提交证据
```

## 6.8 动态自主权

建议不要给系统一个固定“Level 3自主”标签，而是实时计算自主权。

[
A_t=
f(
C_{\mathrm{skill}},
U_{\mathrm{state}},
C_{\mathrm{memory}},
H_{\mathrm{instrument}},
R_{\mathrm{action}},
C_{\mathrm{agent}}
)
]

| 等级 | 权限                     |
| -- | ---------------------- |
| A0 | 只建议，不执行                |
| A1 | 执行低风险、确定性、已认证动作        |
| A2 | 在认证包络内自动执行和恢复          |
| A3 | 自动选择下一实验并闭环，但只能使用已提交证据 |

出现以下情况立即降级：

* 样品状态不确定性升高；
* Skill证书进入Degraded；
* 多Agent记忆出现冲突；
* 仪器校准失效；
* Agent近期置信校准变差；
* 连续QC失败；
* 操作超出历史验证域。

## 6.10 SciTX验收标准

建议第一版至少通过以下故障注入：

| 故障             | 合格行为                |
| -------------- | ------------------- |
| 命令确认丢失，但仪器已执行  | 不盲目重试，识别已发生动作       |

| 仪器显示完成，但热平衡未通过 | 物理完成、证据拒绝           |

| 人工审批后参数被修改     | 原审批令牌失效             |

核心指标：

* 无效证据提交率；
* 盲目重试次数；
* 重复物理作用漏检率；
* 状态核对准确率；
* 故障恢复完整率；
* 越权动作逃逸率；
* 证据包完整率；
* 有界风险下的自主执行覆盖率。

# 七、创新二：E-Mem证据守恒多Agent记忆

# 7.1 研究命题

> 多Agent记忆经过写入、共享、冲突、重复引用、压缩和修订后，能否保持与原始证据相同的科学判断强度和实验决策？

当前多Agent记忆的一项关键开放问题就是共享状态的一致性；最新研究已经开始把它类比为计算机体系结构中的缓存一致性问题。 ([arXiv][8])

---

## 7.2 四层记忆架构

```text
L0 不可变原始事件层
L1 有效证据层
L2 主张与假设层
L3 Agent工作缓存与压缩层
```

### L0：不可变原始事件层

保存：

* 原始仪器文件；
* 传感器日志；
* 操作事件；
* 样品状态历史；
* Agent提案；
* 人工审批；
* 代码、模型和Skill版本。

只能追加，不能覆盖。

### L1：有效证据层

只允许写入：

* SciTX已提交的实验结果；
* 经过来源验证的文献片段；
* 可复算的派生结果；
* 明确标记的无效或反例数据；
* 校准和质控结果。

### L2：主张与假设层

保存：

* 假设；
* 桥接假设；
* 经验主张；
* 竞争解释；
* 支持证据；
* 反驳证据；
* 适用条件；
* 可推翻条件；
* 当前结论等级。

### L3：Agent工作缓存

保存：

* 当前计划；
* 检索摘要；
* 临时分析；
* 草稿；
* 角色相关上下文。

L3可以被压缩或删除，但不能直接成为权威证据。

## 7.3 三维状态模型

一个科学主张不能只用一个`status`字段。

### 生命周期状态

```text
PROPOSED
QUARANTINED
ACTIVE
SUPERSEDED
ARCHIVED
INVALIDATED
```

### 认识论状态

```text
SUPPORTED
REFUTED
INCONCLUSIVE
CONTESTED
```

### 结论等级

```text
C0 数据无效
C1 单次有效观察
C2 可复现行为
C3 经验模型支持
C4 与机制预测一致但存在替代解释
C5 多模态证据和因果干预确认
```

这样可以表示：

```text
lifecycle = ACTIVE
epistemic_status = CONTESTED
claim_level = C3
```

即该主张仍在系统中有效，但证据存在冲突，且只达到经验模型层面。

## 7.5 多Agent不能按“票数”累积证据

三个Agent引用同一篇论文，不是三条独立证据。

建议按照独立根来源计算证据：

[
W(c)=
\sum_{r\in \mathrm{UniqueRoots}(c)}
q_r,a_{r,c},d_r
]

其中：

* (q_r)：来源质量；
* (a_{r,c})：对当前主张的适用性；
* (d_r)：来源独立性权重。

根来源定义：

| 来源类型    | 独立根                         |
| ------- | --------------------------- |
| 文献      | DOI、版本和具体实验                 |
| 实验      | `physical_effect_id`和独立样品批次 |
| 分析      | 不构成新根，只是已有证据的变换             |
| Agent发言 | 永远不构成独立证据根                  |
| 摘要      | 永远不构成独立证据根                  |

这可以消除多Agent“共识膨胀”。

## 7.6 科学真值维护与失效传播

例如：

```text
原始谱 E1
  ↓
派生电导 D1
  ↓
温度模型 M1
  ↓
桥接假设 H1
  ↓
候选排序 R1
  ↓
下一实验 A1
```

如果后来发现E1未达到热平衡：

1. E1标记为`INVALIDATED`；
2. D1重新计算或失效；
3. M1检查是否仍有独立证据；
4. H1降低支持度或进入`CONTESTED`；
5. R1重新排序；
6. A1标记为“基于后失效证据产生”；
7. 必要时重新评价后续实验结果。

需要实现两类传播：

### 硬失效传播

上游不存在替代支持时，下游直接失效。

### 软降级传播

存在其他独立证据时，下游保留，但降低置信度或结论等级。

这是一套非单调科学真值维护，而不是普通数据库级联删除。

## 7.7 多Agent版本一致性

每个Agent读取上下文时获得快照：

```yaml
evidence_graph_version: 182
claim_graph_version: 64
sample_state_version: 27
skill_registry_version: 19
```

Agent输出必须携带：

```yaml
based_on_versions:
  evidence_graph: 182
  claim_graph: 64
used_evidence_ids:
  - E-312
  - E-318
generated_claims:
  - C-proposal-981
```

写入时检查：

* Agent是否基于旧版本；
* 使用的证据是否已经失效；
* 是否与新主张冲突；
* 是否重复计入相同根来源；
* Agent是否有该对象的写权限。

冲突不能采用`last-write-wins`。

正确行为是：

```text
Claim A: 支持H1
Claim B: 反驳H1

→ 创建CONTESTED状态
→ 保留两条证据分支
→ 提取尚未解决的条件
→ 生成区分实验需求
```

## 7.8 记忆写入门

Agent不能直接写：

```text
事实：材料X存在某机制
```

它只能提交：

```yaml
memory_type: proposed_claim
content: ...
supporting_evidence_ids:
  - ...
scope:
  - ...
confidence: ...
falsifiers:
  - ...
```

写入流程：

```text
Agent Proposal
→ 进入Quarantine
→ 来源和版本检查
→ 独立证据检查
→ 适用域检查
→ 与已有主张冲突检查
→ 规则或验证器评估
→ Active / Contested / Rejected
```

---

## 7.9 核心算法：决策不变、主张不增强的记忆压缩

普通压缩优化：

[
\min |\hat M|
]

E-Mem应优化：

[
\min_{\hat M} |\hat M|
]

约束：

[
D_{\mathrm{sci}}(M,\hat M)\le \epsilon
]

定义科学失真：

[
D_{\mathrm{sci}}
================

\lambda_aD_{\mathrm{action}}
+\lambda_cD_{\mathrm{claim}}
+\lambda_sD_{\mathrm{scope}}
+\lambda_xD_{\mathrm{counterevidence}}
+\lambda_pD_{\mathrm{provenance}}
]

其中：

| 项                              | 含义              |
| ------------------------------ | --------------- |
| (D_{\mathrm{action}})          | 压缩前后下一实验选择是否改变  |
| (D_{\mathrm{claim}})           | 主张状态、等级或后验是否改变  |
| (D_{\mathrm{scope}})           | 适用条件是否丢失或扩大     |
| (D_{\mathrm{counterevidence}}) | 反例、冲突和可推翻条件是否丢失 |
| (D_{\mathrm{provenance}})      | 是否还能回到全部原始证据    |

---

## 7.10 压缩验证流程

```text
选择原始权威子图
→ 生成候选摘要
→ 条件保留检查
→ 反证保留检查
→ 主张等级检查
→ 下一动作回放
→ 来源恢复检查
→ 签发CompressionCertificate
```

### 决策不变测试

对压缩前后分别运行固定实验决策探针：

* 下一实验Top-1是否变化；
* Top-k排序变化；
* 是否从“继续诊断”变成“直接执行”；
* 是否从“证据不足”变成“支持”；
* 是否改变重复实验与新实验的选择。

可定义：

[
D_{\mathrm{rank}}
=================

1-\tau(
\mathrm{rank}(M),
\mathrm{rank}(\hat M)
)
]

其中(\tau)可采用秩相关系数。

### 主张不增强测试

要求：

```text
压缩后的结论等级 ≤ 原始证据允许的等级
```

例如摘要不能将：

```text
“与VTF样行为一致，但分段Arrhenius不能排除”
```

压成：

```text
“已证明是VTF机制”
```

## 8.4 三层认证

## 第一层：形式认证

检查：

* 类型；
* 单位；
* 参数边界；
* 权限；
* 资源互斥；
* 状态机可达性；
* 死锁；
* 时间逻辑安全；
* 前后置条件；
* Skill组合条件；
* 禁止执行路径。

可使用：

* JSON Schema/Pydantic做类型；
* Z3/SMT做约束；
* TLA+验证SciTX状态不变量；
* NuSMV、UPPAAL或类似工具验证时间状态机。

VASO已经说明形式反例可以反向改进Skill语义合同，但形式验证只能证明被形式化的性质，不能证明真实实验测量一定科学有效。 ([arXiv][4])

---

## 第二层：统计认证

在认证适用包络(\mathcal E_K)内评估：

* 前置条件满足率；
* 后置条件完成率；
* QC通过率；
* 已知失败模式覆盖率；
* 不确定度校准；
* 不同日期、批次和仪器版本下的稳定性；
* 罕见但严重失败概率。

建议认证条件：

[
\mathrm{LCB}_{1-\alpha}
\left[
P(G_K\mid A_K,\mathcal E_K)
\right]
\ge \tau
]

其中：

* (A_K)：前置条件；
* (G_K)：后置条件；
* (\mathcal E_K)：适用包络；
* LCB：置信下界；
* (\tau)：最低可接受可靠性。

不要只报告平均成功率，应给出置信下界和失败类型。

---

## 第三层：计量认证

检查：

* 校准链；
* 校准有效期；
* 仪器版本；
* 测量不确定度；
* 原始数据完整性；
* 量纲和单位；
* 分析代码版本；
* 参考样品或参考程序；
* 质控规则的适用域。

因此，一个Skill可能：

```text
形式认证：通过
统计认证：通过
计量认证：失效
```

此时它可以在仿真中使用，但不能产生可提交的实验测量证据。

---

## 8.5 Skill适用包络

Skill匹配不能只按名称。

定义：

[
\mathcal E_K=
\left{
(x,s,i,v):
P(G_K\mid A_K,x,s,i,v)\ge1-\delta
\right}
]

其中包括：

* 输入参数；
* 当前样品状态；
* 仪器型号；
* 固件版本；
* 环境范围；
* 上游Skill版本；
* 质控规则版本；
* 数据处理版本。

Agent提议参数(\tilde\theta)后：

[
\theta^*=
\Pi_{\Theta_K^{cert}}(\tilde\theta)
]

即只能投影到认证域内。

超出认证域时只能：

* 拒绝；
* 请求人工批准；
* 进入新Skill验证；
* 使用Shadow模式；
* 创建新版本。

不能让LLM临场解释“应该没问题”。

---

## 8.6 Skill生命周期

```text
DRAFT
→ STATIC_VERIFIED
→ SIMULATED
→ SHADOW
→ CANARY
→ CERTIFIED
→ DEGRADED
→ SUSPENDED
→ REVOKED / DEPRECATED
```

### 权限

| 状态              | 权限          |
| --------------- | ----------- |
| Draft           | 不可调用真实仪器    |
| Static Verified | 仅模拟         |
| Simulated       | 可进入Shadow   |
| Shadow          | 观察人工实验，不控制  |
| Canary          | 受控低风险执行     |
| Certified       | 在认证包络内自动执行  |
| Degraded        | 降低自主权或需人工审批 |
| Suspended       | 禁止新事务       |
| Revoked         | 重新审查历史证据    |

Agent可以提出新Skill或修改建议，但不能自行将其升级为`Certified`。SkillsBench显示，自生成Skill平均没有带来可靠收益，说明Skill生成和Skill认证必须严格分离。 ([arXiv][5])

## 8.7 Skill组合验证

两个Skill只有满足以下条件才能组合：

[
G_{K_i}\models A_{K_{i+1}}
]

此外还要检查：

[
\Delta_{K_i}
\cap
F_{K_{i+1}}
===========

\varnothing
]

其中：

* (G_{K_i})：前一个Skill保证的后置条件；
* (A_{K_{i+1}})：下一个Skill要求的前置条件；
* (\Delta_{K_i})：前一个Skill造成的副作用；
* (F_{K_{i+1}})：下一个Skill禁止的条件。

还必须检查：

* 资源是否冲突；
* 前一Skill是否改变样品状态；
* 单位是否兼容；
* 上下游证据Schema是否兼容；
* 总风险是否超预算；
* 中间状态是否有足够见证。

## 8.9 Skill漂移和撤销

触发条件包括：

* 仪器固件变化；
* 驱动或API变化；
* 代码哈希变化；
* 校准规则变化；
* 分析模型变化；
* 样品类别超出认证域；
* 连续QC失败；
* 后置条件满足率下降；
* 出现新失败模式；
* 上游Skill撤销；
* Harness状态机版本改变。

撤销流程：

```text
Skill K_v 被撤销
→ 查找由K_v产生的所有PhysicalEffect
→ 查找相关EvidenceNode
→ 根据撤销原因判断证据是否失效或降级
→ 更新所有ClaimNode
→ 重算历史决策依赖
→ 通知正在运行的事务
→ 降低系统自主权
```

这一步是PC-Skills相对普通形式化Skill最重要的创新。

# 九、三个创新点的端到端协同流程

## 场景一：正常实验

```text
1. Agent提出ActionProposal
2. SciTX冻结样品、仪器、Skill和证据图版本
3. PC-Skills确认Skill证书及适用包络
4. SciTX获得资源锁并执行
5. PC-Skills Runtime收集见证和Evidence Bundle
6. QC服务评估结果
7. SciTX提交EvidenceNode
8. E-Mem更新证据图和主张图
9. BO或实验设计器读取Committed Evidence
10. 产生下一ActionProposal
```

---

## 场景二：仪器超时但物理动作已经发生

```text
1. ExecutionAttempt超时
2. SciTX进入RECONCILING
3. 查询仪器、文件、传感器和样品状态
4. 确认physical_effect已经发生
5. 禁止重试
6. 若数据完整，继续QC
7. 若数据不完整，事务进入Quarantine
8. 样品状态按实际物理历史更新
```

---

## 场景三：事后发现校准有问题

```text
1. Calibration证书被撤销
2. 找到受影响的Skill执行记录
3. 标记相关EvidenceNode为待重评
4. E-Mem沿依赖图传播
5. 派生结果重新计算
6. 主张降级、争议化或失效
7. 受影响BO模型重新训练
8. 历史决策保留，但标注其证据基础已失效
```

---

## 场景四：多Agent记忆冲突

```text
Agent A：支持H1
Agent B：反驳H1
Agent C：引用与A相同的论文

E-Mem：
- A与C归并到同一个根来源
- B保留为独立反证分支
- H1状态设为CONTESTED
- 不执行多数投票
- 生成“区分H1与替代解释所需的实验条件”
```

---

## 场景五：上下文压缩

```text
1. E-Mem选择相关权威子图
2. 生成摘要
3. 检查条件、反证、来源和主张等级
4. 用摘要与原始图分别运行下一实验决策
5. 若决策或主张变化超过阈值，拒绝压缩
6. 通过后签发CompressionCertificate
7. Agent使用摘要，但高风险决策自动回溯原始证据
```

* 候选变量；
* 约束；
* 代理模型；
* 采集函数；
* 重复或探索决策。

其动作价值偏向：

[
U(a)
====

\mathbb E[\Delta HV]
-\beta C(a)
-\gamma R(a)
]

二者只有“如何产生ActionProposal”不同。

之后都必须经过：

```text
SciTX → PC-Skills → 实验 → QC → E-Mem
```

因此系统创新与材料性能、BO算法或某个候选无关。

# 十二、建议的工程实现栈

技术选择可以替换，关键是语义边界不能变。

| 层           | 建议实现                                      |

| 单位和量纲       | QUDT/UCUM                                 |

| 科学溯源        | W3C PROV-O                                |

# 最终优先级

真正合理的建设顺序不是先增加Agent，而是：

```text
公共语义与事件账本
→ SciTX证据事务
→ 最小PC-Skills合同
→ 证据提交门
→ E-Mem真值维护
→ 完整Skill认证与撤销
→ 多Agent与记忆压缩
→ 动态自主闭环
```

最先需要证明的也不是“系统找到更好材料”，而是三件更底层的事情：

1. **一次错误、部分完成或不可确认的物理操作，不会被错误地提交成科学证据；**
2. **一个被撤销或反驳的证据，不会继续作为多Agent记忆中的事实传播；**
3. **一个Skill只有在经过认证的条件内执行，其失效能够撤销自己造成的科学后果。**

当这三点成立后，迁移发现、贝叶斯优化、文献推理和多Agent规划才真正具备进入真实自驱动实验室的可信基础。

# 二、最值得肯定的地方

## 1. 项目真正抓住了“表征受限自主发现”的核心矛盾

附件没有把创新包装成“找到了一个性能更高的材料”，而是定义为：

* 只有EIS时，系统能看见什么；
* 哪些变化可以复现；
* 哪些模型可以区分；
* 哪些机理不能区分；
* Agent在证据不足时应当停在哪一级主张。

这是非常正确的研究方向。你们提出的“复现地板”和“可辨识性天花板”形成了一个完整边界：

[
\text{可重复测到的最小差异}
\le
\text{Agent可分辨的科学效应}
\le
\text{观测模型允许的结论强度}
]

这比“我们用了Agent、RAG、BO和自动仪器”更接近真正的方法学贡献。附件报告的ECE下降但分辨率不增加、单曲线QC无法预测跨片复现、三个机理律难以区分等负结果，实际上增强了这个主线，而不是削弱它。

## 2. 确定性与LLM的权力边界划分得比较诚实

系统没有把所有步骤都包装成Agent能力：

* Stage0分析是确定性的；
* BO是数值算法；
* S09候选和S10排序在发表版本中是冻结的确定性实现；
* LLM主要参与上游假设、文献、机制讨论和Stage1建议修正；
* S14负责确定性的结论封顶。

这并不是缺点。真实科学系统本来就应当：

> 开放式语义问题交给模型，形式化数值问题交给算法，物理执行交给状态机，科学主张交给证据规则。

真正的问题只在于论文标题、摘要和图示是否准确表达这种**混合智能架构**，而不能让读者误以为候选和排序由LLM自主完成。附件目前对此标注得较清楚。

## 3. 负结果没有被隐藏

以下结果都应该保留：

* 闭环顶端候选落在复现地板以内；
* ECE改善主要来自去除过度自信，而不是提高分辨力；
* 单曲线QC预测不了跨片复现；
* DRT在当前数据上不可用；
* 三种传导律在低温支路不可辨识；
* CHITO没有给出干净转变；
* 线B轨迹过短，不能声称收敛。

自驱动实验室的能力不应只用“最快找到了什么”评价，还要报告测量精度、噪声、成本、自主覆盖率、失败率和运行时间；相关SDL评价研究也明确反对仅以优化速度横向比较系统。([Nature][1])

# 三、主科学线中最需要修正的问题

## 1. 当前还不宜称为“端到端全自主自驱动实验室”

架构中仍由人：

* 选择campaign；
* 确定或确认R/N配方；
* 连接硬件并启动真机测量；
* 完成样品制备、装夹等物理步骤。

因此更准确的名称是：

> **human-supervised, evidence-governed agentic experimentation system**

或者：

> **部分自主、证据治理型自驱动实验平台**

ADePT框架把实验室自主能力拆分为适应与学习、灵巧操作、感知能力和任务复杂度。按这个框架，你们在“适应与学习”和“任务复杂度”上已有中等能力，但在自动样品操作、物理感知和具身灵巧性上仍较低。这个定位不影响创新，反而能避免因“fully autonomous”被审稿人攻击。([PMC][2])

## 2. “13/15个数据集出现转变”与数据清单不一致

附件的数据表列出：

* LRS 7次；
* starch 4次；
* CHITO 2次；

总数是13次，而P1写的是13/15个数据集出现转变。必须在论文和补充材料中明确：

* 15个数据集分别是什么；
* 哪13个是阳性；
* 哪2个是阴性；
* 是否所有数据集在分析前已经定义；
* 是否有数据因QC被排除；
* 排除发生在观察结果之前还是之后。

这是一个容易被审稿人立即发现的计数问题。

## 3. “phase transition”命名过强

虽然正文使用的是“传输转变”，但代码和事件中仍有：

```text
phase_detect.py
phase_transition
mechanism_discovery
```

在没有DSC、XRD、NMR或其他结构/热学证据时，建议统一改为：

```text
transport_regime_change
conductivity_breakpoint
mechanistic_consistency
```

否则代码语义会与C4“不能证明结构或因果机制”的治理规则发生冲突。EIS模型解释本身依赖先验和模型选择，不同等效电路可能同样拟合同一组数据，因此描述性转折可以成立，但相变或唯一机理不能由EIS单独推出。([PMC][3])

## 4. Rb方法切换可能制造或放大断点

Stage0在不同温区会采用不同Rb提取方法：

* 深冷平台法；
* 过零点；
* 寻谷；
* 等效电路兜底。

这会产生一个关键风险：

[
T_{\text{break}}
\approx
T_{\text{Rb-method-switch}}
]

即所谓传输断点可能部分来自算法路由切换，而不完全来自材料行为。

附件已经有`rb_method_invariance`旁路分析，这是正确方向，但它必须从“v2旁路”升级成主论文的核心稳健性证据，至少报告：

1. 每条曲线的Rb方法随温度分布；
2. 断点是否与方法切换温度重合；
3. 仅用单一方法可覆盖的温区重算结果；
4. 多方法模型平均后的断点后验；
5. 去除等效电路兜底点后的敏感性；
6. 合成无断点数据下的假阳性率。

否则P1会是材料主线中最大的分析学风险。

## 5. 两套combined score存在“指标漂移”风险

附件中至少出现两套标量：

[
\log_{10}\sigma-1.0E_{a,\mathrm{high}}-0.2E_{a,\mathrm{excess}}
]

以及：

[
\log_{10}\sigma-3.0E_{a,\mathrm{high}}-0.5E_{a,\mathrm{excess}}
]

它们可能分别服务于审计评分、BO展示和campaign目标，但目前命名接近，容易造成：

* 最优trial定义不同；
* replay比较使用不同目标；
* termination与BO排序不一致；
* 论文中的“提升”取决于选用哪一套权重。

建议建立唯一的`ObjectiveRegistry`：

```yaml
objective_id: combined_score_campaign_v3
formula: ...
purpose: campaign_termination
frozen_at: ...
used_by:
  - history_db
  - replay
  - manuscript_figure_6
```

其他标量必须使用不同名称，不要都叫`score_v3`或`combined_score`。

## 6. G1是必要条件，但n=3只是最低门槛

线B缺少同配方独立重复，确实是当前最严重的实验缺口。G1必须明确为：

> 三个独立制备、独立装夹、最好跨日期的样品。

不能是同一片膜重复测三次；后者主要测到仪器和装夹重复性，不能估计配方—制备复现性。

而且在近似正态假设下，只有3个样品时，样本标准差的95%区间大约是：

[
0.52s \sim 6.28s
]

这意味着n=3能够证明“不是完全无重复”，但对复现地板的精确估计仍非常粗。建议将其描述为：

> **direct preliminary reproducibility estimate**

而不是稳定的材料体系复现地板。

# 四、对 M5-A 三重提交 Harness 的评价

## 结论

> **这是三个创新中当前工程价值最高、最接近形成真实湿实验贡献的一项。**

C(_P)、C(_M)、C(_E)分别表示：

* 物理动作是否发生；
* 测量是否具有计量资格；
* 结果是否可被当前科学主张使用。

这个分解非常适合湿实验，因为它明确拒绝：

```text
API调用成功
= 物理动作成功
= 测量有效
= 科学证据成立
```

这比普通Agent工具调用框架更接近真实实验室。

## 但当前有五个实质缺口

### 1. Shadow agreement可能是同源自证

当前shadow是在现有分析结果出来后，将同一结果再送给`CommitController`，并与原有`success/OK`比较。如果C(_M)又复用了相同的QA、KK和Rb逻辑，那么高agreement rate只能说明：

> 两个使用相同输入和相似规则的模块给出了相近答案。

它不能证明三提交更接近物理真值。

真正有价值的指标应是：

* 基线放行、Harness拒绝的案例；
* 基线盲目重试、Harness成功核对的案例；
* Harness错误阻断的假阳性率；
* 独立人工或传感器oracle判断。

### 2. C(_P)需要独立物理见证

若“动作是否发生”只根据应用日志或仪器软件返回值判断，C(_P)仍是软件状态，不是物理状态。

至少需要组合：

* 仪器ACK；
* 原始文件时间戳与哈希；
* 温控轨迹；
* 样品位置或夹具状态；
* 操作前后状态；
* 必要时人工确认。

### 3. C(_M)与KK警告策略存在潜在矛盾

主线中KK失败只是warning、不熔断。如果C(_M)代表“具有计量资格”，就需要定义：

* KK warning的数据可否进入BO；
* 可否支持单点电导；
* 可否支持温度转折；
* 可否支持机理一致性。

更合理的设计不是一个全局C(_M)，而是：

[
C_M(y,\text{intended use})
]

同一个谱可能足以支持C1观察，却不足以支持C3温度模型或C4机理一致性。

### 4. 哈希链还不是不可篡改证据

内部SHA256链可以发现局部修改，但如果控制数据库的人重写全部历史并重新计算链，仍可能得到一条自洽新链。

应增加外部锚定，例如：

* 定期签名的checkpoint；
* Git签名tag；
* RFC 3161时间戳；
* OSF或Zenodo公开哈希；
* 独立审计存储。

### 5. 尚未覆盖真正困难的故障

近期LAP预印本已提出InstrumentCard、仪器/样品排他锁、安全确认令牌，以及带单位、校准和不确定度的MeasurementResult。因此M5-A不宜把“设备锁、单位、参数Schema”作为核心新颖性；真正的区别应落在**从物理执行一直到证据提交和撤销的事务语义**上。([arXiv][4])

应至少验证：

| 故障          | Harness必须做出的正确行为    |
| ----------- | ------------------- |
| ACK丢失但动作已发生 | 核对后禁止重试             |
| 文件部分生成      | 隔离，不进入BO            |
| 仪器完成但未热平衡   | C(_P)=真，C(_M)=假     |
| 校准执行中失效     | 阻止证据提交              |
| 重复命令        | 识别同一physical effect |
| 样品ID错配      | 立即停止并隔离             |
| 传感器与仪器状态冲突  | 状态转为UNKNOWN而非强行判断   |

AILA在真实AFM任务中已经观察到Agent越界执行和对提示变化敏感的问题，这进一步说明安全边界和状态转移不能只放在Prompt中。([Nature][5])

# 五、对 M5-B 证明携带科学记忆的评价

## 结论

> **这是三个创新中算法与论文潜力最高的一项，但当前实现距离你们之前提出的“多Agent记忆、记忆压缩、决策不变压缩”仍有明显距离。**

现有实现的亮点是：

* SQLite证据超图；
* 四值逻辑；
* 最小支持集；
* 独立支持计数；
* 上游证据失效后的传播；
* 使用KK符号bug和ECE泄漏作为真实风格fixture。

这已经超越普通向量数据库。

## 但它目前更准确的名称是：

> **scientific claim truth-maintenance prototype**

还不能完整称为：

> **multi-agent scientific memory system**

因为附件尚未显示以下能力：

* 多Agent并发读写；
* 版本快照与过期写入检测；
* 角色权限；
* 同源证据去重；
* 摘要与原始记录双层存储；
* 记忆压缩；
* 压缩前后决策不变性；
* 冲突合并；
* 选择性遗忘；
* 对BO和下一实验的影响传播。

MemoryAgentBench把Agent记忆能力至少分为准确检索、测试时学习、长程理解和选择性遗忘；现有系统还主要覆盖“冲突与失效维护”，没有覆盖完整记忆能力谱。([arXiv][6])

TierMem也已经提出“摘要层＋不可变原始日志＋必要时回溯原始证据”。因此，你们不能只以“有原始账本和可回溯摘要”作为创新；真正的新颖性应是：

> **证据失效是否改变主张、下一实验和模型状态，以及记忆压缩是否保持这种科学决策不变性。** ([arXiv][7])

## 最关键的缺失闭环

当前似乎是：

```text
证据失效
→ 主张图重新判定
```

真正需要做到：

```text
证据失效
→ 派生指标撤销
→ 主张重新判定
→ BO训练集重建
→ 代理模型重训
→ 历史推荐标记为受污染
→ 下一实验策略重新计算
```

只有完成这一步，M5-B才从“知识图谱功能”变成“自主科学记忆”。

## 当前fixture数量不足

两个真实风格错误是很好的起点，但无法证明泛化。建议建立不少于以下类型的场景集：

* 原始数据完全失效；
* 部分温点失效；
* 有替代独立证据；
* 支持和反驳同时存在；
* 分析模型版本撤销；
* Skill证书撤销；
* 同一文献被多个Agent重复引用；
* 新证据缩小适用域；
* 旧结论被更新但非完全推翻；
* 摘要遗漏反证；
* Agent基于过期图版本写入；
* 失效是否应改变下一实验。

评价指标应是失效传播precision/recall、错误主张保留率、错误决策保留率，而不只是`acceptance_pass=True`。

# 六、对 M5-C 可认证 Scientific Skills 的评价

## 结论

> **概念正确，但目前最容易被审稿人认为是“Schema设计而非科学结果”。**

现有组件包括：

* Skill合同；
* Skill证书；
* 生命周期；
* 注册表；
* 组合相容性；
* 风险—覆盖曲线；
* 认知账户与执行账户分离。

其中最有潜力的是：

> **高认知声誉不自动获得高物理执行权限。**

例如，一个Agent可以在文献推理上长期表现很好，但仍然没有权力执行高风险、不可逆或超适用域的操作。这个双账户结构比普通“Agent评分”更适合实验室。

## 目前缺少的是“证书如何产生”

如果一个Skill只是声明：

```yaml
certified: true
```

那它不是真正的可认证Skill。

证书至少要来自三类证据：

1. **形式验证**：类型、单位、边界、状态机、权限、资源冲突；
2. **统计验证**：在认证域中的成功率、QC通过率、置信下界和失败分布；
3. **计量验证**：校准、原始数据、测量不确定度、分析版本和参考程序。

还需要证明：

* Skill只能在认证适用包络内执行；
* 固件或代码变化后证书自动失效；
* 撤销Skill后，其产生的历史证据能被找到并重新评价；
* 多个Skill组合时，前一个的后置条件真正满足下一个的前置条件。

SkillsBench发现，人工整理的Skills平均有明显帮助，但效果高度依赖任务，部分任务反而退化；模型自行生成Skills平均没有收益。这说明你们必须做`no skill / curated skill / self-generated skill`三臂对照，而不能以“有一个Skill包”作为能力证明。([arXiv][8])

## 第一批应真正接入的Skill

建议不是再写抽象Demo，而是直接把现有真流程拆成：

```text
verify_sample_identity
verify_thermal_equilibrium
acquire_eis_spectrum
admit_eis_measurement
extract_transport_metrics
update_bo_from_committed_evidence
```

其中：

* 前三个具有物理副作用或物理前置条件；
* 中间两个产生计量和认识论证据；
* 最后一个只能读取C(_E)=true的数据。

# 七、三个创新目前没有真正合成一个系统

这是当前最核心的结构性问题。

附件展示的是三个包：

```text
scientific_harness/
scientific_memory/
scientific_skills/
```

但还没有证明以下唯一链路已经成立：

```text
Agent Proposal
→ Skill匹配与证书验证
→ Harness Prepare
→ 真实物理执行
→ C_P
→ 测量QC
→ C_M
→ 针对当前主张进行证据准入
→ C_E
→ 写入证据超图
→ 更新BO
→ 证据或Skill失效
→ 撤销主张并重建BO
```

目前主线中的`/api/agent`仍可经过`hw.enqueue_command`驱动硬件，而M5-A只是shadow旁路。这意味着系统实际上存在一条绕过M5治理内核的物理执行路径。

在M5成为正式方法学贡献之前，必须满足一个强不变量：

> **所有改变真实样品或仪器状态的命令，只能经由Scientific Skill → Harness事务 → 权限引擎执行。**

不能同时保留另一条直接硬件通路。

# 八、几个容易被忽视但会被审稿人抓住的问题

## 1. 只存Prompt哈希，不足以复现LLM决策

哈希只能证明“某个已知Prompt没有变化”，但不能从哈希恢复：

* Prompt原文；
* 注入的历史数据；
* system/user消息；
* 模型返回；
* 重试过程；
* 解析器版本；
* provider路由。

建议保存一个受权限保护的完整LLM调用包，对外只公开哈希。无需保存隐藏思维链，但必须保存实际输入、结构化输出和调用元数据。

## 2. `temperature=0.0`不等于严格确定性

它只能降低随机性。真正的重现还依赖：

* 模型快照；
* provider；
  -路由；
  -服务端实现；
  -上下文顺序；
  -重试；
  -解析器版本。

所以建议使用“低随机性运行”而不是“确定性LLM”。

## 3. `thought_chain_event`建议改名

前端事件最好改成：

```text
decision_trace_event
agent_activity_event
rationale_summary_event
```

因为系统保存的是工具调用、摘要理由和状态，不应暗示保存或展示了模型的完整思维链。

## 4. 11条禁词只能治理措辞，不能治理科学内容

把“证明”替换成“支持”并不自动使主张正确。

M8中“40处过度声称降到0”可能部分只说明词面过滤成功。更强的评价应是：

* 主张是否有证据ID；
* 适用域是否完整；
* 反例是否保留；
* 效应量和区间是否存在；
* 主张等级是否与证据匹配；
* 删除所有禁词后，是否仍然存在隐含过度推断。

## 5. Top-1稳定不等于候选正确

S10对权重扰动后top-1稳定，只能证明打分规则稳定。附件也承认，流行度基线同样可能选中LRS。

因此应把：

> `top1_stability = 1.0`

解释为**评分函数鲁棒性**，而不能解释为**发现有效性**。

# 九、对论文与发表路径的客观判断

## A轨：表征受限的证据治理型自主发现

当前最合理的主论文应当聚焦：

> **在EIS-only、样本少、实验昂贵、机理不可辨识的条件下，如何量化自主发现的复现下界、可辨识上界和可允许主张。**

这个主线已经具备：

* 真实数据；
* 多批重复；
* 迁移候选；
* 正例和边界案例；
* 真实闭环；
* 前瞻冻结；
* 校准；
* 负结果；
* 主张治理。

完成G1并解决Rb方法不变性、数据集计数、目标函数版本等问题后，**面向材料信息学、自主实验或化学信息学的领域期刊是合理目标**。但“已经达到某档期刊”仍不能仅凭两份报告确定，需要看完整手稿、图和原始数据。

## B轨：Scientific Agent基础设施方法论文

目前还不应以顶刊方法学成果提交，因为：

* M5尚未进入主执行通路；
* Harness没有真机故障对照；
* Memory没有完整多Agent和压缩；
* Skills没有真实认证实验；
* 三个组件没有端到端撤销闭环；
* 只有27个自定义测试和3个Demo；
* 缺独立基线和跨任务泛化。

NIST目前仍把样品管理、仪器控制、数据与知识管理、算法与模型集成列为自主实验室需要共同解决的四类标准问题，这恰好说明方法论文必须证明跨层集成，而不仅是三个局部软件模块。([NIST][9])

## 不建议把A轨和B轨全部塞进一篇论文

最容易发生的问题是：

* 材料审稿人觉得Agent方法太复杂；
* AI审稿人觉得数据规模太小；
* 自动化审稿人觉得物理自主性不足；
* 三条创新各自只有有限篇幅；
* 最后没有一个贡献被完整证明。

更合理的是：

1. **A轨论文**：真实实验、复现地板、可辨识上限、治理闭环；
2. **B轨论文**：三提交Harness＋反事实失效记忆＋可撤销Skills，使用A轨作为真实案例；
3. M5-C作为B轨支撑层，除非双账户机制进一步形式化，否则不必单独作为第三篇主论文。

# 十、优先级建议

## P0：在下一轮实验前完成

1. 解释13/15数据集；
2. 统一或版本化两套combined score；
3. 将`phase_transition`改成`transport_regime_change`；
4. 将`mechanism_discovery`改成`mechanistic_consistency`；
5. 明确C(_M)和C(_E)对不同用途的准入规则；
6. 保存完整LLM调用包，而不只是Prompt哈希；
7. 审计所有绕过Harness的硬件写路径。

## P1：做G1时同步获取M5-A真机证据

* 三个独立制备重复；
* shadow harness全开；
* 记录命令、ACK、温度轨迹、原始文件和样品状态；
* 安全注入ACK丢失、重复事件、延迟文件、过期校准、样品ID错配等故障；
* 比较主线、shadow和人工oracle；
* 不只统计agreement rate，还统计“阻止了哪些错误”。

## P2：把三包接成一个完整事务

至少完成一次：

```text
Skill证书有效
→ Harness执行
→ 证据提交
→ Memory入图
→ BO更新
→ 人为撤销校准或Skill
→ 证据失效
→ 主张降级
→ BO自动重建
```

这一次完整演示的价值，会高于再增加几十个孤立单元测试。

## P3：建立真正的Agent方法学基准

| 模块           | 最低有说服力的验证                     |
| ------------ | ----------------------------- |
| Harness      | 多类故障注入、基线对照、真实物理见证            |
| Memory       | 多Agent版本冲突、证据去重、失效传播、下一决策影响   |

| Dual account | 风险—覆盖曲线、权限降级、消融               |
| 总系统          | 错误证据进入BO率、错误主张率、自主覆盖率         |

# 三、SciTX与当前项目的对应关系

## 1. 已经高度对应的部分

当前M5-A已经实现：

* `PhysicalCommit`：C(_P)，动作是否发生；
* `MetrologicalCommit`：C(_M)，测量是否具备计量资格；
* `EpistemicCommit`：C(_E)，结果是否能进入BO、主张和长期记忆；
* `timeout ⇒ reconcile before retry`；
* append-only SHA256事件链；
* 故障注入；
* shadow recorder；
* “无C(_E)不得进入BO”的不变量。

这些功能与SciTX的核心思想是吻合的。

当前项目还已经提供了SciTX所需要的基础能力：

```text
Stage0 QA
→ KK检查
→ Rb提取
→ 电导率计算
→ Arrhenius模型竞争
→ objective_valid
→ Stage1拒绝无效数据入库
```

因此，从软件结构上看，你们不是从零开始构建Harness，而是已经有一条可靠度较高的确定性证据管道。 

---

## 2. 当前SciTX最大的结构性矛盾

### Harness没有真实控制权

目前真实硬件路径仍然是：

```text
/api/agent
→ planner
→ critic
→ orchestrator
→ hw.enqueue_command
```

而M5-A只在分析结果返回后，将结果旁路送入`CommitController`记录C(_P)/C(_M)/C(_E)。 

这意味着当前Harness是：

> **观察者和审计者。**

而不是：

> **真实实验动作的事务协调器。**

因此，当前系统即使发现：

* Skill证书无效；
* 样品状态未知；
* 动作尚未核对；
* C(_M)不满足；
* Agent越权；

也不一定能够阻止另一条API路径直接调用硬件。

这与SciTX最重要的不变量冲突：

```text
任何改变真实样品或仪器状态的命令
必须只能经过SciTX
```

AILA在真实AFM实验中已经观察到Agent偏离指令、“sleepwalking”和对轻微Prompt格式变化敏感的问题，因此实验边界不能只依赖Prompt或事后审计，必须放到确定性的运行时控制层。([Nature][2])

---

## 3. 当前C(_P)还不是严格意义上的“物理信念态”

C(_P)的目标应该是判断：

[
\text{某个物理作用是否真实发生}
]

但附件没有显示C(_P)已经综合使用独立物理见证，例如：

* 仪器ACK；
* 原始文件生成；
* 温控轨迹；
* 样品位置；
* 夹具状态；
* 操作前后状态；
* 人工或第二传感器确认。

如果C(_P)主要来自同一个软件调用结果，那么它更接近：

```text
command_status
```

而不是：

```text
physical_effect_belief
```

建议严格区分三个对象：

```text
attempt_id          软件尝试
physical_effect_id  推断或确认的真实物理作用
evidence_id         最终提交的证据
```

否则无法正确处理：

```text
ACK丢失，但测量实际上已经完成
```

或者：

```text
软件返回成功，但样品并未达到平衡
```

近期LAP预印本已经把仪器能力卡、资源锁、样品锁、安全确认令牌、物理单位、校准和不确定度纳入Agent—仪器协议。因此，SciTX未来的新颖性不能仅是仪器锁和参数Schema，而应集中在**物理作用核对、测量准入、证据提交和事后撤销**。([arXiv][3])

---

## 4. 当前C(_M)过于接近“已有QC的第二次包装”

附件说明C(_M)复用了现有QA、KK和Rb规则。

这在工程上合理，但会产生两个问题。

### 问题一：shadow agreement可能是同源一致

如果：

```text
原系统判定 = QA/KK/Rb
C_M判定     = 同一组QA/KK/Rb
```

那么二者高度一致，只能说明软件重构正确，不能说明C(_M)更接近真实计量资格。

### 问题二：计量资格不是全局布尔量

当前KK失败只产生warning，不一定熔断；但同一张谱对于不同科学用途，其有效性不同。

更合理的定义应当是：

[
C_M(y,u)
]

其中(u)是预期用途。

例如：

| 用途       | 某张存在KK warning的谱是否可用 |
| -------- | -------------------- |
| 报告单次原始观察 | 可能可用                 |
| 计算单点电导率  | 条件性可用                |
| 判断温度断点   | 可能不足                 |
| 区分传导机制   | 通常不足                 |
| 更新BO     | 取决于目标和不确定度           |

所以C(_M)不应只是：

```text
true / false
```

而应是：

```text
valid_for:
  - descriptive_observation
limited_for:
  - conductivity_estimation
invalid_for:
  - mechanism_discrimination
```

---

## 5. 当前C(_E)仍未真正和主张图绑定

SciTX中最有创新价值的不是测量是否“总体有效”，而是：

[
C_E(e,c)
]

即证据(e)能否支持具体主张(c)。

例如同一组EIS数据可能：

* 支持“出现了可复现温度依赖变化”；
* 部分支持“存在经验断点”；
* 不支持“发生了结构相变”；
* 不支持“唯一证明了某质子传导机制”。

当前项目已经有C0–C5主张阶梯，并将EIS-only主张硬封顶在C4，这是很好的基础。

但目前C(_E)和Stage3主张审计仍是两个分开的机制。理想关系应为：

```text
EvidenceCommit
→ 自动写入证据图
→ 根据claim_id判断可支持等级
→ S14只消费已提交证据
```

而不是：

```text
Harness一套C_E
Stage3再独立做一次claim guardrail
```

---

## 6. 对SciTX的客观评价

### 当前可以声称

> 已实现并通过软件测试的三提交证据准入原型，并完成了与真实在线分析流程的shadow接口。

### 当前不宜声称

> 已实现并验证了真实湿实验中的证据事务型Harness。

### 核心缺口

1. 未掌握所有硬件写权限；
2. 缺独立物理见证；
3. 缺样品状态信念模型；
4. C(_M)尚未按用途区分；
5. C(_E)尚未按主张绑定；
6. 缺真机故障对照；
7. 缺补偿图和样品隔离语义；
8. 哈希链尚未外部锚定。

# 四、E-Mem与当前项目的对应关系

## 1. 当前实现与原创新的对应度很高

现有M5-B已经包括：

* SQLite证据超图；
* `UNKNOWN / SUPPORTED / REFUTED / CONTESTED`四值逻辑；
* 最小支持集；
* 独立支持计数；
* 上游证据失效后的传播重判；
* KK符号bug和ECE数据泄漏fixture。

这已经明显超过普通RAG或向量记忆。

特别是“失效传播”与当前项目非常匹配，因为项目已经真实经历过：

* KK符号bug；
* 随机划分造成的ECE泄漏；
* 分析版本更新；
* legacy与v2结果分层；
* 某些分析结果被降级为HOLD。

所以E-Mem不是为了制造一个虚构需求，而是在解决项目中已经发生过的科学知识失效问题。

---

## 2. 但当前更像“科学真值维护器”，还不是完整Agent记忆

MemoryAgentBench把Agent记忆至少分为：

1. 准确检索；
2. 测试时学习；
3. 长程理解；
4. 选择性遗忘。

现有方法总体上仍不能同时做好这四项。([OpenReview][4])

当前M5-B主要覆盖：

* 主张状态；
* 支持关系；
* 反驳关系；
* 证据失效。

附件尚未显示它已经覆盖：

* 多轮Agent实际检索；
* 不同角色Agent的上下文构造；
* 跨运行记忆更新；
* 多Agent并发写入；
* 过期快照检测；
* 选择性遗忘；
* 记忆压缩；
* 摘要回溯；
* 对下一实验选择的影响。

因此，现阶段更准确的命名是：

> **证明携带的科学主张真值维护原型。**

而不是：

> **完整多Agent科学记忆系统。**

---

## 3. 当前项目的几种“记忆”还没有统一

现有系统中至少存在：

| 当前记忆形态               | 实际作用           |
| -------------------- | -------------- |
| Stage1 history DB    | 配方—目标值历史       |
| round logger         | 每轮建议、结果和决策摘要   |
| Stage3 evidence seed | 结构化科学证据        |
| agentic memory       | advisory层的情景记忆 |
| M5-B超图               | 主张和证据失效传播      |
| 原始数据文件               | 权威实验记录         |
| Prompt哈希             | LLM调用指纹        |

这些对象目前是并列存在的，而不是一个统一的四层记忆：

```text
L0 原始事件
L1 有效证据
L2 主张与假设
L3 Agent工作缓存
```

特别需要注意的是，系统目前只保存Prompt SHA256指纹，不保存完整Prompt原文。

这能证明：

> 某个已知Prompt是否被修改。

但不能恢复：

* 当时完整system message；
* 注入的实验历史；
* 文献上下文；
* 模型返回原文；
* JSON解析失败与重试；
* provider具体路由；
* Agent基于哪个证据图版本作答。

对科学记忆而言，这意味着Agent决策的认识论上下文仍不完整。

---

## 4. 多Agent一致性尚未真正被测试

“有多个Agent模块”不等于“实现了多Agent记忆”。

真正的多Agent记忆至少需要处理：

```text
Agent A基于图版本v10支持H
Agent B基于图版本v12反驳H
Agent C重复引用了A使用的同一篇文献
```

系统必须知道：

* A的写入是否过期；
* C是否只是重复同一证据；
* B是否拥有独立证据；
* H应该进入CONTESTED还是被覆盖；
* 哪个Agent有权修改主张状态。

当前超图有“独立支持计数”，这是好的起点，但附件没有显示独立根已经绑定到：

```text
文献：DOI + 具体实验
实验：physical_effect_id + 独立样品批次
分析：不构成新的独立证据根
Agent发言：不构成证据根
摘要：不构成证据根
```

如果缺少这种根来源语义，多Agent重复转述仍可能造成“共识膨胀”。

---

## 5. 记忆压缩这一原创核心目前基本尚未实现

TierMem已经提出了：

* 快速摘要层；
* 不可变原始日志；
* 摘要不足时升级到原始记录；
* 验证后写回带来源的摘要。

因此，“摘要＋原始日志＋可回溯”本身已经不是足够强的新颖点。([arXiv][5])

你们原创新真正强的部分是：

> **压缩前后，科学主张和下一实验决策不发生不可接受的变化。**

即：

[
D_{\mathrm{sci}}(M,\hat M)
==========================

D_{\mathrm{claim}}
+
D_{\mathrm{action}}
+
D_{\mathrm{scope}}
+
D_{\mathrm{counterevidence}}
]

目前附件没有显示：

* `CompressionCertificate`；
* 压缩前后主张等级比较；
* 压缩前后下一实验Top-k比较；
* 适用条件丢失检测；
* 反证丢失检测；
* 摘要版本随证据图变化自动失效。

所以“决策不变压缩”仍然是尚未落地的算法创新，不应算作当前M5-B已经完成的功能。

---

## 6. 失效传播还没有进入BO和真实决策

当前路径看起来是：

```text
证据失效
→ 超图中的主张重新判定
```

真正完整的E-Mem应是：

```text
证据失效
→ 派生指标撤销或重算
→ 主张状态更新
→ Stage1 history DB重建
→ BO训练集重建
→ 代理模型重训
→ 历史推荐标记受污染
→ 终止判断重算
→ 下一实验变化
```

这一步是M5-B从“图数据库功能”变成“科学Agent记忆”的关键。

如果KK符号bug导致部分电导或模型结果失效，E-Mem必须回答：

* 哪些BO trial因此失去资格；
* 是否需要重训GP；
* 原来的“best trial”是否仍然成立；
* 之后的推荐是否受到污染；
* 当前闭环应该继续、回退还是重新确认。

附件尚未表明这条链已经闭合。

---

## 7. 对E-Mem的客观评价

### 当前可以声称

> 已实现可执行的科学主张—证据超图和反事实证据失效传播原型。

### 当前不宜声称

> 已实现多Agent科学记忆和决策不变记忆压缩。

### 核心缺口

1. 没有统一L0–L3记忆体系；
2. 没有真实多Agent并发和版本一致性；
3. 没有角色权限和写入门；
4. 没有完整Prompt/上下文溯源；
5. 没有压缩证书；
6. 没有决策不变测试；
7. 失效尚未传播到BO和下一实验；
8. 独立证据根语义不充分。

# 五、PC-Skills与当前项目的对应关系

## 1. 项目非常适合做Scientific Skills

现有流程天然可以被拆成一组真实科学技能：

```text
verify_sample_identity
verify_thermal_equilibrium
acquire_eis_spectrum
assess_eis_quality
extract_rb_and_conductivity
fit_temperature_models
admit_measurement_for_bo
generate_next_recipe
audit_scientific_claim
```

现有代码中已经存在：

* 输入参数；
* 参数范围；
* QA规则；
* KK规则；
* Rb策略；
* safety validator；
* Pydantic Schema；
* objective_valid；
* fallback；
* claim guardrail。

所以你们具备把普通函数升级为Scientific Skill的良好基础。

当前M5-C也已经实现了：

* `ScientificSkillContract`；
* `SkillCertificate`；
* 生命周期；
* 注册表；
* 组合相容性；
* 风险—覆盖曲线；
* 认识论账户与执行账户分离。

其中“认知能力不自动产生物理执行权限”是非常好的设计：

```text
Agent在文献推理中表现好
≠
Agent可以自动操作仪器
```

---

## 2. 当前证书更像Schema，不是被验证产生的证书

真正的PC-Skills证书应回答：

> 这个Skill为什么可以在当前仪器、样品和参数域中被信任？

而不能只保存：

```yaml
certified: true
```

完整证书至少需要三部分。

### 形式证书

证明：

* 类型正确；
* 单位正确；
* 参数不越界；
* 状态机没有非法路径；
* 资源不冲突；
* 前置条件充分；
* 权限正确；
* Skill组合合法。

### 统计证书

证明在认证适用域中：

* 后置条件成功率；
* QC通过率；
* 故障分布；
* 置信下界；
* 跨日期和批次稳定性；
* 罕见严重故障概率。

### 计量证书

证明：

* 仪器校准有效；
* 原始数据完整；
* 测量不确定度可追踪；
* 分析版本冻结；
* 参考程序通过；
* 输出适合预期科学用途。

附件没有显示当前证书已经通过以上流程自动产生，因此目前应称为：

> **可认证Skill的数据模型和治理原型。**

而不是：

> **已经认证的Scientific Skills。**

---

## 3. 当前主流程仍然绕过Skill注册表

即使M5-C注册表判断某Skill：

* 未认证；
* 已过期；
* 超适用域；
* 需要人工批准；

现有`/api/agent → hw.enqueue_command`路径仍有可能直接执行。

所以当前PC-Skills尚未拥有真正的执行权。

其必须成为：

```text
Agent Proposal
→ Skill Matcher
→ Certificate Check
→ Applicability Envelope Check
→ Harness Transaction
→ Instrument Gateway
```

而不是一个附加的软件包。

---

## 4. 缺少真实的Skill适用包络

一个Skill不是对所有输入都同样有效。

例如EIS采集Skill至少依赖：

* 仪器型号；
* 固件；
* 频率范围；
* 阻抗范围；
* 温度范围；
* 样品厚度；
* 电极面积；
* 当前热平衡状态；
* 样品是否已经经历过循环；
* 校准版本；
* 下游分析版本。

所以应定义：

[
\mathcal E_K
============

{x,s,i,v:
P(G_K\mid A_K,x,s,i,v)\ge1-\delta}
]

当前Skill合同可能包含部分字段，但附件没有显示：

* 认证包络如何从实验数据估计；
* 超出包络如何自动阻断；
* 包络如何随仪器漂移更新；
* 版本变化如何自动触发降级。

---

## 5. Skill生命周期尚未和历史证据连接

当前已经有Skill生命周期，这是正确的。

但“可撤销Skill”的真正含义不是：

```text
以后不再调用这个Skill
```

而是：

```text
Skill版本失效
→ 找到该版本产生的全部测量
→ 判断哪些测量受影响
→ 更新证据图
→ 降级或撤销下游主张
→ 重建BO
```

如果某个Rb提取Skill后来发现方法切换造成系统偏差，仅仅把Skill设为`REVOKED`是不够的。系统还需要找到：

* 哪些温点用了该方法；
* 哪些断点依赖这些点；
* 哪些主张依赖这些断点；
* 哪些BO目标来自这些结果；
* 哪些候选排序因此需要重算。

这正是PC-Skills、SciTX和E-Mem必须合成的地方。

---

## 6. Skill效果还缺严格对照

SkillsBench发现：

* 人工整理的Skills平均能提高任务通过率；
* 但效果高度依赖任务；
* 一部分任务使用Skill后反而下降；
* 模型自生成Skill平均没有产生收益。

这说明“有Skill”不能被直接视为改进。([arXiv][6])

你们至少需要比较：

```text
无Skill
人工策划Skill
Agent自生成Skill
经过认证的Scientific Skill
```

并测量：

* 任务成功；
* 错误证据提交；
* 越权动作；
* 前置条件漏检；
* QC失败；
* token和延迟；
* 人工干预；
* 科学主张错误率。

近期Notes2Skills还指出，实验记录中的事实、判断和建议不能被不加区分地编译为可执行指令，否则可能把不确定判断“洗白”为确定行动。你们的Skill编译器也需要保留这种认识论状态。([arXiv][7])

---

## 7. 对PC-Skills的客观评价

### 当前可以声称

> 已实现Scientific Skill合同、证书Schema、生命周期、组合检查和认知—执行双账户原型。

### 当前不宜声称

> 已实现携证、可证明、可撤销的真实湿实验Scientific Skills。

### 核心缺口

1. 证书没有真实产生流程；
2. 没有形式、统计和计量三层认证；
3. 主流程不强制经过Skill；
4. 没有真实适用包络；
5. 没有运行时Evidence Bundle；
6. 没有漂移检测；
7. 没有历史证据撤销；
8. 没有Skill有无和来源的对照实验。

# 六、三项创新之间目前最关键的断裂

当前三个包分别存在：

```text
scientific_harness/
scientific_memory/
scientific_skills/
```

但没有证据表明它们已经形成以下唯一权威链：

```text
Agent Proposal
        ↓
PC-Skills匹配与认证
        ↓
SciTX Prepare
        ↓
真实物理执行
        ↓
C_P：物理作用核对
        ↓
C_M：针对用途的计量准入
        ↓
C_E：针对主张的证据准入
        ↓
E-Mem写入证据图
        ↓
BO更新
        ↓
Skill/校准/证据失效
        ↓
主张撤销 + BO重建
```

## 当前实际状态更接近

```text
现有Stage0/Stage1主线正常运行
              │
              ├── M5-A旁路观察
              ├── M5-B独立Demo
              └── M5-C独立Demo
```

这是当前最大的问题。

不是功能数量不够，而是：

> **三个创新没有获得系统权威性。**

# 七、现有主项目为三项创新提供了什么独特优势

虽然M5目前整合不足，但你们拥有一个别人很难复制的实验条件。

## 1. EIS-only带来的认识论限制

没有结构表征意味着系统必须经常输出：

```text
INCONCLUSIVE
```

这非常适合验证C(_E)、主张等级和证据守恒记忆。

许多Agent系统只在“任务是否完成”层面验证；AILA也发现领域知识问答能力不能自动转化为真实实验能力，并强调真实工作流评测和安全协议的重要性。([Nature][2])

## 2. 样本少、实验昂贵

这使得：

* 盲目重试；
* 错误数据进入BO；
* 无效证据写入长期记忆；
* Skill超适用域执行；

都具有真实代价，而不是软件Benchmark中的抽象错误。

## 3. 已经有真实错误fixture

KK符号bug、ECE泄漏、Rb方法差异、代理复现地板，都是构建科学失效传播Benchmark的好素材。

## 4. 已有正例、反例和不可辨识结果

这使E-Mem可以测试：

* 支持；
* 反驳；
* 冲突；
* 证据不足；
* 适用域缩小；
* 主张降级。

---

# 八、三项创新不能替代的科学问题

需要明确：

> 三项Agent创新主要解决“错误是否进入系统、是否被传播、是否被过度声称”，不能创造缺失的实验信息。

它们不能直接解决：

| 当前科学问题        | 三项创新能做什么  | 不能做什么           |
| ------------- | --------- | --------------- |
| 只有EIS、无结构表征   | 阻止机制过度声称  | 不能识别真实微观结构      |
| 线B无同配方重复      | 管理复现不确定性  | 不能替代真实重复实验      |
| 闭环只有10点/2前瞻轮  | 防止声称收敛    | 不能证明BO已经收敛      |
| Rb方法可能随温度切换   | 记录方法和不确定度 | 不能自动消除算法偏差      |
| CHITO仅n=2     | 标记证据等级低   | 不能将n=2变成可靠反例    |
| 单曲线QC不能预测跨片复现 | 正确拒绝过度自信  | 不能凭Agent产生复现预测器 |

项目报告已经明确：线B复现地板仍是代理、闭环轨迹短、复现感知接近随机、机理只能到描述符层。

# 九、当前仍存在的项目级问题

## 1. G1只解决A轨，不解决B轨

凹凸棒土同配方重复实验能够解决：

* 线B真实复现地板；
* 候选差异是否高于噪声；
* 边缘最优还是内部最优。

但它只能顺便为M5-A提供shadow数据。

它不能自动证明：

* Harness能阻止错误物理动作；
* Memory能处理多Agent冲突；
* 压缩保持决策不变；
* Skill证书可靠；
* Skill撤销能重建BO。

所以：

> “G1是唯一硬门槛”仅适用于当前材料—治理论文，不适用于三项Agent创新论文。

---

## 2. 数据集计数需要统一

附件的数据表列出：

* LRS 7次；
* starch 4次；
* CHITO 2次；

合计13次，但P1部分使用“13/15个数据集出现转变”。

这不一定必然错误，可能还有两个未在简表中列出的数据集，但正式手稿必须明确：

* 15个数据集具体是什么；
* 哪13个阳性；
* 哪2个阴性；
* 哪些被QC排除；
* 排除规则何时冻结。

否则会影响E-Mem中的证据根和P1的统计口径。 

---

## 3. 两个目标标量需要版本化

架构报告中出现：

[
\log_{10}\sigma
-1.0E_{a,\mathrm{high}}
-0.2E_{a,\mathrm{excess}}
]

以及campaign目标：

[
\log_{10}\sigma
-3.0E_{a,\mathrm{high}}
-0.5E_{a,\mathrm{excess}}
]

它们可能有不同用途，并不一定矛盾；但必须具有不同的`objective_id`、用途和冻结版本。

否则当证据失效或BO重建时，E-Mem无法判断：

* 哪个分数用于候选排序；
* 哪个分数用于终止；
* 哪个分数用于论文图；
* 哪个版本定义了“最优trial”。

---

## 4. Rb方法路由必须进入Skill证书和C(_M)

Stage0会在深冷平台法、过零点法、寻谷法和等效电路法之间路由。

这意味着Rb不是单一测量算子，而是一个条件性Skill组合：

```text
select_rb_method
→ extract_rb
→ estimate_conductivity
```

若断点温度和方法切换温度相近，必须排查算法断点。

这个问题不能只放在旁路敏感性分析中，应进入：

* Skill适用域；
* C(_M)用途准入；
* E-Mem分析版本依赖；
* 主张失效传播。

---

## 5. 自主程度的定位需要更准确

按SDL性能评价框架，自主程度应与运行寿命、参数空间、精度、吞吐、实验成本和优化表现一起报告；有人负责样品制备、连接硬件、启动测量或重置系统的系统，更接近半闭环或混合自主，而不是完全闭环。([Nature][8])

你们现阶段最准确的描述是：

> **human-supervised、evidence-governed、semi-closed-loop scientific agent system。**

这不会削弱创新，反而使自主权边界更可信。

---

# 十、三项创新现在最应该合成的唯一关键实验

目前最缺的不是再增加模块，而是完成一次真正的跨层因果演示：

```text
1. 一个真实EIS Skill通过证书检查
2. SciTX启动真实事务
3. 发生可控故障：
   ACK丢失 / 文件延迟 / 校准失效 / 样品ID错配
4. SciTX正确核对物理状态
5. 错误测量没有进入BO
6. E-Mem记录失效并撤销相关主张
7. Skill版本被降级或撤销
8. BO训练集自动重建
9. 下一实验因此发生可解释变化
10. 与没有三项保护的基线比较
```

这个实验同时证明：

* Harness不是旁路日志；
* Memory不是独立知识图；
* Skill不是Schema；
* 三者共同改变了真实科学系统的行为。

其评价对象不是材料性能，而是：

| 指标                                | 说明                |
| --------------------------------- | ----------------- |
| invalid-evidence admission rate   | 无效证据进入BO的概率       |
| blind-retry rate                  | 未核对便重试的比例         |
| physical-effect identity accuracy | 是否正确识别物理作用已经发生    |
| invalidation propagation recall   | 失效证据的下游影响是否全部找到   |
| wrong-claim survival rate         | 错误主张是否仍保持有效       |
| BO contamination rate             | 失效结果是否仍留在训练集      |
| skill-revocation coverage         | Skill撤销是否覆盖全部历史影响 |
| autonomy coverage at bounded risk | 在限定风险下能够自动执行多少动作  |

# 十一、最终客观评价

## 对应关系怎么样？

### 概念层：**非常好**

三项创新不是外加包装，而是直接对应现有项目中真实出现的：

* 物理动作与软件状态不一致；
* 测量有效性和科学可用性不一致；
* 数据与分析可能事后失效；
* 多Agent可能重复错误证据；
* Skill可能越界或失效；
* EIS-only条件下结论必须封顶。

### 软件实现层：**中等**

三个模块都有真实代码和测试，不是纯概念。

### 主流程整合层：**偏低**

Harness仍是shadow，Memory没有控制BO，Skills没有成为唯一调用入口。

### 真实实验验证层：**低**

尚未通过真机故障、跨批运行和基线对照证明三项机制真正减少了错误科学结论。

## 当前项目最准确的定位

> **一个已经运行的、证据治理型、表征受限EIS自主实验原型，加上三个尚未取得主流程权威性的Scientific Agent基础设施原型。**

## 最大优势

不是有更多Agent，而是：

> 你们已经拥有一个会真实产生无效测量、分析版本变化、证据冲突、不可辨识结果和昂贵实验决策的环境。

这正是验证Scientific Harness、科学记忆和Scientific Skills的稀缺条件。

## 最大问题

不是某个功能缺失，而是：

> **三项创新目前还不能共同决定什么可以被执行、什么可以被记住、什么可以被相信。**

当所有真实动作必须经PC-Skills和SciTX、所有BO更新必须消费E-Mem中的已提交证据、任何Skill或证据失效都会自动改变主张和下一实验时，这三项创新才从三个“做出来的软件包”，变成一个完整的Scientific Agent方法学贡献。
