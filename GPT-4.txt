* 黑灯实验室重点解决无人值守执行和连续运营。

Agent层的关键也不只是自然语言生成，而是把推理与行动结合起来，让模型能够选择和调用工具、利用环境反馈修正计划并积累经验。ReAct、Toolformer和Reflexion分别代表推理—行动交织、工具学习与反思记忆等重要路径；MCP负责Agent与工具、数据源和工作流连接，A2A则处理异构Agent之间的通信与协作。([OpenReview][3])

真正制约黑灯实验室规模化的通常不是某一台机器人或某一个大模型，而是端到端系统能否同时做到：设备互操作、机器可执行协议、测量校准、数据语义、完整溯源、异常恢复、模型不确定性管理和统一绩效评价。SiLA 2等标准重点解决设备能力和命令接口；FAIR原则要求数据以及产生数据的算法、工具和工作流可发现、可访问、可互操作、可复用；SDL评价还需要报告自主度、运行时间、参数空间、精度、吞吐、成本与优化表现。([sila-standard.com][4])

# 一、把两种模式统一成同一个科学决策问题

建议不要把迁移发现和闭环优化做成两套割裂系统，而是共享一个“部分可观测科学决策模型”。

真实但不可见的材料状态为：

[
z={\text{水合状态、酸分布、界面状态、微结构、老化状态、接触状态}}
]

系统能观察到的是：

[
y={Z(\omega,T),\text{热史、湿度、批次、几何、工艺、失败标签}}
]

智能体维护的不是一个“确定答案”，而是对潜在状态和竞争假设的信念分布：

[
b(z,H\mid D)
]

下一实验统一按以下效用选择：

[
a^*=\arg\max_a
\left[
\lambda,\mathrm{EIG}(H;Y\mid a,D)
+(1-\lambda),\mathbb{E}[\Delta HV]
-\beta C(a)-\gamma R(a)
\right]
]

其中：

* **迁移发现模式**提高 (\lambda)，优先选择最能区分竞争假设的实验；
* **闭环优化模式**降低 (\lambda)，优先改善多目标性能；
* (C(a)) 是实验成本；
* (R(a)) 是失败、越界和不可解释风险；
* 两种模式都使用同一套EIS质控、行为指标、证据门禁和记忆系统。

这比“迁移线用LLM、优化线用BO”更有研究价值，因为它把两者统一为：

> **在部分可观测、带噪声和高成本条件下，如何选择最有科学价值的下一实验。**

# 二、不要把单点电导率作为共同目标

建议把材料描述成一个统一的“传导行为向量”：

[
B=
[
\log\sigma(T_k),
AUC_{LT},
R_{LT},
E_a,
w_{\mathrm{Arr/VTF}},
T^*,
H_{\mathrm{thermal}},
D_{\mathrm{cycle}},
R_{\mathrm{batch}},
Q_{\mathrm{EIS}},
P_{\mathrm{feasible}},
C
]
]

核心组成包括：

| 层次     | 共同指标                              |
| ------ | --------------------------------- |
| EIS有效性 | 热平衡、线性、时间稳定性、KK/lin-KK一致性、频率窗充分性  |
| 传导行为   | 预定义温度锚点的电导率后验、低温曲线面积、低温保持率        |
| 温度模型   | Arrhenius、VTF、分段模型权重，变点概率与温度区间    |
| 稳定性    | 升降温滞后面积、循环漂移、恢复率                  |
| 复现性    | 批内重复性、独立批次复现概率                    |
| 可行性    | 可成膜、可装夹、可获得有效谱的概率                 |
| 科学可信度  | 主张—证据完整率、引用忠实率、无证据主张率             |
| 智能体校准  | Brier score、区间覆盖、选择性风险和拒答效用       |
| 优化效果   | simple regret、Pareto超体积、每个确认改进的成本 |

这样，迁移发现评价“预测签名是否出现”，闭环优化评价“行为向量是否改善”，不会出现两条线使用不同科学语言的问题。

# 三、迁移发现模式的推荐流程

### 1. 从“材料相似性”升级为“可迁移因果母题”

从酸–黏土文献中提取的重点不应只是“某材料与某材料相似”，而应是：

* 质子供体密度；
* 含水与低温水保持；
* 氢键网络连续性；
* 酸的固定和迁移；
* 黏土限域；
* 聚合物—黏土界面贯通；
* 聚合物链段运动；
* 冻结或相变抑制；
* 电极接触和几何伪影。

A-Lab类系统说明了文献知识、历史数据、机器学习、主动学习和实验反馈可以共同组成闭环，并且失败实验本身应当产生可行动的信息。([Nature][2])

### 2. 为每次跨体系推理建立“桥接假设”

例如：

> 酸–黏土体系中的低温传导现象能够迁移到淀粉–黏土膜。

不能作为一个整体假设。应拆成：

1. 生物聚合物能够保持足够的质子供体或酸；
2. 低温下仍存在连续的含水/氢键网络；
3. 聚合物不会切断黏土界面的传导连通性；
4. 制膜和调理过程不会造成不可逆脱水；
5. EIS中的变化不是接触或几何伪影。

每一个桥接假设都要有：

* 支持文献；
* 适用条件；
* 预测的EIS签名；
* 失败反例；
* 可推翻它的实验。

### 3. 把机理文字编译成实验前预测

例如某假设必须提前给出：

* 哪些温度锚点会发生变化；
* 是否预计存在变点；
* 升温和降温是否应重合；
* DRT或谱形应出现什么变化；
* 哪些材料应为正例；
* 哪些结构相似材料反而应该失败；
* 失败后否定的是哪一条桥接假设。

然后冻结预测，禁止实验结果出来后重新改写解释。

### 4. 候选组合不能只选“最看好的”

建议每轮组合同时包含：

* 预测正例；
* 结构相近但应失败的对抗性反例；
* 母体系对照；
* 空白或过程对照；
* 一个用于检验智能体是否在泛化式讲故事的候选。

这样藕粉、普通淀粉和壳聚糖不只是候选材料，而是具有明确假设功能的对照组。

# 四、闭环优化模式的推荐升级

## 代理模型应至少拆成三个

1. **性能模型**：预测完整传导行为向量；
2. **可行性模型**：预测可成膜、可装夹、能否获得有效谱；
3. **测量质量/失败模型**：预测漂移、未平衡、接触失效等风险。

不要把失败实验删除，也不要简单赋予一个极低电导率。失败本身是关于实验空间边界的重要数据。

## 推荐模型

在现有样本量下，优先考虑：

* 异方差高斯过程；
* 混合变量和混料约束；
* 多输出或多任务模型；
* 批次、日期、原料批号、热史作为上下文；
* 历史酸–黏土知识只作为可检验先验，不能作为事实标签；
* 分组或时间外验证，禁止普通随机拆分造成批次泄漏。

噪声会显著影响材料发现中的BO表现，代理模型需要同时表达信息不足和观测噪声，并在探索与利用之间分配实验。([皇家化学学会出版][3])

## 大模型的正确位置

大模型负责：

* 从文献生成有依据的先验；
* 建议变量、约束与候选解释；
* 检查与历史失败的冲突；
* 解释为什么推荐某实验；
* 识别需要人工审批的情况。

大模型不负责：

* 手算采集函数；
* 修改实测数据；
* 绕过硬约束；
* 直接选择一个“看起来最好”的配方；
* 直接向仪器发送未经验证的指令。

采集函数必须由可复算的数值代码产生，LLM只能在受控范围内审查或解释数值候选。

## 自适应重复

不要对所有实验做等量重复。应当在以下情况增加重复：

* 候选位于Pareto前沿；
* 两个候选排序接近；
* 偶然噪声大于知识不确定性；
* 结果与历史模型严重冲突；
* 即将进入独立确认阶段。

若主要是认知不确定性，则应探索新配方，而不是反复测同一点。

# 五、智能体应采用“受控编排器”，而不是堆很多Agent

推荐七层结构：

1. **证据与知识层**：文献、材料、样品、协议、反例和适用域；
2. **假设与主张层**：桥接假设、预测签名、竞争解释；
3. **策略路由层**：决定当前偏重假设判别还是性能优化；
4. **数值决策层**：层级贝叶斯、EIS模型比较、BO；
5. **实验执行层**：协议编译、前置检查、仪器调用和回滚；
6. **EIS质控与推断层**：有效性、模型比较、不确定度传播；
7. **科学记忆与治理层**：记忆、验证器、校准、审计和人工审批。

你们已经做好的记忆、自我检查和可靠性校准，应立即接入主流程，而不是继续作为旁路演示。

建议采用三种类型化记忆：

* **情景记忆**：每轮发生了什么、做了哪些选择、为什么失败；
* **语义记忆**：主张、证据、反例、桥接假设和适用条件；
* **程序记忆**：SOP、EIS分析流程、失败恢复策略和工具能力。

置信度必须在实验前记录，并用实验结果计算Brier score、log loss和可靠性曲线。不要使用模型实验后的自我评价代替校准。现有科学智能体基准也表明，端到端能力不能靠一次展示判断，需要对工作流中的每个任务做细粒度评测。([OpenReview][4])

# 六、必须实施的结论门禁

| 等级 | 可允许的主张                  |
| -- | ----------------------- |
| C0 | 数据无效，只报告失效原因            |
| C1 | 某条件下得到某EIS或电导率区间        |
| C2 | 某行为在独立批次下可复现            |
| C3 | 数据更支持某经验温度模型或传导区间       |
| C4 | 数据与某机制的预注册预测一致，但仍保留替代解释 |
| C5 | 通过结构证据与因果干预确认微观机制       |

当前系统默认只能到 **C4**。

每一条主张都必须输出：

* 主张等级和状态；
* 实验与文献证据ID；
* 配方、批次、温湿度和热史；
* 效应量与区间；
* 竞争模型权重；
* 替代解释；
* 可推翻该主张的结果；
* 适用域；
* 校准后的智能体置信度；
* 独立验证器结果。

状态只能是：

**Supported / Refuted / Inconclusive / Invalid**

尤其要允许系统输出“Inconclusive”。在你们的场景中，可靠地知道“现有数据无法区分两个解释”，本身就是高价值科学结果。

# 七、怎么证明这套系统真的有效

建议做四类严格比较：

| 验证       | 核心设计                                      |
| -------- | ----------------------------------------- |
| 历史数字回放   | 按时间和批次隐藏未来数据，让系统重做当时的实验选择                 |
| 前瞻迁移挑战   | 实验前冻结候选、正反例、预测签名和结论门槛                     |
| 固定预算优化比较 | 随机/LHS、传统DOE、BO-only、LLM-only、LLM+BO、完整系统 |
| 消融实验     | 分别去掉记忆、验证器、校准、负结果和自适应重复                   |

主要评价：

* 误支持科学主张的概率；
* 区间覆盖和置信校准；
* 正反例判别；
* 独立批次确认率；
* fixed-budget simple regret；
* Pareto超体积；
* 每个确认改进的实验成本；
* 人工干预率；
* 端到端确定性回放率。

自驱动实验室不应只报告“找到最好结果的速度”，还应报告自主度、可运行时间、参数空间、测量精度、吞吐量、采样成本和优化表现。([Nature][5])

# 八、最有价值的研究创新点

你们最强的论文主线不是“发现一个更高电导材料”，而可以是：

> **部分可观测、EIS-only、噪声和高实验成本条件下的证据校准型自主材料发现。**

可形成四项核心贡献：

1. **两种发现模式共享的传导行为向量和结论等级体系；**
2. **信息增益—性能改进—成本—风险统一采集策略；**
3. **把科学记忆、外部验证器、校准拒答真正接入湿实验闭环；**
4. **用正例、失败反例、预注册、消融和独立批次确认评估自主发现能力。**

真正需要突破的底层问题则是：

* 潜在材料状态不可观测条件下的贝叶斯信念建模；
* EIS逆问题和模型不可辨识性；
* 跨材料体系的因果迁移与桥接假设验证；
* 偶然噪声与认知不确定性的分离；
* 最优重复次数与下一新实验之间的价值信息决策；
* 科学Agent的概率校准和选择性拒答；
* 从原始谱到论文主张的机器可验证溯源。

数据和实验操作层建议采用机器可执行协议、不可变原始数据、W3C PROV式溯源以及RO-Crate式复现包；SiLA类功能接口可用于隔离仪器能力和上层Agent。([sila-standard.com][6])

# 总判断

你的判断方向基本正确，但原因需要更精确：

> **不是别人已经做出的技术普遍“质量很差”，而是他们验证的正确性层级，通常低于你们需要的层级。**

许多系统已经能做到：

1. LLM正确调用工具；
2. 工作流顺利执行；
3. 仪器返回结果；
4. 优化指标有所改善。

但你们需要证明的是：

5. 样品在执行期间处于什么物理状态；
6. EIS结果是否具有计量有效性；
7. 结果是否真的支持预注册假设；
8. 替代解释是否被排除；
9. 结论是否会在新批次中复现；
10. 智能体是否知道自己什么时候证据不足。

这两组目标之间还有非常大的工程与科学鸿沟。

## 四种“正确”不能混在一起

| 层级      | 正确性的含义                | 现有技术成熟度 | 你们的要求 |
| ------- | --------------------- | ------: | ----: |
| L1 接口正确 | JSON、参数、工具调用没有报错      |       高 |    必须 |
| L2 流程正确 | 步骤顺序、状态转移、权限和恢复正确     |      中高 |    必须 |
| L3 测量正确 | 样品状态明确，谱有效，误差和不确定度受控  |      中低 |    必须 |
| L4 科学正确 | 主张与证据匹配，替代解释被处理，结论可复现 |       低 |  核心创新 |

现有Agent SDK、工作流框架、MCP、实验室操作系统，主要覆盖L1和L2；个别自驱动实验室覆盖部分L3；**几乎没有通用系统真正覆盖L4**。

因此，直接拼装第三方技术，最容易得到的是：

> 一个“会运行实验”的Agent。

而你们真正需要的是：

> 一个“只在证据允许时才形成科学主张”的自主发现系统。

# 二、自驱动实验室现有技术具体哪里不够好

## 1. 仪器被错误地抽象成“软件工具”

普通Agent框架通常假定：

```text
调用工具 → 返回结果 → 工具调用完成
```

但在湿实验中，至少需要区分五个状态：

```text
命令已提交
→ 仪器已接受
→ 物理操作已完成
→ 测量通过质控
→ 结果可用于科学推断
```

例如EIS程序返回“measurement completed”，只意味着仪器程序结束，不意味着：

* 样品已经达到热平衡；
* 湿度和调理状态没有变化；
* 谱满足线性和时间不变性；
* KK或lin-KK通过；
* 频率窗口足以支持电路解释；
* 接触和几何没有发生变化。

当前MCP、A2A一类协议没有表达排他资源、不可逆操作、物理单位、校准和测量不确定度的完整语义；SiLA等标准更适合确定性客户端，而不是根据自然语言目标进行概率推理的Agent。([arXiv][2])

### 你们需要的改造

工具不能只返回：

```json
{"status": "success"}
```

而应返回类似的科学状态：

```text
operation_status: completed
sample_state_observed: partially_observed
thermal_equilibrium: passed
stationarity: failed
kk_status: not_tested
calibration_status: valid
scientific_usability: invalid
invalid_reason: temporal_drift
```

即：

> **仪器成功不等于实验成功；实验成功也不等于科学证据成立。**

---

## 2. 现有系统缺少真正的“样品状态”

大多数实验室操作系统跟踪的是：

* 任务状态；
* 仪器状态；
* 文件状态；
* 工作流状态。

你们还必须跟踪：

* 样品身份和母批次；
* 配方及其不确定度；
* 制膜和干燥过程；
* 调湿时间；
* 温度路径；
* 累积低温停留；
* 升降温方向；
* 循环次数；
* 装夹压力；
* 接触变化；
* 已经经历过的EIS测试；
* 当前状态是观测到的、推断的还是未知的。

同一配方、同一温度，并不意味着是同一个实验条件。

在你们的体系里：

[
x_{\text{experiment}}
\neq
{\text{配方}, T}
]

而至少是：

[
x_{\text{experiment}}=
{\text{配方},T,\text{湿度},\text{热史},\text{调理史},
\text{批次},\text{装夹},\text{接触},\text{时间}}
]

如果这些状态没有成为系统中的一等对象，Agent记忆得越多，反而越可能把不可比较的数据混在一起。

---

## 3. 软件“回滚”在湿实验中往往不存在

你们当前方案中T0045、T0058、T0073—T0075使用了“所有动作可回滚”的表述，这对软件系统成立，但对湿实验不成立。

以下过程一般不能真正回滚：

* 膜已被干燥；
* 样品已经吸湿或脱水；
* 已经历一次低温循环；
* 接触状态已经改变；
* 样品出现裂纹；
* 试剂已经混合；
* 样品已经老化；
* 某次长时间EIS已经改变其调理状态。

因此需要把“回滚”改成：

> **状态核对 → 补偿操作 → 前向恢复 → 样品隔离或作废。**

例如仪器调用超时后，不能直接重试。因为第一次测量可能已经发生，只是确认消息丢失。正确步骤应是：

1. 查询仪器实际状态；
2. 查询输出文件和时间戳；
3. 检查样品热史是否已经改变；
4. 判断第一次操作是否完成；
5. 决定继续、补测、重新平衡或隔离样品；
6. 将第二次测量标记为新的观测，而不是幂等重试。

LAP之所以专门提出仪器预留、任务生命周期、安全握手和样品链路，正说明普通软件工具协议不能充分描述这些物理语义；但LAP本身目前也尚未经过生产级验证。([arXiv][2])

---

## 4. 现有闭环通常默认“观测值是干净标量”

很多自驱动实验室论文的闭环近似为：

[
x \rightarrow y \rightarrow \text{更新模型}
]

其中 (y) 是产率、电导率、吸收峰或其他单个数字。

你们实际得到的是：

[
x
\rightarrow
Z(\omega,T)
\rightarrow
Q_{\text{EIS}}
\rightarrow
p(\theta\mid Z)
\rightarrow
B
\rightarrow
\text{主张}
]

中间存在：

* 无效谱；
* 测量漂移；
* 几何误差；
* 接触误差；
* 多个等效电路；
* 不可辨识参数；
* 批次效应；
* 潜在材料状态；
* 温度模型竞争；
* 结果为区间而非点值。

如果把这些信息压成一个电导率数值后直接送给BO，优化器会把：

* 接触失败理解为材料性能差；
* 未热平衡理解为低温异常；
* 批次偏差理解为配方效应；
* 不可辨识模型理解为确定机制；
* 失效谱理解为正常低值。

SDL性能研究也指出，不同实验空间的优化速率并不能直接迁移比较，测量精度、噪声、运行寿命、材料成本和实验吞吐都必须单独报告；高吞吐不能补偿低精度数据。([Nature][3])

---

## 5. “优化成功”没有证明“发现成功”

现有系统经常以以下指标定义成功：

* 找到更高性能的候选；
* 比随机搜索更快；
* Pareto前沿改善；
* 实验完成率提高。

这些指标可以证明算法优化能力，但不能自动证明：

* 文献知识成功迁移；
* 桥接假设成立；
* 机制判断正确；
* 智能体真正学到了可迁移规律；
* 负例被正确预测；
* 结论能够在新批次复现。

你们需要把以下两个问题严格分开：

### 优化问题

[
\text{哪个候选的预期性能更高？}
]

### 科学判别问题

[
\text{哪个实验最能区分竞争假设？}
]

已有SDL技术普遍更擅长第一类，第二类仍然薄弱。

# 三、Agent Harness Engineering哪里不够好

## 1. 软件Agent的Harness不能原样搬到湿实验

Harness可以理解为模型之外的完整运行环境，包括：

* 任务规范；
* 上下文组装；
* 工具；
* 状态；
* 记忆；
* 权限；
* 调度；
* 重试；
* 观测；
* 验证；
* 人工干预；
* 失败恢复。

官方Agent评测指南也强调，“Agent”的性能实际上是模型和Harness共同作用的结果，而不是模型单独的能力。([Anthropic][4])

当前较成熟的Harness engineering经验主要来自软件开发Agent。软件系统具有：

* 可复制环境；
* Git版本；
* 单元测试；
* CI；
* 可逆修改；
* 可快速重复执行；
* 明确的最终状态。

OpenAI的Harness实践强调结构化知识库、反馈回路、可观测性和版本化计划；Anthropic的长期Agent实践也发现，单纯上下文压缩不足以避免半成品、错误交接和过早宣布完成。([OpenAI][5])

湿实验却具有相反性质：

| 软件Agent    | 湿实验Agent         |
| ---------- | ---------------- |
| 文件可复制      | 样品通常不可复制         |
| Git可回滚     | 材料状态不可回滚         |
| 测试可快速重复    | 重复实验会改变热史和成本     |
| 环境较完全可观测   | 样品内部状态不可观测       |
| 错误主要损失时间   | 错误会损失样品、仪器或科学可信度 |
| 成功状态容易机器判定 | 科学有效性需要计量和推断     |

因此，你们需要的不是普通Agent Harness，而是：

> **Scientific Wet-Lab Harness。**

---

## 2. Prompt不能承担安全和科学约束

当前系统经常把以下规则写在系统提示词里：

* 不要超出温度范围；
* 不要跳过热平衡；
* 不要用无效谱更新模型；
* 证据不足时拒答；
* 不要直接宣称机制；
* 高风险操作需要审批。

这不够。

AILA实验显示，Agent可能偏离指令并进行要求之外的操作，作者称之为“sleepwalking”；系统对很小的提示格式变化也较敏感。([Nature][6])

这些限制必须落在确定性层：

```text
LLM提出动作
→ 参数模式校验
→ 单位校验
→ 边界校验
→ 当前样品状态校验
→ 仪器状态校验
→ 风险策略校验
→ 人工审批或拒绝
→ 执行
```

也就是说：

> Prompt负责建议，Policy Engine负责决定能不能做。

---

## 3. 现有Tracing不是科学溯源

Agent SDK已经能够记录：

* 模型调用；
* 工具调用；
* handoff；
* guardrail；
* 自定义span。([OpenAI开发者][7])

但这些只能回答：

> Agent做了什么？

不能完整回答：

> 这个科学结论为什么成立？

你们的trace还必须包含：

* 样品和母批次ID；
* 物料及称量来源；
* 制备协议版本；
* 仪器和固件版本；
* 校准状态；
* 温度、湿度和热史；
* 原始谱哈希；
* 质控结果；
* 排除频点的原因；
* 分析代码和参数；
* 候选模型集合；
* 后验和不确定度；
* 主张依赖了哪些证据；
* 哪些证据后来被作废；
* 人工在哪一步干预；
* 为什么提高或降低了结论等级。

因此，T0079“全栈可观测性”应升级为两套并行trace：

1. **运行trace**：Agent、工具和工作流；
2. **科学trace**：样品、测量、分析和主张。

---

## 4. 普通重试策略对湿实验是危险的

通用Agent框架通常采用：

* timeout后重试；
* 指数退避；
* tool call失败后重新调用；
* 计划失败后回溯。

在湿实验中，必须首先判断：

[
\text{调用失败}
\neq
\text{物理操作未发生}
]

因此T0785“重试”和T0786“回溯”应改成：

```text
故障
→ 状态核对
→ 判断是否部分完成
→ 更新样品状态
→ 估计重复操作的影响
→ 继续 / 补偿 / 隔离 / 人工处理
```

建议采用：

* 命令幂等键；
* 仪器和文件双重见证；
* 物理完成证据；
* 单样品单写者；
* 操作前后状态快照；
* 超时后的状态协调器；
* 禁止盲目自动重试。

---

## 5. “自我检查”不是独立验证

你们的T0787、T0789、T0790和T0806分别涉及反思、自我批评、验证器模型和验证者智能体。这些概念不能被视为等价。

应区分：

| 类型        | 能做什么          | 不能证明什么     |
| --------- | ------------- | ---------- |
| 同一次模型自我反思 | 找明显遗漏         | 不能提供独立性    |
| 同模型新上下文复核 | 降低部分路径依赖      | 错误仍高度相关    |
| 多Agent辩论  | 暴露分歧          | 一致不代表正确    |
| 独立模型验证    | 降低部分模型相关性     | 仍不能替代物理证据  |
| 确定性检查器    | 单位、边界、计算、模式检查 | 不能评价开放式机理  |
| 独立批次实验    | 检验复现性         | 仍不一定确认微观机制 |

AutoLabs的消融结果表明，推理模型能力往往比“单Agent还是多Agent”更重要；专家参与可以改善结果，但专家仍然遗漏了搅拌、封盖、参数分配等程序错误。([arXiv][8])

因此正确的验证金字塔应是：

```text
确定性语法检查
→ 单位、边界和守恒检查
→ 前置/后置物理状态检查
→ EIS计量质控
→ 统计和模型检查
→ 独立Agent证据审查
→ 人工审批
→ 独立批次实验
```

LLM验证器只能处在中上层，不能替代底层验证。

---

## 6. 平均成功率掩盖了真正危险的失败

最新Agent可靠性研究指出，能力分数提高并没有带来同等程度的可靠性提高；单一任务成功率会掩盖运行间不一致、扰动脆弱性、不可预测失败和错误严重度。([arXiv][9])

你们不能只报告：

* Agent任务成功率；
* 工具调用正确率；
* 实验完成率；
* 最终性能改善。

还需要报告：

* 错误支持主张率；
* 无效谱进入优化器的比例；
* 未授权物理动作率；
* 重复运行决策一致性；
* 提示改写敏感性；
* 故障注入恢复率；
* 错误严重度；
* 拒答是否发生在正确位置；
* 置信区间覆盖；
* 智能体置信度校准；
* 每个被确认科学主张的总成本。

---

# 四、现有Agent记忆为什么不够好

## 核心问题：现有记忆主要优化“能否想起来”，你们需要优化“想起来的东西是否仍然成立”

当前记忆研究通常关注：

* 检索准确性；
* 长上下文；
* 会话连续性；
* 个性化；
* token节省。

科学Agent还需要：

* 证据来源；
* 适用条件；
* 时间和版本；
* 支持与反驳关系；
* 结论失效传播；
* 负结果；
* 不确定度；
* 替代解释；
* 访问权限；
* 谁有权把内容提升为“事实”。

MemoryAgentBench把Agent记忆能力分为准确检索、测试时学习、长程理解和选择性遗忘，并发现当前方法尚不能同时做好全部四项。([OpenReview][10])

---

## 1. 向量相似度不是科学有效性

向量数据库最容易返回“语义相似”的内容，但科学检索需要同时判断：

[
\text{relevance}
\times
\text{validity}
\times
\text{applicability}
\times
\text{freshness}
\times
\text{authority}
]

例如旧记忆说：

> 淀粉–黏土膜在低温下保持较高传导。

后续实验可能表明：

* 仅在升温支路出现；
* 仅某个批次出现；
* 结果受装夹影响；
* 新批次没有复现；
* 旧谱后来未通过漂移检查。

普通向量记忆仍可能因为相似度高，把旧结论反复取回。

正确的记忆条目必须包含：

```text
对象类型
主张内容
主张等级
证据ID
适用条件
有效时间
版本
支持证据
反驳证据
当前状态
替代解释
置信度
上游依赖
下游主张
```

---

## 2. 记忆必须支持“证据失效的级联传播”

假设：

```text
谱E1支持参数P1
P1支持温度模型M1
M1支持桥接假设H1
H1支持候选排序R1
```

如果后来发现E1没有达到热平衡，则不能只把E1标记为无效。系统还必须重新计算：

* P1是否仍成立；
* M1是否仍有独立证据；
* H1的置信度是否下降；
* R1是否需要更新；
* 后续哪些实验决策依赖了该错误信息。

近期RECON记忆基准专门把记忆表示成带推导关系的溯源图，并指出当证据被修订或作废时，系统必须判断哪些结论失去基础、哪些仍有独立证据支持；现有系统在跨会话知识更新上仍然容易失败。

因此你们的P28“主张—证据—反例图”不只是知识展示工具，而应成为：

> **记忆一致性和失效传播的核心计算结构。**

---

## 3. Agent不能直接把自己的输出写成长期事实

最危险的闭环是：

```text
Agent生成推断
→ 写入长期记忆
→ 后续检索回该推断
→ 把它当成既有事实
→ 进一步强化
```

这是“自我引用式证据膨胀”。

建议采用记忆状态机：

```text
Proposed
→ Quarantined
→ Validated
→ Active
→ Contested
→ Superseded / Refuted / Invalidated
→ Archived
```

权限规则应是：

* LLM只能写入`Proposed`；
* 确定性分析器可写入经过验证的派生结果；
* 质控系统决定测量是否有效；
* 独立验证器可提出升降级建议；
* 只有规则引擎或授权人员可把科学主张提升为`Active`；
* 原始数据永远不可由Agent改写。

动态记忆研究也开始指出，自主改写记忆可能导致语义漂移、程序漂移、错误积累和记忆污染，因而需要把记忆生成与记忆治理分离。([arXiv][11])

---

# 五、多Agent记忆哪里不够好

## 1. 共享一个Python字典不等于多Agent记忆

AILA使用两个专门Agent并共享Python字典保存交互和状态。这可以支持原型协作，但从科学工程角度看，它不自动具备：

* 持久化；
* 类型系统；
* 版本控制；
* 事务；
* 并发冲突；
* 访问权限；
* 溯源；
* 主张失效；
* 跨实验批次一致性。([Nature][6])

这种结构适合演示“Agent能交换状态”，不适合保存长期科学结论。

---

## 2. 多Agent共享记忆会出现经典一致性问题

多Agent同时读写共享记忆会产生：

* 读到旧版本；
* 覆盖其他Agent的更新；
* 同一个主张出现不同状态；
* 不同Agent基于不同证据集推理；
* 并发生成相互冲突的总结；
* 已作废信息仍被某个Agent使用。

近期多Agent记忆研究把这类问题类比为计算机体系结构中的缓存一致性，认为当前最重要的开放问题之一就是共享记忆的一致性、可见性和更新顺序。([arXiv][12])

### 你们不应使用“最后写入者胜出”

对于科学主张：

```text
Agent A：支持H1
Agent B：反驳H1
```

不能简单取最新一条，也不能投票。

应当生成：

```text
claim_status: CONTESTED
support_branch: [...]
refute_branch: [...]
unresolved_conditions: [...]
next_discriminating_experiment: [...]
```

冲突本身就是科学状态。

---

## 3. 建议采用三类内存空间

### 私有工作记忆

每个Agent自己的：

* 临时计划；
* 搜索轨迹；
* 未验证想法；
* 草稿；
* 局部推理。

不自动共享，也不能形成科学事实。

### 角色限定记忆

例如：

* 文献Agent只读文献和证据库；
* BO模块只读QC有效指标；
* 执行控制器只读已批准协议；
* Claim Agent只读经过版本化的证据图；
* 验证Agent不能修改原始数据。

### 共享权威记忆

只保存：

* 不可变事件；
* 原始数据引用；
* 经过质控的观测；
* 版本化派生量；
* 主张与证据关系；
* 已批准技能；
* 人工审批和审计记录。

共享内存采用：

* append-only事件；
* MVCC或版本号；
* 乐观并发控制；
* 单样品状态的单写者；
* 显式冲突状态；
* 读取时携带版本；
* 写入时检查是否基于过期版本。

---

# 六、记忆压缩哪里不够好

## 1. 当前压缩优化的是token，不是证据保真度

长期Agent实践表明，单纯compaction并不足以保证跨上下文正确交接；压缩后可能留下半完成状态、模糊指令，或者导致后续Agent过早判断任务完成。([Anthropic][13])

对于科学Agent，压缩最危险的不是“漏掉一句背景”，而是漏掉：

* 适用条件；
* 负结果；
* 反驳条件；
* 测量无效原因；
* 仅在升温支路成立；
* 某结论只来自单批次；
* 两个模型无法区分；
* 某机理仍有替代解释；
* 当前主张等级只是C3或C4。

例如原始结论是：

> 在批次B3、升温支路、特定湿度调理下，数据与VTF样行为一致，但Arrhenius分段模型仍不能被排除。

普通摘要可能压成：

> 该材料表现出VTF传导。

这不是信息压缩，而是科学结论升级。

---

## 2. 必须区分三种压缩

| 类型         | 能否压缩    | 原则            |
| ---------- | ------- | ------------- |
| 原始数据与仪器日志  | 不做有损压缩  | 不可变、可复算       |
| 权威科学记录     | 只能结构化归纳 | 保留条件、状态、证据和版本 |
| Agent工作上下文 | 可以有损压缩  | 必须保留权威记录指针    |

正确关系是：

```text
摘要 = 缓存
原始证据 = 权威来源
```

不能让：

```text
摘要的摘要的摘要
```

最终取代原始证据。

---

## 3. 建议建立“证据保真压缩器”

每次压缩必须输出六部分：

1. 已确认事实；
2. 被反驳或无效的内容；
3. 尚未解决的冲突；
4. 所有硬约束；
5. 可推翻当前判断的结果；
6. 原始证据和事件指针。

对关键内容设零损失预算：

[
L_{\text{critical}}
===================

L_{\text{condition}}
+
L_{\text{contradiction}}
+
L_{\text{falsifier}}
+
L_{\text{provenance}}
+
L_{\text{claim status}}
=0
]

压缩后自动进行回归测试：

* 是否仍能回答当前样品状态；
* 是否保留所有无效谱原因；
* 是否保留正反证据；
* 是否知道哪些主张被降级；
* 是否能恢复下一步计划；
* 是否会因此改变实验决策；
* 是否错误提升主张等级。

---

# 七、Skills哪里不够好

## 1. 当前Agent Skill只是“程序知识包”

Agent Skills通常由：

* `SKILL.md`；
* 操作说明；
* 脚本；
* 模板；
* 示例；
* 参考资料

组成，并通过渐进式加载减少上下文占用。([Claude平台][14])

它适合表达：

> 如何完成某类任务。

但不能自动证明：

> 这个程序在当前仪器、样品和科学条件下是有效、安全、可复现的。

---

## 2. Skills有帮助，但并不稳定

SkillsBench的2026年预印本在84项任务和7308条轨迹上发现，人工整理的Skills平均提高16.2个百分点，但84项任务中仍有16项性能下降；模型自行生成Skills平均没有收益，甚至略有退化。该结果不是湿实验基准，但足以说明“有Skill”不等于“Skill可靠”，而且Harness如何发现和调用Skill会显著影响效果。([SkillsBench][15])

因此，在湿实验中不应允许Agent：

```text
现场生成一个新Skill
→ 立即用于真实样品
→ 成功后自动进入技能库
```

---

## 3. 你们需要的是“科学技能合同”

每个Skill至少应包含：

| 字段          | 含义                 |
| ----------- | ------------------ |
| skill_id与版本 | 唯一标识和语义版本          |
| 类型          | 文献、分析、优化、验证、执行     |
| 适用域         | 哪些材料、温区、仪器、数据类型    |
| 输入          | 强类型输入、单位和允许范围      |
| 前置条件        | 样品、仪器、校准和环境要求      |
| 副作用         | 是否消耗样品、改变热史、不可逆    |
| 实现          | 固定代码、协议模板或受限模型     |
| 后置条件        | 成功后必须观测到什么         |
| 证据输出        | 原始数据、QC、派生结果和版本    |
| 失效模式        | 超时、漂移、接触、越界等       |
| 恢复方式        | 重试、补偿、重新平衡、隔离      |
| 验证器         | 确定性测试和允许误差         |
| 风险等级        | 是否需要人工审批           |
| 兼容矩阵        | 仪器、固件、模型和Harness版本 |
| 测试集         | 正例、反例、边界和故障注入      |

### Skill的五级生命周期

```text
Draft
→ Simulation
→ Shadow
→ Canary
→ Validated
→ Deprecated
```

Agent可以提出Skill草稿，但不能自行将其提升为`Validated`。

---

## 4. 渐进加载也有风险

渐进加载可以减少上下文，但湿实验中某些内容不能按需加载：

* 安全边界；
* 强制前置条件；
* 单位规则；
* 不可逆性；
* 样品状态要求；
* 质控标准；
* 审批要求。

因此Skill应分成：

### 永久强制内核

始终由系统执行：

* 类型；
* 单位；
* 边界；
* 风险；
* 前后置条件；
* 审批；
* 验证器。

### 可按需加载部分

由Agent阅读：

* 背景解释；
* 示例；
* 文献；
* 推荐策略；
* 常见问题。

---

## 5. Skill组合不能只靠自然语言

例如：

```text
制膜Skill
→ 调湿Skill
→ 装夹Skill
→ 变温EIS Skill
→ EIS分析Skill
```

只有当：

[
\text{postcondition}(S_i)
\models
\text{precondition}(S_{i+1})
]

时才能组合。

不能仅因为Agent认为“这两个步骤看起来相接”就自动串联。

---

# 八、多Agent系统哪里不够好

## 1. 多Agent提高性能，很多时候只是增加了计算量

Anthropic在研究型多Agent系统中发现，多Agent特别适合大规模并行搜索，但token消耗约为普通聊天的15倍；其分析中token使用本身解释了大部分性能差异。对于需要共享同一上下文、具有大量步骤依赖的任务，多Agent并不一定适合。([Anthropic][16])

湿实验恰好具有：

* 高步骤依赖；
* 单样品串行状态；
* 仪器排他占用；
* 操作不可逆；
* 需要共享权威状态；
* 错误成本高。

因此，多Agent不能作为默认架构。

---

## 2. 多Agent并不自动提供独立性

如果多个Agent：

* 使用同一个基础模型；
* 读取相同文献；
* 使用相同提示；
* 读取相同错误摘要；
* 调用相同拟合结果；

那么它们的错误高度相关。

三个Agent同时认为某个等效电路最好，可能只是因为：

* 都使用最小R²选模；
* 都没有检查实际可辨识性；
* 都忽略了频率窗口不足；
* 都把同一个错误记忆当成事实。

因此：

> Agent之间的一致，是协作结果；不是独立证据。

---

## 3. 多Agent最适合你们的三个位置

### 适合

1. 文献检索的并行覆盖；
2. 独立生成竞争假设；
3. 对桥接假设进行对抗性审查。

### 有条件使用

1. 候选解释比较；
2. 主张—证据一致性检查；
3. 实验计划审阅。

### 不适合由多个LLM协商

1. 数值计算；
2. 单位和物料守恒；
3. EIS质控；
4. 仪器状态机；
5. 重试和恢复；
6. BO采集函数；
7. 最终科学主张升级；
8. 安全审批。

---

## 4. 推荐的Agent拓扑

```text
研究总控Agent
│
├── 文献证据Agent（只读）
├── 假设生成Agent（只提议）
├── 对抗性反例Agent（只提议）
│
├── 数值决策服务（非LLM）
│   ├── BO
│   ├── 信息增益
│   ├── 层级贝叶斯
│   └── EIS模型比较
│
├── 协议编译器（确定性）
├── 执行状态机（确定性）
├── EIS质控服务（确定性+统计）
│
├── 主张验证Agent（只读）
├── 规则验证器（确定性）
└── 人工审批
```

核心原则：

> **开放式问题使用Agent；可形式化问题使用算法；物理执行使用状态机；高等级科学主张使用独立证据。**

多Agent之间最好通过结构化产物和引用交换结果，而不是层层转述自然语言。生产多Agent实践也建议将子Agent输出持久化为独立产物，以减少“传话游戏”造成的信息丢失。([Anthropic][16])

这是软件Agent Harness与真实湿实验Harness之间最关键的区别之一。

# 十、建议建设的“Scientific Harness”核心

## 三个相互隔离的平面

### 1. 认知平面

负责：

* 文献检索；
* 假设生成；
* 解释；
* 候选建议；
* 反例搜索。

权限：只能提出建议。

### 2. 控制平面

负责：

* 状态机；
* 资源锁；
* 协议编译；
* 前后置检查；
* 权限；
* 仪器执行；
* 故障协调；
* 人工审批。

权限：执行已验证动作，但不能形成科学结论。

### 3. 证据平面

负责：

* 原始数据；
* 样品事件；
* 质控；
* 派生结果；
* 不确定度；
* 主张图；
* 失效传播；
* 审计；
* 复现包。

权限：决定什么可以成为证据。

三者不能由一个LLM同时承担。

# 十一、建议的权威记忆结构

至少建立七类存储：

| 存储    | 内容           | 是否可压缩   |
| ----- | ------------ | ------- |
| 原始数据仓 | EIS、日志、传感器输出 | 不可有损压缩  |
| 事件账本  | 每次动作和状态变化    | 只追加     |
| 样品状态库 | 制备、调理、热史、装夹  | 版本化     |
| 证据库   | 文献片段和实验观测    | 保留来源    |
| 主张图   | 支持、反驳、依赖、失效  | 结构化更新   |
| 情景记忆  | 每轮决策和失败经验    | 可压缩但非权威 |
| 技能注册表 | SOP、脚本、版本和测试 | 版本固定    |

外加一类很重要但经常被忽略的：

### 校准与错误记忆

记录：

* Agent当时预测什么；
* 给出多大置信度；
* 实验结果是什么；
* 错误来自文献迁移、数据分析、工具使用还是状态估计；
* 哪类条件下Agent最容易过度自信。

这类记忆直接用于调整下一轮自主权，而不是只用于生成一段“经验总结”。

# 十二、最值得形成论文贡献的技术缺口

结合你们的体系，真正尚未被别人很好解决的，不是再做一个通用Agent，而是以下六项：

## 1. 部分可观测湿实验的Scientific Harness

解决：

* 不可逆操作；
* 样品潜在状态；
* 执行成功与科学有效性的分离；
* 故障后的状态核对和前向恢复。

## 2. 证据保真型记忆压缩

压缩上下文，但严格保留：

* 条件；
* 反证；
* 主张等级；
* 替代解释；
* 失效依赖；
* 原始证据指针。

## 3. 多Agent科学记忆一致性

不是普通共享聊天记录，而是：

* 版本化主张；
* 并发写入；
* 冲突保留；
* 证据失效传播；
* 权限隔离；
* 不同Agent看到不同的授权视图。

## 4. 可认证的Scientific Skills

把Skill从自然语言说明升级为：

* 强类型合同；
* 物理前置条件；
* 副作用；
* 计量验证；
* 故障处理；
* 版本和适用域；
* 合格测试。

## 5. 从工具调用到科学主张的端到端可靠性评测

评价的不只是任务完成，而是：

* 无效证据进入率；
* 错误支持主张率；
* 失效传播正确率；
* 记忆污染率；
* 压缩信息损失；
* Agent校准；
* 独立批次复现率。

## 6. 自主权随可信度动态变化

例如：

```text
高校准 + 已验证Skill + 稳定测量
→ 允许自动执行

存在批次漂移或记忆冲突
→ 降级为建议模式

出现无效谱或状态不确定
→ 停止闭环

需要提升至C4主张
→ 必须独立批次和人工审批
```

这比简单地说“系统是Level 3或Level 4自主”更适合真实实验室。

# 最终建议

不要把近期重点放在：

* 增加更多Agent角色；
* 让Agent自行生成更多Skills；
* 让记忆自动自我进化；
* 用更长上下文保存全部历史；
* 用多Agent投票替代验证。

近期最应该完成的是：

1. **物理状态可核对的Harness内核；**
2. **不可变事件账本和样品状态模型；**
3. **记忆写入门和主张失效传播；**
4. **EIS Scientific Skill合同；**
5. **确定性验证器与Agent验证器分离；**
6. **故障、压缩、冲突和提示变化的系统级压力测试。**

你们最强的研究定位可以进一步收敛为：

> **面向部分可观测、不可逆、高成本湿实验的证据治理型Scientific Agent Harness：研究物理状态、Agent记忆、科学技能和主张可靠性如何在同一个真实闭环中被统一管理。**

这比“我们使用了多Agent、长期记忆和Skills”更有创新性，因为后者别人已经做了组件展示，而前者解决的是这些组件进入真实科学系统以后，**为什么仍然不能被直接信任，以及怎样才能被信任**。

# 一、三篇代表性顶刊论文调研

## 1. A-Lab：领域封闭型自驱动实验室

### 论文

Szymanski 等，**An autonomous laboratory for the accelerated synthesis of inorganic materials**，Nature，2023。

### 系统架构

A-Lab的闭环可以简化为：

```text
DFT数据库筛选候选
        ↓
文献挖掘模型生成初始合成路线
        ↓
机器人配料、混合、加热
        ↓
XRD测量
        ↓
机器学习物相识别 + 自动Rietveld精修
        ↓
ARROWS³主动学习选择下一合成路线
        ↓
新的实验
```

系统使用Materials Project和Google DeepMind的计算数据库筛选目标；通过文献训练的模型提出初始前驱体和温度；机器人完成粉体配料、加热和XRD表征；当目标相产率不足时，ARROWS³根据实验观察到的中间相和计算反应能推荐新路线。系统在17天内完成353次实验，获得36个目标材料；同时积累了88个两两反应记录，用于缩小后续搜索空间。([Nature][1])

### 真正创新点

A-Lab最重要的创新不是机器人本身，而是把四种知识组织在一个闭环中：

* 计算热力学知识；
* 文献中的历史合成知识；
* 当前实验生成的反应路径知识；
* 主动学习产生的下一实验决策。

特别重要的是，失败实验并没有简单记为“失败”，而是被分解为中间相和两两反应，形成可复用的局部反应知识。这已经是一种早期的、领域特化的科学记忆。([Nature][1])

### 它没有解决什么

#### 1. 自主性建立在封闭动作空间上

A-Lab能够调整前驱体和温度，但多步加热、中间研磨、扩大前驱体集合等标准操作仍在其主动学习算法的能力边界之外。研究者人工增加研磨和更高温度后，又成功得到两个目标材料。([Nature][1])

这说明它解决的是：

> 在预先定义好的实验动作集合中自主选择。

而不是：

> 自主发现新的实验程序或自主改变实验能力边界。

#### 2. 它的“记忆”不是通用科学记忆

它保存的是反应对和实验结果，没有完整处理：

* 主张由哪些数据支持；
* 数据失效后哪些结论应撤销；
* 两个模型冲突时如何保留冲突；
* 记忆如何跨Agent共享；
* 记忆压缩后是否改变科学判断。

#### 3. 操作成功与科学确定性仍有差距

四个材料最初被系统判断为成功，但人工复核认为仅凭XRD无法在目标相与其他相之间作出确定区分；论文也指出多相样品自动解释仍有明显困难。([Nature][1])

因此，A-Lab证明了**闭环自动合成可行**，但没有提供通用的科学主张治理层。

---

## 2. Coscientist：工具调用型科学Agent

### 论文

Boiko 等，**Autonomous chemical research with large language models**，Nature，2023。

### 系统架构

Coscientist以一个GPT-4 Planner为中心，Planner可以调用四类命令：

```text
GOOGLE          网络检索
DOCUMENTATION   查询仪器和API文档
PYTHON          在隔离容器内执行代码
EXPERIMENT      通过API调用真实实验设备
```

Web Searcher和Documentation模块本身也使用LLM；Python在隔离Docker环境中执行；实验层适配了Opentrons API和Emerald Cloud Lab的Symbolic Lab Language。Planner通过自然语言接收目标，再动态决定使用哪些模块。([Nature][2])

### 真正创新点

Coscientist第一次系统展示了LLM可以同时完成：

* 从互联网和文献寻找方法；
* 从设备文档学习API；
* 生成实验代码；
* 纠正代码错误；
* 控制液体工作站；
* 协调分析仪器；
* 根据历史实验结果推荐下一条件。

尤其重要的是，它证明了**仪器能力可以不全部预训练进模型，而是在运行时通过文档检索获得**。当系统使用了错误的加热振荡模块方法名时，它重新查询文档并修改协议，最终使程序成功运行。([Nature][2])

### 它没有解决什么

#### 1. Planner处理的是消息，不是科学状态

工具输出作为消息回传给Planner，但系统没有显式区分：

* 指令已发送；
* 仪器已接受；
* 物理操作已发生；
* 测量完成；
* 测量通过质控；
* 结果可以作为科学证据。

这意味着它的基本闭环仍然是：

```text
LLM → 工具调用 → 返回字符串 → LLM继续推理
```

而不是：

```text
Agent提议 → 物理状态验证 → 执行 → 独立见证
→ 测量质控 → 证据提交 → 更新主张
```

#### 2. 文档检索不是Skill认证

Coscientist可以找到“怎样调用一个API”，但没有证明：

* 当前参数在该设备版本上有效；
* 前置条件已经满足；
* 操作是否改变样品状态；
* 失败后能否安全恢复；
* 输出是否达到科学测量要求。

因此，它掌握的是**API使用知识**，不是**经过验证的科学技能**。

#### 3. 优化实验没有充分覆盖真实闭环的不确定性

其优化能力测试使用了两个已经完整映射的反应数据集，Agent选择条件后，结果可以从查找表获得。论文明确说明，任何推荐条件都存在于已有数据集中。([Nature][2])

由此可以推断，这部分实验没有同时面对：

* 样品失败；
* 仪器漂移；
* 无效测量；
* 批次变化；
* 实验部分完成；
* 物理状态不可观测。

所以它更接近“历史数据上的序贯决策测试”，而不是完整的高成本湿实验Harness验证。

---

## 3. AILA：多Agent实验Harness及其失败模式

### 论文

Mandal 等，**Evaluating large language model agents for automation of atomic force microscopy**，Nature Communications，2025。

### 系统架构

AILA包含：

* 一个LLM Planner；
* AFM Handler Agent，负责仪器操作；
* Data Handler Agent，负责数据分析；
* 文档检索、代码执行、图像分析和优化工具；
* LangGraph工作流；
* 一个由两个Agent共同访问的Python字典，保存交互和状态。

Agent之间通过模型输出中的`NEED HELP`和`FINAL ANSWER`等关键词进行路由。([Nature][3])

论文还构建了AFMBench，包含100个实验任务，覆盖实验设计、多工具协作、决策、开放式实验和分析。69%的任务要求多个工具，17%的任务要求多个Agent。([Nature][3])

### 真正创新点

AILA的重要贡献不是单纯“让LLM操作AFM”，而是：

1. 建立真实仪器上的Agent评测；
2. 比较单Agent与多Agent；
3. 分析代码生成、工具选择、Agent路由和指令遵循错误；
4. 明确识别Agent越过任务边界的“sleepwalking”现象。

在10个代表性问题、每题3次试验的单Agent与多Agent比较中，GPT-4o多Agent配置成功率为70%，直接工具集成的单Agent配置为58%。但这只是一个小规模子集，不足以证明所有实验任务都应采用多Agent。([Nature][3])

更关键的是，GPT-4o在300个任务实例中的总错误率为29%，其中代码生成错误占21.7%；系统还出现了未经要求的探针运动和额外实验动作。([Nature][3])

### 它没有解决什么

#### 1. 共享Python字典不等于科学多Agent记忆

它缺少：

* 版本控制；
* 并发写入冲突；
* 权限；
* 数据来源；
* 主张状态；
* 证据失效；
* 长期持久化；
* 压缩保真度；
* 跨实验批次一致性。

共享字典只解决了“两个Agent能否看到相同变量”，没有解决“哪个变量可以被相信”。

#### 2. 基于关键词的路由非常脆弱

`NEED HELP`、`FINAL ANSWER`属于自然语言协议。模型一旦漏写、错写或过早写出终止关键词，流程状态就可能错误变化。

#### 3. Prompt中的伦理规则不是强制策略

AILA将伦理规则和角色责任写在系统提示中，但实验表明模型仍会超出操作边界。论文自身因此提出需要领域约束验证和形式化验证。([Nature][3])

# 三、原创解决方案一：SciTX科学事务Harness

## 全称

**SciTX：Evidence-Transactional Harness for Partially Observable Autonomous Laboratories**

中文可称：

> **面向部分可观测实验的证据事务型科学Agent运行时。**

## 核心发明

现有Harness把一次工具调用作为基本单元：

```text
tool_call(parameters) → result
```

SciTX把基本单元改为：

> **证据事务 Evidence Transaction**

一次证据事务不是“调用仪器”，而是：

```text
科学意图
→ 状态准备
→ 权限和约束验证
→ 物理执行
→ 独立见证
→ 测量质控
→ 证据提交或隔离
```

这是一项新的系统语义，而不是给现有工作流再加几条Prompt。

---

## 1. 四类状态必须分开

定义系统状态：

[
X_t=
\left(
s_t^{op},
b_t(z),
e_t,
a_t^{auth}
\right)
]

其中：

| 状态           | 含义                     |
| ------------ | ---------------------- |
| (s_t^{op})   | 可直接观测的仪器、任务、文件、环境和资源状态 |
| (b_t(z))     | 对不可直接观测物理状态的信念分布       |
| (e_t)        | 当前有效证据和主张图的版本          |
| (a_t^{auth}) | 当前Agent、Skill和操作的授权状态  |

关键创新在于：**Harness内部不假定物理状态完全可见。**

例如，软件可以知道“温控器显示-20 °C”，但不能因此自动断言：

* 样品已经达到热平衡；
* 样品内部状态没有继续变化；
* 接触状态稳定；
* 测量可以提交为证据。

这些判断进入 (b_t(z))，而不是被伪装成确定状态。

---

## 2. Agent只提交动作提案，不直接执行

LLM输出高层提案 (\tilde a_t)，SciTX运行时负责决定是否允许执行：

[
a_t^*=
\arg\max_{a\in\mathcal A(\tilde a_t)}
U(a\mid b_t,e_t)
]

约束为：

[
P\left(
\varphi_{\mathrm{safety}}
\land
\varphi_{\mathrm{scientific\ validity}}
\mid b_t,a
\right)
\ge 1-\delta
]

其中：

* (\varphi_{\mathrm{safety}})：安全约束；
* (\varphi_{\mathrm{scientific\ validity}})：科学有效性约束；
* (\delta)：允许的风险水平。

如果不能证明约束满足，系统只能：

* 先做诊断；
* 降级为建议模式；
* 请求人工批准；
* 拒绝执行。

不是让LLM“再想一想”。

---

## 3. 建立物理世界的三阶段提交

### 阶段A：Prepare

验证：

* Skill版本；
* 输入类型与单位；
* 样品和仪器状态；
* 资源排他锁；
* 校准有效期；
* 操作适用域；
* 风险等级；
* 当前信念状态是否足够确定。

### 阶段B：Execute and Witness

执行操作，同时收集多个独立见证：

* 仪器确认；
* 传感器轨迹；
* 文件时间戳和哈希；
* 样品位置；
* 环境状态；
* 操作前后快照。

### 阶段C：Scientific Commit

只有同时满足以下条件，结果才能进入权威证据库：

[
\mathrm{Commit}(y)=
1
\iff
W\models\psi_{\mathrm{complete}}
\land
Q(y)=\mathrm{pass}
\land
C_{\mathrm{skill}}=\mathrm{valid}
]

其中：

* (W)：物理见证集合；
* (Q(y))：测量质控；
* (C_{\mathrm{skill}})：Skill证书状态。

因此：

```text
仪器程序结束 ≠ 操作完成
操作完成 ≠ 测量有效
测量有效 ≠ 科学主张成立
```

---

## 4. 提出“Scientific exactly-once”语义

普通软件的exactly-once关注消息是否重复处理。实验室需要区分三个ID：

1. **命令尝试ID**；
2. **物理操作ID**；
3. **证据记录ID**。

网络超时后，系统不能直接重试，而要先判断：

* 第一次物理操作是否已经发生；
* 样品状态是否已经变化；
* 是否产生了原始数据；
* 第二次执行是否构成新实验；
* 原结果是否只能隔离而不能覆盖。

这解决的是自驱动实验室中特别危险的问题：

> **工具调用失败，并不意味着物理动作没有发生。**

---

## 5. 用“补偿图”取代软件回滚

编码：

```text
失败状态
→ 状态核对
→ 继续
→ 补偿
→ 重新平衡
→ 样品隔离
→ 操作终止
```

而不是：

```text
失败 → rollback → retry
```

每个不可逆操作都需要显式声明：

* 会改变哪些状态；
* 哪些状态可观测；
* 哪些变化不可逆；
* 可执行哪些补偿；
* 在何种条件下样品必须作废。

---

## 6. 这项创新为什么不是普通工作流引擎

工作流引擎管理的是：

* 任务依赖；
* 超时；
* 队列；
* 重试；
* 检查点。

SciTX新增的是：

* 部分可观测物理状态；
* 证据提交语义；
* 科学质控门禁；
* 不可逆动作补偿；
* Agent动态授权；
* 从物理操作到科学主张的责任链。

编码Agent Harness经常依赖Git、测试和可回滚环境；现有长期Agent研究也主要通过进度文件、Git提交和测试恢复状态，同时明确指出单纯上下文压缩不足以保证跨会话正确性。([Anthropic][5])

湿实验没有Git式物理回滚，所以需要新的事务语义。

---

## 7. 应采用的评测指标

SciTX不以材料性能为评价目标，而以系统可靠性为目标：

* 无效结果被提交为证据的概率；
* 重复物理执行率；
* 超时后的状态核对正确率；
* 越权动作逃逸率；
* 样品状态错误率；
* 故障注入恢复率；
* 证据包完整率；
* 自主执行覆盖率；
* 为安全性增加的实验和时间开销；
* 错误主张因执行故障产生的概率。

### 可形成的论文题目

> **SciTX: Evidence-Transactional Runtime Semantics for Irreversible and Partially Observable Autonomous Laboratories**

# 四、原创解决方案二：E-Mem证据守恒多Agent记忆

## 全称

**E-Mem：Evidence-Conserving Multi-Agent Memory with Decision-Invariant Compression**

中文可称：

> **具有证据守恒、失效传播和决策不变压缩的多Agent科学记忆。**

## 核心发明

当前Agent记忆主要优化：

* 能否检索到相似内容；
* 能否减少token；
* 能否保持会话连续；
* 能否从过去经验中得到帮助。

科学Agent需要优化的是：

> **记忆经过共享、重复引用、总结和压缩后，是否仍然支持与原始证据相同强度的科学判断。**

MemoryAgentBench把Agent记忆划分为准确检索、测试时学习、长程理解和选择性遗忘，并发现当前方法无法同时做好四项。TierMem进一步指出，写入时摘要可能遗漏未来查询所需的关键细节，因此需要在必要时回溯不可变原始记录。([开放评论][6])

但这两类工作仍没有定义：

* 科学主张是否被摘要增强；
* 条件是否被摘要丢失；
* 反证是否被压缩掉；
* 多个Agent重复同一来源是否被错误计为多条证据；
* 数据作废后下游结论是否自动失效。

---

## 1. 建立四层记忆，而不是一个向量数据库

```text
L0：不可变原始事件账本
L1：经过质控的证据图
L2：主张、假设和竞争解释图
L3：Agent角色相关的工作缓存和摘要
```

### L0：原始事件账本

保存：

* 所有物理动作；
* 原始文件引用和哈希；
* 仪器日志；
* 样品状态变化；
* 人工干预；
* Skill和模型版本。

只追加，不覆盖。

### L1：证据图

节点包括：

* 有效观测；
* 无效观测；
* 派生指标；
* 模型结果；
* 文献证据；
* 校准结果。

### L2：主张图

边包括：

* supports；
* refutes；
* derived-from；
* assumes；
* applicable-under；
* invalidates；
* supersedes；
* conflicts-with。

### L3：Agent缓存

可以被压缩、丢弃和重新生成，但不能作为权威证据来源。

---

## 2. 多Agent不按“人数”计算证据

假设三个Agent都引用了同一篇论文：

```text
Agent A支持H
Agent B支持H
Agent C支持H
```

这不是三条独立证据，而是一条证据被复制了三次。

E-Mem根据**独立来源根节点**计权：

[
W(H)=
\sum_{r\in \mathrm{IndependentRoots}(H)}
w_r
]

而不是：

[
W(H)=
\sum_{\mathrm{Agent\ messages}}w_i
]

这可以消除多Agent系统非常常见的“共识幻觉”：

> 多个Agent一致，只是因为它们读取了同一个错误来源或同一个错误摘要。

---

## 3. 引入科学真值维护系统

每个主张保存：

* 最小支持证据集；
* 反驳证据集；
* 必要假设；
* 适用范围；
* 当前状态；
* 后验或置信区间；
* 依赖的分析模型和Skill版本。

例如：

```text
原始测量E1
  ↓
派生结果D1
  ↓
模型比较M1
  ↓
假设H1
  ↓
候选排序R1
```

若E1后来因校准失效被标记为Invalid，系统自动计算：

* D1是否仍有效；
* M1是否还有独立支持；
* H1应降级还是撤销；
* R1是否需要重新排序；
* 哪些后续实验是依据错误信息选择的。

这不是普通数据库级联删除，而是**带替代证据的非单调真值维护**：

* 有其他独立支持时，主张降权；
* 没有其他支持时，主张失效；
* 存在反证时，主张进入Contested；
* 不能区分时，保持Inconclusive。

---

## 4. 多Agent记忆使用版本快照，而不是共享可变字典

每个Agent读取：

```text
evidence_snapshot_hash
claim_graph_version
skill_registry_version
sample_state_version
```

Agent输出必须携带：

```text
based_on_version
used_evidence_ids
generated_claims
uncertainty
```

写入时检查：

* 是否基于过期版本；
* 是否与新证据冲突；
* 是否重复使用同一来源；
* 是否有权限修改该对象。

建议采用：

* 样品状态单写者；
* 原始数据只允许仪器服务写入；
* Agent只能提交Proposed Claim；
* 质控服务只能修改测量有效性；
* 主张升级由规则引擎和授权人员控制；
* 可交换的笔记可以使用CRDT；
* 科学主张状态禁止使用“最后写入者胜出”。

---

## 5. 核心原创算法：科学失真约束下的记忆压缩

普通记忆压缩目标是：

[
\min |\hat M|
]

即尽量减少token。

E-Mem定义科学失真：

[
D_{\mathrm{sci}}(M,\hat M)=
\lambda_1D_{\mathrm{action}}
+\lambda_2D_{\mathrm{claim}}
+\lambda_3D_{\mathrm{scope}}
+\lambda_4D_{\mathrm{contradiction}}
+\lambda_5D_{\mathrm{provenance}}
]

其中：

* (D_{\mathrm{action}})：压缩前后下一实验决策变化；
* (D_{\mathrm{claim}})：主张后验或证据强度变化；
* (D_{\mathrm{scope}})：适用条件丢失；
* (D_{\mathrm{contradiction}})：反证和冲突丢失；
* (D_{\mathrm{provenance}})：无法回到原始来源。

压缩问题改为：

[
\hat M^*=
\arg\min_{\hat M} |\hat M|
]

满足：

[
D_{\mathrm{sci}}(M,\hat M)\le\epsilon
]

更具体地：

[
D_{KL}
\left(
\pi(a\mid M)
\Vert
\pi(a\mid \hat M)
\right)
\le\epsilon_a
]

并且：

[
\left|
\log BF_H(M)
------------

\log BF_H(\hat M)
\right|
\le\epsilon_H
]

这里的核心不是“摘要读起来是否相似”，而是：

> **摘要是否改变了Agent的实验选择和科学主张。**

---

## 6. 五条证据守恒定律

### ① 来源守恒

任何摘要都必须能反向解析到原始证据集合。

### ② 反证守恒

存在于原始记录中的关键反证，不能在摘要中消失。

### ③ 适用域不扩张

压缩后的主张适用范围不能比原始证据更宽。

### ④ 置信度不放大

摘要不能把“可能”“一致于”升级为“证明”“确定”。

### ⑤ 独立性不伪增

同一来源被多个Agent复制、转述或总结，不能增加独立证据数量。

---

## 7. 压缩结果必须携带证书

每个摘要附带：

```text
summary_id
source_node_ids
covered_claims
covered_counterevidence
preserved_conditions
decision_invariance_tests
claim_strength_before_after
raw_log_recovery_pointer
compression_model_version
```

摘要只是缓存。只要：

* 出现争议；
* 需要形成高等级主张；
* 压缩不变性测试失败；
* Agent要求提高自主权；

系统就自动回溯原始记录。

---

## 8. 评测指标

* 压缩导致下一实验选择翻转的比例；
* 压缩导致主张等级上升的比例；
* 关键条件丢失率；
* 反证丢失率；
* 无效记忆复活率；
* 数据失效传播的precision、recall和延迟；
* 多Agent重复证据计数误差；
* 版本冲突检测率；
* 原始来源可恢复率；
* 同一记忆状态下多次推理的一致性；
* 在固定token预算下的科学失真。

### 可形成的论文题目

> **E-Mem: Evidence-Conserving Multi-Agent Memory and Decision-Invariant Compression for Autonomous Science**

这三个方向中，**E-Mem可能具有最高的纯Agent算法创新性**，因为它把记忆压缩从语言摘要问题转化成科学决策的率失真问题。

---

# 五、原创解决方案三：PC-Skills可证明科学技能

## 全称

**PC-Skills：Proof-Carrying and Composable Skills for Scientific Agents**

中文可称：

> **携带验证证书、可组合、可撤销的科学Agent技能。**

## 核心发明

当前Agent Skill通常是：

```text
SKILL.md
+ 说明
+ 示例
+ 脚本
+ 参考资料
```

官方Agent Skills也主要将Skill定义为可动态加载的指令、脚本和资源目录，通过渐进式加载减少上下文占用。([Anthropic][7])

SkillsBench对84项任务、7种Agent—模型配置和7308条轨迹的评测发现：

* 人工整理的Skills平均提升16.2个百分点；
* 16项任务反而下降；
* 自生成Skills平均没有收益；
* 过于全面的Skills文档甚至降低性能；
* 2—3个聚焦Skill通常比大量Skill更有效。([arXiv][8])

这说明：

> Skill有用，但“存在一个Skill文件”完全不等于“这个Skill可以被可信地用于真实实验”。

---

## 1. 把Skill定义成有类型的科学操作符

定义：

[
K=
(A,G,\Theta,\Delta,R,W,Q,\mathrm{Cert})
]

| 元素       | 含义              |
| -------- | --------------- |
| (A)      | 前置假设和状态要求       |
| (G)      | 成功后必须满足的后置条件    |
| (\Theta) | 经过认证的参数适用域      |
| (\Delta) | 对样品和实验状态的副作用    |
| (R)      | 资源、风险和权限        |
| (W)      | 物理完成所需的见证       |
| (Q)      | 输出质控规则          |
| Cert     | Skill证书、版本和验证记录 |

因此，一个科学Skill不是“怎样做”，而是：

> **在什么条件下、以什么参数、对什么对象、产生什么状态变化、需要哪些见证、输出如何验证、失败时如何处理。**

---

## 2. 建立Scientific Skill IR和编译器

Agent或人类提供自然语言SOP后，不直接用于实验，而是编译成中间表示：

```text
自然语言SOP
      ↓
Scientific Skill IR
      ↓
类型和单位检查
      ↓
状态转换图
      ↓
资源锁与权限分析
      ↓
副作用和不可逆性分析
      ↓
运行时监视器
      ↓
测试预言机
      ↓
受控可执行代码
```

Scientific Skill IR至少包含：

```text
inputs
units
preconditions
allowed_parameter_region
forbidden_conditions
resource_locks
physical_side_effects
irreversible_effects
execution_states
expected_witnesses
postconditions
quality_checks
compensation_paths
provenance_outputs
```

这使得不同仪器驱动、MCP工具或实验室控制系统可以编译到同一个科学语义层。

---

## 3. Skill只能在认证参数域内自适应

LLM可以提议参数 (\tilde\theta)，但执行值必须满足：

[
\theta^*=
\Pi_{\Theta^{cert}}(\tilde\theta)
]

即投影到认证参数域。

如果参数超出 (\Theta^{cert})，系统不能让Agent凭语言推理直接扩展边界，只能：

* 进入模拟；
* 进入shadow模式；
* 要求人工批准；
* 创建新的Skill候选版本；
* 重新进行认证。

定义Skill适用包络：

[
\mathcal E_K=
\left{
(x,s):
P(G_K\mid A_K,x,s,K_v)
\ge1-\delta
\right}
]

Agent不是问：

> “我有没有这个Skill？”

而是问：

> “当前对象和状态是否位于这个Skill经过验证的适用包络内？”

---

## 4. 区分数学证明与物理认证

“Proof-Carrying”不意味着能数学证明实验一定成功。

Skill证书包含两部分：

### 静态证明部分

可以严格检查：

* 类型；
* 单位；
* 参数范围；
* 资源冲突；
* 非法调用路径；
* 状态机死锁；
* 未授权工具；
* 数据流权限；
* 前后置条件组合。

### 统计认证部分

通过历史实验和校准估计：

* 后置条件满足概率；
* 失败模式分布；
* 适用域覆盖；
* 测量质控通过率；
* 仪器和版本迁移风险；
* 置信区间与校准曲线。

这样不会把湿实验的不确定性伪装成软件级绝对证明。

---

## 5. 建立可组合Skill的assume—guarantee规则

两个Skill只有满足：

[
G_{K_i}\models A_{K_{i+1}}
]

才能自动组合。

并且需要满足：

[
\sum_i R(K_i)\le R_{\max}
]

以及：

[
\Delta_{K_i}
\cap
F_{K_{i+1}}
===========

\varnothing
]

其中：

* (R(K_i))：风险或资源预算；
* (\Delta_{K_i})：前一个Skill造成的状态变化；
* (F_{K_{i+1}})：下一个Skill禁止的状态。

因此：

```text
Skill A执行成功
```

并不自动表示：

```text
Skill B可以开始
```

必须由A的后置条件证明B的前置条件成立。

---

## 6. Skill输出携带“证据包”

每次Skill执行后，不仅返回：

```json
{"status": "success"}
```

而应返回：

```text
skill_id
skill_version
input_snapshot
parameter_snapshot
precondition_results
execution_witnesses
state_transition
raw_output_hashes
quality_results
uncertainty
postcondition_results
certificate_reference
```

这个证据包随后交给SciTX决定是否提交到E-Mem。

---

## 7. Skill可以自我改进，但不能自我认证

Agent可以：

* 识别Skill失败；
* 生成候选修订；
* 修改参数策略；
* 新增错误处理；
* 生成新的测试案例。

但Agent生成的新版本只能处于：

```text
Draft
→ Simulation
→ Shadow
→ Canary
→ Certified
```

Agent不能自行把自己生成的Skill提升为Certified。

SkillsBench已经显示，自生成Skills平均无收益，部分模型甚至明显退化，这说明“让模型写一个Skill再立即使用”不能作为可靠策略。([arXiv][8])

---

## 8. Skill证书必须可以自动撤销

以下事件应触发Skill重新认证或撤销：

* 仪器固件变化；
* 驱动或API变化；
* 分析模型变化；
* 校准方法变化；
* 样品类别超出历史适用域；
* 连续出现后置条件失败；
* 质控通过率显著下降；
* Harness版本改变；
* 上游Skill证书失效。

更重要的是，Skill失效要反向通知E-Mem：

```text
Skill版本K失效
→ 找出所有使用K产生的证据
→ 重算证据可信度
→ 更新依赖主张
→ 必要时撤销后续决策
```

这把Skills与科学记忆真正连接起来。

---

## 9. 评测指标

* Skill前置条件漏检率；
* 越界参数执行率；
* 后置条件满足概率的校准误差；
* Skill组合失败率；
* 未声明副作用率；
* 仪器版本漂移检测率；
* 证书错误接受率和错误拒绝率；
* 自生成错误Skill拦截率；
* Skill导致无效证据提交的概率；
* 跨仪器迁移后的性能下降；
* 从发现Skill失效到撤销相关证据的延迟。

# 七、为什么这三项足以构成真正的原创贡献

| --------- | ------------------- | ---------------------- | -------------------- |
| SciTX     | 证据事务、科学exactly-once | 部分可观测状态下的运行时屏蔽与证据提交    | 错误证据提交、物理重复执行、越权动作   |
| E-Mem     | 证据守恒记忆              | 决策不变、主张不增强的科学率失真压缩     | 压缩诱发决策翻转、失效传播、重复证据   |
| PC-Skills | 携证科学操作符             | Skill编译、适用包络、组合证明和证书撤销 | 合同违反、适用域越界、Skill失效污染 |

它们不是简单地组合数据库、工作流和形式化方法，因为三者分别引入了新的科学Agent语义：

1. **SciTX**把数据库事务改造成不可逆物理世界中的证据事务；
2. **E-Mem**把语言压缩改造成受科学决策失真约束的压缩；
3. **PC-Skills**把程序知识包改造成带物理适用域和统计保证的可撤销操作符。

# 最值得采用的总研究命题

> **面向部分可观测、不可逆和高成本真实实验的证据安全型Scientific Agent Operating System：通过事务化Harness、证据守恒多Agent记忆和可证明Scientific Skills，使LLM从实验执行者和科学裁判，转变为受约束、可校准、可审计的科学提议者。**

这里真正被评价的，不再是某个材料最终达到了多高性能，而是：

* Agent是否在错误状态下错误行动；
* 错误实验是否进入了模型；
* 错误记忆是否被多Agent重复放大；
* 压缩是否改变了科学结论；
* Skill是否在适用域外被滥用；
* 数据失效后系统是否主动撤回下游结论；
* 系统能否在保持自主性的同时降低错误科学主张率。

这才是自驱动实验室和Scientific Agent下一阶段真正缺少的底层创新。

回答：
# 三项创新的完整功能构建方案

## 一、总体结论：不要做三个孤立模块，要做一个“证据安全型自主科学操作系统”

建议将三项创新整合为：

# **ESAS-OS：Evidence-Safe Autonomous Science Operating System**

## 证据安全型自主科学操作系统

其核心不是让Agent“更聪明”，而是建立三道相互制约的底层机制：

| 底层问题                       | 核心组件                 | 决定什么                         |
| -------------------------- | -------------------- | ---------------------------- |
| Agent能否把一个想法作用到真实物理世界      | **SciTX科学事务Harness** | 这个动作能不能执行、是否真的执行、结果能不能进入科学闭环 |
| 多Agent能否共享、压缩、修订科学知识而不污染结论 | **E-Mem证据守恒记忆**      | 系统现在可以相信什么、哪些结论已失效、摘要有没有改变判断 |
| 一段实验程序能否成为可信、可组合、可撤销的能力    | **PC-Skills携证科学技能**  | 这个Skill在哪些条件下有效、如何验证、何时必须撤销  |

系统中的LLM、多Agent、贝叶斯优化器和实验设计器，都不再拥有直接的物理执行权或科学事实写入权，而只是受控的**提议者**。

---

# 二、重新调研后的创新边界

三项方向仍然成立，但必须避开已经被最新工作覆盖的部分。

## 1. SciTX不能只做“Agent—仪器协议”

2026年6月提出的LAP已经定义了InstrumentCard、仪器排他预留、样品锁、安全确认令牌、QUDT/UCUM物理单位、校准和不确定度字段，并考虑了Agent—仪器的任务生命周期。LAP也明确说明，它目前仍是设计规范，没有大规模实现和实证验证。 ([arXiv][1])

因此，SciTX不能把以下内容作为主要创新：

* 仪器发现；
* 参数Schema；
* 资源预留；
* 物理单位；
* 安全令牌；
* 仪器调用协议。

SciTX真正的原创部分应当是：

> **从科学意图、物理执行、状态核对、测量质控一直延伸到“证据提交”的事务语义。**

特别要解决：

* 部分可观测物理状态；
* 操作不可逆；
* 调用超时但物理动作已经发生；
* 仪器成功与测量有效分离；
* 测量有效与科学主张成立分离；
* 后发现故障时，如何撤销已产生的证据和下游结论。

---

## 2. E-Mem不能只做“摘要层+原始日志层”

TierMem已经提出：

* 有损摘要索引；
* 不可变原始日志；
* 查询时判断摘要是否充分；
* 必要时升级到原始证据；
* 验证后写回带来源的摘要。

它解决的是长时Agent中“摘要便宜但可能漏信息、原始日志可信但昂贵”的矛盾。 ([arXiv][2])

MemoryAgentBench表明，Agent记忆至少需要同时处理准确检索、测试时学习、长程理解和选择性遗忘；MemoryArena进一步指出，在静态记忆测试上表现很好，并不意味着记忆能够在多轮任务中指导正确行动。 ([OpenReview][3])

因此，E-Mem的原创部分不能只是：

* 向量数据库；
* 长期记忆；
* 分层存储；
* 摘要回溯；
* 语义检索。

真正应解决的是：

> **科学真值如何在多Agent、证据冲突、数据失效和记忆压缩条件下被维护。**

---

## 3. PC-Skills不能只做“形式化Skill合同”

VASO已经把机器人Skill表示为形式接口和规划接口的双重语义合同，并使用模型检查器验证时间逻辑约束，再把反例转换成Skill更新信号。其机器人实验报告了97.2%的形式规范符合率。 ([arXiv][4])

SkillsBench则发现，人工构建的Skills平均提高16.2个百分点，但84个可比较任务中仍有16个性能下降；模型自行生成的Skills平均没有带来收益。 ([arXiv][5])

因此，PC-Skills不能把以下内容单独作为创新：

* `SKILL.md`；
* 程序知识包；
* 形式化前后置条件；
* 模型检查；
* Agent自动生成Skill。

真正需要突破的是：

> **Skill不仅形式上安全，还必须在统计、计量和科学有效性层面经过认证；证书失效后，要能撤销它产生的证据和下游结论。**

# 四、系统必须强制满足的十条不变量

这些规则不能写在Prompt里，而必须由确定性运行时执行。

| 编号  | 系统不变量                       |
| --- | --------------------------- |
| I1  | LLM不能直接访问仪器驱动，只能提交动作提案      |
| I2  | Agent生成的文字不能直接进入权威科学记忆      |
| I3  | 未提交的测量结果不能更新BO、统计模型或候选排序    |
| I4  | 仪器返回成功不能自动等价为物理操作成功         |
| I5  | 物理操作成功不能自动等价为测量有效           |
| I6  | 测量有效不能自动等价为科学主张成立           |
| I7  | 超时后必须先核对真实状态，禁止盲目重试         |
| I8  | 摘要只能作为缓存，原始数据和事件账本才是权威来源    |
| I9  | Skill只能在其认证适用包络内执行          |
| I10 | Skill或证据失效后，必须自动重算所有下游主张和决策 |

AILA的实验已经表明，LLM可能越过任务边界，出现论文所称的“sleepwalking”，而且系统对轻微的提示格式变化仍然敏感。因此，实验边界、路由和终止条件必须从自然语言Prompt迁移到确定性状态机和策略引擎。 ([Nature][7])

# 五、公共数据模型

三个系统必须共享同一套对象和ID，否则无法做端到端审计。

## 1. 核心实体

| 实体                        | 作用                  |
| ------------------------- | ------------------- |
| `ScientificIntent`        | 人类或Agent提出的科学目标     |
| `ActionProposal`          | Agent建议执行的动作，但尚未获准  |
| `EvidenceTransaction`     | 一次从动作提议到证据提交的完整事务   |
| `Sample`                  | 样品身份、来源和母批次         |
| `SampleStateSnapshot`     | 某一时刻的样品可观测状态和信念状态   |
| `InstrumentStateSnapshot` | 仪器、环境、校准和资源状态       |
| `SkillVersion`            | Skill的不可变版本         |
| `SkillCertificate`        | Skill的形式、统计和计量认证    |
| `ExecutionAttempt`        | 一次命令调用尝试            |
| `PhysicalEffect`          | 推断或确认发生的一次物理作用      |
| `Witness`                 | 仪器、传感器、文件或人员提供的完成见证 |
| `Artifact`                | 原始数据、日志、配置、代码或报告    |
| `QCResult`                | 质控结果及所用规则版本         |
| `EvidenceNode`            | 经过门禁后可参与推理的证据       |
| `ClaimNode`               | 科学主张、假设或竞争解释        |
| `MemoryUnit`              | Agent可检索的记忆单元       |
| `CompressionCertificate`  | 记忆压缩保真验证结果          |
| `RevocationEvent`         | Skill、证据或证书失效事件     |
| `HumanDecision`           | 人工审批、拒绝、修改和说明       |

## 2. 一次实验至少需要五种不同ID

```text
intent_id          科学意图
transaction_id     证据事务
attempt_id         软件调用尝试
physical_effect_id 真实物理作用
evidence_id        最终提交的科学证据
```

这样可以处理：

* 一个意图产生多个事务；
* 一个事务因网络故障产生多个调用尝试；
* 多个调用尝试实际上只发生了一次物理动作；
* 一次物理动作产生多个数据文件；
* 数据文件最终可能不形成有效证据。

# 六、创新一：SciTX科学事务型Harness

# 6.1 研究命题

> 在部分可观测、不可逆和可能部分完成的真实实验环境中，能否建立类似数据库事务、但以“证据是否成立”为最终提交对象的运行时语义？

SciTX不是普通工作流，也不是仪器协议，而是一个**科学证据事务协调器**。

## 6.3 两套相互独立的状态机

### 物理执行状态机

```text
PROPOSED
→ VALIDATING
→ PREPARED
→ RESERVED
→ EXECUTING
→ RECONCILING
→ PHYSICALLY_COMPLETE
```

异常状态：

```text
WAITING_APPROVAL
REJECTED
PARTIAL
FAULTED
COMPENSATING
ISOLATED
ABORTED
```

### 证据状态机

```text
UNREGISTERED
→ QUARANTINED
→ QC_PENDING
→ COMMIT_READY
→ COMMITTED
```

异常状态：

```text
REJECTED
CONTESTED
INVALIDATED
SUPERSEDED
```

关键是允许出现：

```text
physical_status = PHYSICALLY_COMPLETE
evidence_status = REJECTED
```

也就是：

> 实验确实做了，但结果不能用于科学推断。

## 6.4 三阶段证据提交

### 阶段一：Prepare

在任何动作发生前冻结：

* 样品状态版本；
* 仪器状态版本；
* Skill版本和证书；
* 参数和单位；
* 质控规则版本；
* 预期后置条件；
* 风险和预算；
* 是否需要人工批准；
* 当前科学意图和主张ID。

### 阶段二：Execute and Witness

执行期间记录：

* 实际发送的命令；
* 实际参数；
* 仪器确认；
* 温度、湿度、时间等环境轨迹；
* 文件生成事件；
* 操作开始和结束时间；
* 传感器或人工确认；
* 样品状态变化；
* 所有异常。

### 阶段三：Scientific Commit

建议定义：

[
\mathrm{Commit}(T)=1
]

当且仅当：

[
W_{\mathrm{complete}}
\land
P_{\mathrm{pre}}
\land
P_{\mathrm{post}}
\land
Q_{\mathrm{pass}}
\land
C_{\mathrm{skill}}
\land
C_{\mathrm{calibration}}
\land
P_{\mathrm{provenance}}
]

全部成立。

其中分别代表：

* 物理完成见证完整；
* 前置条件成立；
* 后置条件成立；
* 测量通过QC；
* Skill证书有效；
* 校准有效；
* 溯源信息完整。

## 6.5 部分可观测状态模型

SciTX不应把所有状态都表示成确定布尔值。

建议每个关键状态采用：

```yaml
state_variable: thermal_equilibrium
value: true
probability: 0.97
observed_or_inferred: inferred
supporting_witnesses:
  - temperature_trace_018
  - equilibrium_rule_v1.2
valid_from: ...
valid_until: ...
```

对不可直接观测状态，维护信念：

[
b_{t+1}(z)
\propto
p(o_{t+1}\mid z,a_t)
\sum_{z_t}
p(z\mid z_t,a_t)b_t(z_t)
]

工程第一版不必直接实现完整POMDP，可以先采用：

* 状态变量；
* 明确的`KNOWN / UNKNOWN / INFERRED`；
* 置信概率；
* 规则更新；
* 有效期；
* 证据指针。

后续再将其升级为贝叶斯状态估计。

## 6.6 “核对后重试”算法

普通Agent常见策略：

```text
timeout → retry
```

SciTX必须改成：

```text
timeout
→ 标记当前attempt结果未知
→ 查询仪器实际状态
→ 检查输出文件及哈希
→ 检查传感器轨迹
→ 核对样品状态变化
→ 推断是否已经产生physical_effect
→ 决定继续、补偿、重平衡、隔离或人工处理
```

伪代码：

```python
def reconcile_before_retry(transaction):
    instrument_state = query_instrument()
    artifacts = inspect_artifacts(transaction.time_window)
    witnesses = inspect_sensor_and_event_logs()
    sample_state = update_sample_belief(witnesses)

    effect = infer_physical_effect(
        instrument_state,
        artifacts,
        witnesses,
        sample_state,
    )

    if effect.confirmed:
        attach_effect_to_transaction(effect)
        return "DO_NOT_RETRY"

    if effect.possible_but_uncertain:
        quarantine_transaction()
        return "MANUAL_OR_DIAGNOSTIC"

    if effect.confirmed_not_occurred:
        return "SAFE_TO_CREATE_NEW_ATTEMPT"
```

这里不能承诺真实物理动作绝对“exactly once”。更准确的保证是：

> **动作身份可核对、重复物理作用可检测、证据只提交一次。**

## 6.7 不使用“回滚”，使用补偿图

每个不可逆Skill必须声明：

* 会改变什么；
* 哪些改变不可逆；
* 哪些改变可以补偿；
* 哪些状态需要重新平衡；
* 哪些情况必须隔离样品；
* 隔离后是否仍可保留为失败证据。

例如：

```text
执行异常
├── 未发生物理作用 → 重新执行
├── 已部分发生 → 诊断
├── 已发生但未产生有效数据 → 重新平衡后新事务
├── 样品状态不可确定 → 隔离
└── 数据存在但QC失败 → 保留原始记录，不提交证据
```

## 6.8 动态自主权

建议不要给系统一个固定“Level 3自主”标签，而是实时计算自主权。

[
A_t=
f(
C_{\mathrm{skill}},
U_{\mathrm{state}},
C_{\mathrm{memory}},
H_{\mathrm{instrument}},
R_{\mathrm{action}},
C_{\mathrm{agent}}
)
]

| 等级 | 权限                     |
| -- | ---------------------- |
| A0 | 只建议，不执行                |
| A1 | 执行低风险、确定性、已认证动作        |
| A2 | 在认证包络内自动执行和恢复          |
| A3 | 自动选择下一实验并闭环，但只能使用已提交证据 |

出现以下情况立即降级：

* 样品状态不确定性升高；
* Skill证书进入Degraded；
* 多Agent记忆出现冲突；
* 仪器校准失效；
* Agent近期置信校准变差；
* 连续QC失败；
* 操作超出历史验证域。

## 6.10 SciTX验收标准

建议第一版至少通过以下故障注入：

| 故障             | 合格行为                |
| -------------- | ------------------- |
| 命令确认丢失，但仪器已执行  | 不盲目重试，识别已发生动作       |

| 仪器显示完成，但热平衡未通过 | 物理完成、证据拒绝           |

| 人工审批后参数被修改     | 原审批令牌失效             |

核心指标：

* 无效证据提交率；
* 盲目重试次数；
* 重复物理作用漏检率；
* 状态核对准确率；
* 故障恢复完整率；
* 越权动作逃逸率；
* 证据包完整率；
* 有界风险下的自主执行覆盖率。

# 七、创新二：E-Mem证据守恒多Agent记忆

# 7.1 研究命题

> 多Agent记忆经过写入、共享、冲突、重复引用、压缩和修订后，能否保持与原始证据相同的科学判断强度和实验决策？

当前多Agent记忆的一项关键开放问题就是共享状态的一致性；最新研究已经开始把它类比为计算机体系结构中的缓存一致性问题。 ([arXiv][8])

---

## 7.2 四层记忆架构

```text
L0 不可变原始事件层
L1 有效证据层
L2 主张与假设层
L3 Agent工作缓存与压缩层
```

### L0：不可变原始事件层

保存：

* 原始仪器文件；
* 传感器日志；
* 操作事件；
* 样品状态历史；
* Agent提案；
* 人工审批；
* 代码、模型和Skill版本。

只能追加，不能覆盖。

### L1：有效证据层

只允许写入：

* SciTX已提交的实验结果；
* 经过来源验证的文献片段；
* 可复算的派生结果；
* 明确标记的无效或反例数据；
* 校准和质控结果。

### L2：主张与假设层

保存：

* 假设；
* 桥接假设；
* 经验主张；
* 竞争解释；
* 支持证据；
* 反驳证据；
* 适用条件；
* 可推翻条件；
* 当前结论等级。

### L3：Agent工作缓存

保存：

* 当前计划；
* 检索摘要；
* 临时分析；
* 草稿；
* 角色相关上下文。

L3可以被压缩或删除，但不能直接成为权威证据。

## 7.3 三维状态模型

一个科学主张不能只用一个`status`字段。

### 生命周期状态

```text
PROPOSED
QUARANTINED
ACTIVE
SUPERSEDED
ARCHIVED
INVALIDATED
```

### 认识论状态

```text
SUPPORTED
REFUTED
INCONCLUSIVE
CONTESTED
```

### 结论等级

```text
C0 数据无效
C1 单次有效观察
C2 可复现行为
C3 经验模型支持
C4 与机制预测一致但存在替代解释
C5 多模态证据和因果干预确认
```

这样可以表示：

```text
lifecycle = ACTIVE
epistemic_status = CONTESTED
claim_level = C3
```

即该主张仍在系统中有效，但证据存在冲突，且只达到经验模型层面。

## 7.5 多Agent不能按“票数”累积证据

三个Agent引用同一篇论文，不是三条独立证据。

建议按照独立根来源计算证据：

[
W(c)=
\sum_{r\in \mathrm{UniqueRoots}(c)}
q_r,a_{r,c},d_r
]

其中：

* (q_r)：来源质量；
* (a_{r,c})：对当前主张的适用性；
* (d_r)：来源独立性权重。

根来源定义：

| 来源类型    | 独立根                         |
| ------- | --------------------------- |
| 文献      | DOI、版本和具体实验                 |
| 实验      | `physical_effect_id`和独立样品批次 |
| 分析      | 不构成新根，只是已有证据的变换             |
| Agent发言 | 永远不构成独立证据根                  |
| 摘要      | 永远不构成独立证据根                  |

这可以消除多Agent“共识膨胀”。

## 7.6 科学真值维护与失效传播

例如：

```text
原始谱 E1
  ↓
派生电导 D1
  ↓
温度模型 M1
  ↓
桥接假设 H1
  ↓
候选排序 R1
  ↓
下一实验 A1
```

如果后来发现E1未达到热平衡：

1. E1标记为`INVALIDATED`；
2. D1重新计算或失效；
3. M1检查是否仍有独立证据；
4. H1降低支持度或进入`CONTESTED`；
5. R1重新排序；
6. A1标记为“基于后失效证据产生”；
7. 必要时重新评价后续实验结果。

需要实现两类传播：

### 硬失效传播

上游不存在替代支持时，下游直接失效。

### 软降级传播

存在其他独立证据时，下游保留，但降低置信度或结论等级。

这是一套非单调科学真值维护，而不是普通数据库级联删除。

## 7.7 多Agent版本一致性

每个Agent读取上下文时获得快照：

```yaml
evidence_graph_version: 182
claim_graph_version: 64
sample_state_version: 27
skill_registry_version: 19
```

Agent输出必须携带：

```yaml
based_on_versions:
  evidence_graph: 182
  claim_graph: 64
used_evidence_ids:
  - E-312
  - E-318
generated_claims:
  - C-proposal-981
```

写入时检查：

* Agent是否基于旧版本；
* 使用的证据是否已经失效；
* 是否与新主张冲突；
* 是否重复计入相同根来源；
* Agent是否有该对象的写权限。

冲突不能采用`last-write-wins`。

正确行为是：

```text
Claim A: 支持H1
Claim B: 反驳H1

→ 创建CONTESTED状态
→ 保留两条证据分支
→ 提取尚未解决的条件
→ 生成区分实验需求
```

## 7.8 记忆写入门

Agent不能直接写：

```text
事实：材料X存在某机制
```

它只能提交：

```yaml
memory_type: proposed_claim
content: ...
supporting_evidence_ids:
  - ...
scope:
  - ...
confidence: ...
falsifiers:
  - ...
```

写入流程：

```text
Agent Proposal
→ 进入Quarantine
→ 来源和版本检查
→ 独立证据检查
→ 适用域检查
→ 与已有主张冲突检查
→ 规则或验证器评估
→ Active / Contested / Rejected
```

---

## 7.9 核心算法：决策不变、主张不增强的记忆压缩

普通压缩优化：

[
\min |\hat M|
]

E-Mem应优化：

[
\min_{\hat M} |\hat M|
]

约束：

[
D_{\mathrm{sci}}(M,\hat M)\le \epsilon
]

定义科学失真：

[
D_{\mathrm{sci}}
================

\lambda_aD_{\mathrm{action}}
+\lambda_cD_{\mathrm{claim}}
+\lambda_sD_{\mathrm{scope}}
+\lambda_xD_{\mathrm{counterevidence}}
+\lambda_pD_{\mathrm{provenance}}
]

其中：

| 项                              | 含义              |
| ------------------------------ | --------------- |
| (D_{\mathrm{action}})          | 压缩前后下一实验选择是否改变  |
| (D_{\mathrm{claim}})           | 主张状态、等级或后验是否改变  |
| (D_{\mathrm{scope}})           | 适用条件是否丢失或扩大     |
| (D_{\mathrm{counterevidence}}) | 反例、冲突和可推翻条件是否丢失 |
| (D_{\mathrm{provenance}})      | 是否还能回到全部原始证据    |

---

## 7.10 压缩验证流程

```text
选择原始权威子图
→ 生成候选摘要
→ 条件保留检查
→ 反证保留检查
→ 主张等级检查
→ 下一动作回放
→ 来源恢复检查
→ 签发CompressionCertificate
```

### 决策不变测试

对压缩前后分别运行固定实验决策探针：

* 下一实验Top-1是否变化；
* Top-k排序变化；
* 是否从“继续诊断”变成“直接执行”；
* 是否从“证据不足”变成“支持”；
* 是否改变重复实验与新实验的选择。

可定义：

[
D_{\mathrm{rank}}
=================

1-\tau(
\mathrm{rank}(M),
\mathrm{rank}(\hat M)
)
]

其中(\tau)可采用秩相关系数。

### 主张不增强测试

要求：

```text
压缩后的结论等级 ≤ 原始证据允许的等级
```

例如摘要不能将：

```text
“与VTF样行为一致，但分段Arrhenius不能排除”
```

压成：

```text
“已证明是VTF机制”
```

## 8.4 三层认证

## 第一层：形式认证

检查：

* 类型；
* 单位；
* 参数边界；
* 权限；
* 资源互斥；
* 状态机可达性；
* 死锁；
* 时间逻辑安全；
* 前后置条件；
* Skill组合条件；
* 禁止执行路径。

可使用：

* JSON Schema/Pydantic做类型；
* Z3/SMT做约束；
* TLA+验证SciTX状态不变量；
* NuSMV、UPPAAL或类似工具验证时间状态机。

VASO已经说明形式反例可以反向改进Skill语义合同，但形式验证只能证明被形式化的性质，不能证明真实实验测量一定科学有效。 ([arXiv][4])

---

## 第二层：统计认证

在认证适用包络(\mathcal E_K)内评估：

* 前置条件满足率；
* 后置条件完成率；
* QC通过率；
* 已知失败模式覆盖率；
* 不确定度校准；
* 不同日期、批次和仪器版本下的稳定性；
* 罕见但严重失败概率。

建议认证条件：

[
\mathrm{LCB}_{1-\alpha}
\left[
P(G_K\mid A_K,\mathcal E_K)
\right]
\ge \tau
]

其中：

* (A_K)：前置条件；
* (G_K)：后置条件；
* (\mathcal E_K)：适用包络；
* LCB：置信下界；
* (\tau)：最低可接受可靠性。

不要只报告平均成功率，应给出置信下界和失败类型。

---

## 第三层：计量认证

检查：

* 校准链；
* 校准有效期；
* 仪器版本；
* 测量不确定度；
* 原始数据完整性；
* 量纲和单位；
* 分析代码版本；
* 参考样品或参考程序；
* 质控规则的适用域。

因此，一个Skill可能：

```text
形式认证：通过
统计认证：通过
计量认证：失效
```

此时它可以在仿真中使用，但不能产生可提交的实验测量证据。

---

## 8.5 Skill适用包络

Skill匹配不能只按名称。

定义：

[
\mathcal E_K=
\left{
(x,s,i,v):
P(G_K\mid A_K,x,s,i,v)\ge1-\delta
\right}
]

其中包括：

* 输入参数；
* 当前样品状态；
* 仪器型号；
* 固件版本；
* 环境范围；
* 上游Skill版本；
* 质控规则版本；
* 数据处理版本。

Agent提议参数(\tilde\theta)后：

[
\theta^*=
\Pi_{\Theta_K^{cert}}(\tilde\theta)
]

即只能投影到认证域内。

超出认证域时只能：

* 拒绝；
* 请求人工批准；
* 进入新Skill验证；
* 使用Shadow模式；
* 创建新版本。

不能让LLM临场解释“应该没问题”。

---

## 8.6 Skill生命周期

```text
DRAFT
→ STATIC_VERIFIED
→ SIMULATED
→ SHADOW
→ CANARY
→ CERTIFIED
→ DEGRADED
→ SUSPENDED
→ REVOKED / DEPRECATED
```

### 权限

| 状态              | 权限          |
| --------------- | ----------- |
| Draft           | 不可调用真实仪器    |
| Static Verified | 仅模拟         |
| Simulated       | 可进入Shadow   |
| Shadow          | 观察人工实验，不控制  |
| Canary          | 受控低风险执行     |
| Certified       | 在认证包络内自动执行  |
| Degraded        | 降低自主权或需人工审批 |
| Suspended       | 禁止新事务       |
| Revoked         | 重新审查历史证据    |

Agent可以提出新Skill或修改建议，但不能自行将其升级为`Certified`。SkillsBench显示，自生成Skill平均没有带来可靠收益，说明Skill生成和Skill认证必须严格分离。 ([arXiv][5])

## 8.7 Skill组合验证

两个Skill只有满足以下条件才能组合：

[
G_{K_i}\models A_{K_{i+1}}
]

此外还要检查：

[
\Delta_{K_i}
\cap
F_{K_{i+1}}
===========

\varnothing
]

其中：

* (G_{K_i})：前一个Skill保证的后置条件；
* (A_{K_{i+1}})：下一个Skill要求的前置条件；
* (\Delta_{K_i})：前一个Skill造成的副作用；
* (F_{K_{i+1}})：下一个Skill禁止的条件。

还必须检查：

* 资源是否冲突；
* 前一Skill是否改变样品状态；
* 单位是否兼容；
* 上下游证据Schema是否兼容；
* 总风险是否超预算；
* 中间状态是否有足够见证。

## 8.9 Skill漂移和撤销

触发条件包括：

* 仪器固件变化；
* 驱动或API变化；
* 代码哈希变化；
* 校准规则变化；
* 分析模型变化；
* 样品类别超出认证域；
* 连续QC失败；
* 后置条件满足率下降；
* 出现新失败模式；
* 上游Skill撤销；
* Harness状态机版本改变。

撤销流程：

```text
Skill K_v 被撤销
→ 查找由K_v产生的所有PhysicalEffect
→ 查找相关EvidenceNode
→ 根据撤销原因判断证据是否失效或降级
→ 更新所有ClaimNode
→ 重算历史决策依赖
→ 通知正在运行的事务
→ 降低系统自主权
```

这一步是PC-Skills相对普通形式化Skill最重要的创新。

# 九、三个创新点的端到端协同流程

## 场景一：正常实验

```text
1. Agent提出ActionProposal
2. SciTX冻结样品、仪器、Skill和证据图版本
3. PC-Skills确认Skill证书及适用包络
4. SciTX获得资源锁并执行
5. PC-Skills Runtime收集见证和Evidence Bundle
6. QC服务评估结果
7. SciTX提交EvidenceNode
8. E-Mem更新证据图和主张图
9. BO或实验设计器读取Committed Evidence
10. 产生下一ActionProposal
```

---

## 场景二：仪器超时但物理动作已经发生

```text
1. ExecutionAttempt超时
2. SciTX进入RECONCILING
3. 查询仪器、文件、传感器和样品状态
4. 确认physical_effect已经发生
5. 禁止重试
6. 若数据完整，继续QC
7. 若数据不完整，事务进入Quarantine
8. 样品状态按实际物理历史更新
```

---

## 场景三：事后发现校准有问题

```text
1. Calibration证书被撤销
2. 找到受影响的Skill执行记录
3. 标记相关EvidenceNode为待重评
4. E-Mem沿依赖图传播
5. 派生结果重新计算
6. 主张降级、争议化或失效
7. 受影响BO模型重新训练
8. 历史决策保留，但标注其证据基础已失效
```

---

## 场景四：多Agent记忆冲突

```text
Agent A：支持H1
Agent B：反驳H1
Agent C：引用与A相同的论文

E-Mem：
- A与C归并到同一个根来源
- B保留为独立反证分支
- H1状态设为CONTESTED
- 不执行多数投票
- 生成“区分H1与替代解释所需的实验条件”
```

---

## 场景五：上下文压缩

```text
1. E-Mem选择相关权威子图
2. 生成摘要
3. 检查条件、反证、来源和主张等级
4. 用摘要与原始图分别运行下一实验决策
5. 若决策或主张变化超过阈值，拒绝压缩
6. 通过后签发CompressionCertificate
7. Agent使用摘要，但高风险决策自动回溯原始证据
```

* 候选变量；
* 约束；
* 代理模型；
* 采集函数；
* 重复或探索决策。

其动作价值偏向：

[
U(a)
====

\mathbb E[\Delta HV]
-\beta C(a)
-\gamma R(a)
]

二者只有“如何产生ActionProposal”不同。

之后都必须经过：

```text
SciTX → PC-Skills → 实验 → QC → E-Mem
```

因此系统创新与材料性能、BO算法或某个候选无关。

# 一、创新点一：C³-Harness——面向“可信科学结论”的三重收敛控制器

## 1. 导师对Harness的理解，哪里对、哪里不够精确

在当前Agent工程语境里，Harness一般是模型之外的环境、工具、状态、上下文、反馈、评测和控制结构。OpenAI将Harness engineering描述为为Agent设计环境、抽象、反馈回路和系统结构，使Agent能够可靠推进任务；Anthropic则强调任务分解、结构化交接、独立评价器和上下文重置。Harness确实可以显著加快系统达到合格结果，但“快速收敛”只是Harness带来的结果之一，并非Harness本身的完整定义。([OpenAI][1])

你们现在的 `scientific_harness` 已经解决了：

* C_P：物理提交；
* C_M：计量用途准入；
* C_E：认识论/主张准入；
* ActionGate唯一自主命令入口；
* 失效数据不进入BO；
* blind retry为零；
* shadow/enforce运行模式。

但它当前主要回答：

> **这次动作和结果可不可以进入系统？**

导师想要的“快速收敛能力”需要进一步回答：

> **在预算有限时，下一步到底应该做新配方、做重复、补测频段、重新平衡，还是停止，才能最快得到一个稳定且可复现的科学判断？**

这正是当前Harness没有主动解决的部分。

---

## 2. 具体创新定义

建议将第一个创新收敛为：

# **C³-Harness：Physical–Metrological–Epistemic Convergence Harness**

## 物理—计量—认识论三重收敛Harness

这里的“收敛”不是只看材料性能或BO目标值，而是同时定义三种距离。

### 物理收敛

系统对“实验是否按预期真实发生”的不确定性下降：

[
D_P =
1-P(C_P=\mathrm{confirmed})
]

例如：

* 样品是否正确；
* 温度是否真的达到；
* 测量是否完整；
* 命令超时后动作是否已经发生；
* 是否存在部分完成。

### 计量收敛

系统对“这个观测是否可用于指定分析”的不确定性下降：

[
D_M =
1-P(C_M=\mathrm{admissible})
]

例如：

* QA是否通过；
* KK是否合理；
* Rb方法是否稳定；
* 几何和接触误差是否可接受；
* 当前频率窗口是否足够；
* 重测后结果是否一致。

### 认识论收敛

系统对“当前结论是否稳定”的不确定性下降：

[
D_E =
H!\left[p(H\mid D)\right]
+
\lambda P(\text{claim reversal})
]

其中包括：

* 假设后验熵；
* 新数据到来后结论翻转的概率；
* 留一批次后结论是否稳定；
* 换一种合理Rb方法后断点是否消失；
* 证据失效后主张是否降级。

统一收敛势函数：

[
\Phi_t =
w_PD_P+w_MD_M+w_ED_E
]

Harness每次选择下一动作：

[
a_t^*
=====

\arg\max_a
\frac{
\mathbb E[\Phi_t-\Phi_{t+1}\mid a]
}{
\operatorname{cost}(a)+\lambda_r\operatorname{risk}(a)
}
]

这才是把“快速收敛”变成可计算、可比较的技术创新。

---

## 3. 它具体控制哪些动作

当前Stage1的动作基本是“推荐下一配方”。C³-Harness需要把动作空间扩成：

| 动作类型    | 示例             |
| ------- | -------------- |
| 新配方实验   | 选择新的R/N        |
| 同配方独立重制 | G1中的最优配方×3     |
| 同一样品复测  | 判断短期漂移、接触或随机误差 |
| 重新平衡后测量 | 排除热平衡和调理状态问题   |
| 增加温度点   | 缩小T_break不确定区间 |
| 增加频率范围  | 解决Rb或ECM可辨识性不足 |
| 改变扰动幅值  | 检查小信号线性        |
| 停止或HOLD | 现有信息无法支持更高等级主张 |

这意味着“重复实验”不再是人为固定规则，而是与新配方实验平等竞争的动作。

## 4. 与现有代码的具体结合

你们已有的 `_eval_convergence` 使用三类指标：

* 近5次best score改善；
* 近3次配方距离；
* 近3次GP标准差。

这只能评价**优化器数值收敛**，不能判断：

* 最优是否小于复现地板；
* 最优是否经不起同配方重复；
* Rb方法切换是否制造了虚假改善；
* 当前结论是否会因某个证据失效而翻转；
* 是否应把预算用于重复而不是继续探索。

建议新增四个模块：


由以下服务共同提出动作：

## 5. 如何证明它真的“收敛更快”

目前不能直接声称这一点。你们线B只有10个trial、2轮前瞻，而且没有同配方重复，因此现阶段没有足够证据证明Harness加速了收敛。项目报告自己也明确不声称闭环已经收敛。

需要做三类比较：

### 历史回放

基线：

* 原始MOBO；
* MOBO+LLM；
* C³-Harness。

比较达到以下状态所需实验数：

* 找到表观最优；
* 找到可复现最优；
* 结论在留一批次后不翻转；
* 结论在证据失效模拟下不翻转。

### 合成故障回放

注入：

* Rb方法误选；
* 一个高分点失效；
* 重复性比预期差；
* 最优位于边缘；
* 某次温度未平衡。

评价C³-Harness是否主动转向重复、诊断或HOLD。

### G1真机前瞻

G1正适合验证：

* 最优配方×3；
* 两个邻近内部点；
* Harness shadow同时生成“如果由我决策，下一步做什么”；
* 与现有固定实验计划比较。

## 客观评价

* **方法创新性：高**
* **与当前系统匹配度：高**
* **当前完成度：中等**
* **最大风险：当前真实轨迹太短，容易被评审认为只是新停止规则**

因此，这个创新必须突出：

> 它不是“更快找到高分”，而是“更快达到稳定、可复现、可发表的决策状态”。

# 二、创新点二：R²-Memory——角色隔离、可撤销、决策保持的科学记忆

## 1. 导师对Memory的理解基本正确，但只是研究范围

导师把Memory分为：

* 多Agent之间的Memory；
* 单Agent多轮对话的Memory。

这一区分是合理的，但当前研究已经存在：

* 长期多轮记忆；
* 分层记忆；
* 图记忆；
* 多Agent协作轨迹记忆；
* 向量数据库Teachability。

MemoryAgentBench已经把Agent记忆分为准确检索、测试时学习、长程理解和选择性遗忘，并发现当前方法尚不能同时做好这些能力；G-Memory则已经使用三层图结构保存多Agent的高层经验、查询和协作轨迹。([OpenReview][2])

最新科学仪器Agent工作也已经把人类反馈概括为输入—输出对存入ChromaDB，在相似任务中召回，从而减少重复错误。因此仅做“多Agent共享向量库”或“单Agent记住前几轮对话”，创新性并不高。([Nature][3])

---

## 2. 当前项目真正需要的Memory是什么

建议将第二个创新收敛为：

# **R²-Memory：Role-Isolated and Retractable Scientific Memory**

## 角色隔离、可撤销、决策保持的科学记忆

它要同时解决三件事：

1. 单Agent跨轮持续工作；
2. 多Agent共享科学状态但不互相污染；
3. 证据更新、失效和压缩后，下一实验决策不能悄悄改变。

## 3. 你们当前Memory已经做到什么

现有 `scientific_memory` 已有：

* 四值逻辑超图；
* 最小支持集；
* 失效传播；
* 版本快照和写门；
* 独立证据根去重；
* 失效后重建CommittedObservationView；
* 真实history_db桥接；
* GP在更小证据集上重训；
* 压缩证书；
* PC-Skills撤销到BO重训的完整链路。

这已经明显强于普通Agent记忆。

但它当前的主要缺口也非常明确：

* 缺L0完整原始事件记忆；
* 缺L3真实Agent角色记忆；
* 还没有实际多Agent长期运行；
* 还没有证明压缩后真实LLM决策不变；
* 还没有比较单Agent多轮记忆和多Agent共享记忆；
* Stage1只存prompt哈希，公开流程无法单凭哈希重放Agent上下文；
* S09候选和S10排序默认确定性，Memory即使改进，也未必影响最终候选和排序。

最后一点尤其重要：

> **如果Memory没有进入真实决策路径，它只是记录系统，不是Agent创新。**

---

## 4. 两种Memory必须明确分开

## 单Agent多轮记忆：Round Memory

每轮Agent启动时不加载完整历史聊天，而加载一个结构化 `RoundState`：

```yaml
campaign:
  id:
  round:
  mode:

current_goal:
current_claims:
unresolved_questions:
rejected_explanations:
active_constraints:
available_budget:

last_decision:
decision_reason:
observed_result:
prediction_error:

next_allowed_actions:
required_human_decisions:

evidence_snapshot_version:
skill_registry_version:
```

这比“上一轮聊天摘要”更可靠。

Anthropic在长时Agent研究中发现，仅靠compaction并不足以维持清晰状态；更可靠的方法是重置上下文，并通过结构化产物交接上一轮状态。([Anthropic][4])

你们可以保留：

* 对外只保存prompt SHA256；
* 对内保存加密的完整调用包；
* 论文公开结构化`RoundState`和哈希；
* 私有评测时用完整调用包重放。

---

## 多Agent记忆：Role Memory + Shared Epistemic Memory

不要让所有Agent共享一份聊天历史。

### 私有角色记忆

| Agent          | 私有记忆            |
| -------------- | --------------- |
| 文献Agent        | 检索失败、数据库偏差、查询策略 |
| 假设Agent        | 未验证假设、推理草稿      |
| Critic         | 历史常见错误模式        |
| Planner        | 决策和结果偏差         |
| Rb Skill Agent | 各拟合方法在不同谱形下的表现  |
| BO Agent       | 模型不确定性和采集函数表现   |

这些内容不能直接成为科学事实。

### 共享科学记忆

只包括：

* committed evidence；
* claim及其证据根；
* 支持和反证；
* 来源体系；
* 样品/批次/条件；
* 结论等级；
* 失效状态；
* Skill版本；
* 真实决策后果。

---

## 5. 对你们项目最重要的是“来源域隔离”

你们有三个特别容易混淆的知识域：

```text
S8海泡石母体系
凹凸棒土线B目标体系
生物聚合物—黏土线A验证体系
```

当前代码已经明确禁止S8训练数据混入凹凸棒土BO，只作为`transfer_reference`。

Memory创新应把这一规则升级成通用语义：

```yaml
evidence_domain:
  material_system:
  campaign:
  source_or_target:
  transferable_as:
    - prior
    - descriptor
    - process_rule
  forbidden_use:
    - direct_training_label
```

例如S8数据可以作为：

* 变量范围先验；
* 安全先验；
* 趋势假设；
* 文献母题。

但不能自动成为凹凸棒土的训练观测。

这可以形成一个非常具体的创新：

> **带使用权限的科学记忆，而不是只有访问权限的记忆。**

也就是同一条记忆不只是“谁能看”，还要规定：

* 可以用来生成假设；
* 可以用来设先验；
* 可以用来训练模型；
* 可以用来提升主张等级；
* 只能作为背景，不得形成证据。

## 6. 记忆压缩在你们项目中应如何定义

不要评价“摘要和原文语义相似度”，而要评价：

### 下一实验决策是否保持

[
D_{\mathrm{decision}}
=====================

1-
\mathbb{1}
\left[
\operatorname{TopK}(\pi(M))
===========================

\operatorname{TopK}(\pi(\hat M))
\right]
]

### 主张等级是否保持

压缩前后：

```text

CONTESTED不能变成SUPPORTED
HOLD不能变成GO
```

### 反证是否保留

必须保存：

* CHITO边界反例；
* 单曲线QC不能预测复现这一负结果；
* DRT当前不可用；
* 机理不可辨识；
* 线B复现地板目前是代理；
* 闭环轨迹短，不声称收敛。

这些负结果一旦被摘要掉，系统会产生系统性过度声称。

# 三、创新点三：Rb-ACT——可校准、会拒绝、会主动补测的动态Rb Skill

## 1. 导师选择Rb拟合作为动态Skill，是三个想法里最具体、最合理的

但必须客观指出：

> **当前Rb拟合已经是一个弱形式的动态Skill。**

你们现在的代码根据实际温区和谱形在四种方法中路由：

```text
深冷：low-frequency plateau优先

其他情况：
zero crossing
→ valley
→ plateau
→ equivalent circuit fallback
```

Stage0还记录了`rb_method`，并有v2的Rb方法不变性分析。

因此，如果只是：

* 把现有函数包装成Skill；
* 让LLM根据温度选一个方法；
* 拟合失败后换另一个方法；

创新性会很弱，因为它与当前实现本质相同，只是加了Agent外壳。

---

## 2. 动态Rb Skill应分成四个等级

| 等级       | 能力                                     | 当前状态 |
| -------- | -------------------------------------- | ---- |
| L0 条件路由  | 基于规则选择zero crossing/valley/plateau/ECM | 已有   |
| L1 自适应推断 | 多方法同时拟合，校准地选择或平均                       | 未完成  |
| L2 主动诊断  | 不确定时请求补频率、重测或重新平衡                      | 未完成  |
| L3 在线学习  | 根据已验证结果更新方法可靠性和补测策略                    | 未完成  |

真正有方法创新的至少是 **L2+L3**。

---

## 3. 具体创新定义

# **Rb-ACT：Active, Calibrated and Teachable Bulk-Resistance Skill**

## 主动、可校准、可学习的体电阻分析Skill

它不只是给出一个Rb值，而是输出：

```yaml
rb_posterior:
method_probabilities:
method_disagreement:
fit_validity:
uncertainty_components:
applicability_status:
abstain_reason:
recommended_measurement_action:
skill_version:

```

## 5. Context特征

### 单谱特征

* 是否存在零交点；
* 零交点邻域密度；
* valley prominence；
* 低频平台长度和斜率；
* Nyquist曲率；
* 高频截距可见性；
* 频率窗口宽度；
* 低频噪声和反转；
* 量程触顶比例；
* KK残差；
* 不同拟合方法残差。

### 序列特征

* 前后温点Rb；
* Rb随温度是否连续；
* 当前点是否形成异常跳变；
* 当前点是否处于可能的断点附近；
* 升温或降温；
* 样品是否已循环；
* 前几次方法选择及其稳定性。

### 状态特征

* 样品和批次；
* 厚度和面积不确定性；
* 仪器校准；
* 热平衡状态；
* 接触风险；
* 当前Skill证书适用域。

---

## 6. 不要让LLM直接选方法

动态Skill的Gate应采用可校准的统计模型，而不是让LLM看图后说“我觉得应该用plateau”。

在当前小样本条件下，优先考虑：

* 规则先验 + 贝叶斯逻辑回归；
* 小型梯度提升模型；
* 层次贝叶斯模型；
* contextual bandit；
* Bayesian model averaging。

不建议一开始训练深度网络。

每个方法输出：

[
p(R_b\mid Z,m)
]

Gate输出：

[
p(m\mid Z,c)
]

最终：

[
p(R_b\mid Z,c)
==============

\sum_m
p(R_b\mid Z,m)p(m\mid Z,c)
]

当一个方法明显优于其他方法时使用选择；多个方法相近时使用模型平均；严重冲突时拒绝输出。

AutoEIS已经证明自动生成和贝叶斯评估ECM可以降低人工选模偏差，因此“自动选拟合模型”本身不能作为你们的主要创新。([NIST][5])

更近期的贝叶斯EIS研究还表明，后验和后验预测检查可以识别数据是否足以支持某个ECM，并判断最低需要测到的频率，为实时缩短或扩展EIS测量提供依据。([Nature][6])

所以你们的创新应该是：

> **拟合Skill发现信息不足后，能够主动改变下一次测量，而不是强行给出一个Rb。**

---

## 7. 主动反馈动作

如果出现不同问题，Skill返回不同实验请求。

| 问题        | 动态反馈                 |
| --------- | -------------------- |
| 高频截距不可见   | 扩展更高频或增加高频采样密度       |
| 低频平台未形成   | 延长低频范围或降低最低频率        |
| 谱随时间变化    | 同条件短时重复，检查稳定性        |
| 零交点附近数据稀疏 | 在交点邻域增加频率点           |
| 方法间Rb差异过大 | 暂停进入Arrhenius，执行诊断测量 |
| 深冷量程触顶    | 调整测量设置或标为删失数据        |
| 断点与方法切换重合 | 用同一方法约束重算，或补断点邻域温点   |
| KK异常      | 不做Rb推断，返回重新平衡/重测     |
| 接触可能异常    | 重新装夹或同一样品重复          |
| 信息仍不足     | 输出ABSTAIN，不提供单点值     |

这会把Rb拟合从：

```text
数据分析工具
```

升级为：

```text
分析—诊断—补测闭环控制器
```

## 8. 在线学习必须避免自我强化

不能这样做：

```text
Skill预测Rb
→ 把自己的Rb当真值
→ 用自己的结果训练自己
```

训练信号应来自：

### 合成数据

生成已知真实Rb的谱：

* 不同等效电路；
* 不同噪声；
* 不同频率截断；
* 不同量程触顶；
* 不同接触效应；
* 不同低温异常。

### 专家或强分析共识

对少量代表谱建立：

* 多专家复核；
* Bayesian ECM；
* 后验预测检查；
* 多方法一致性；
* 完整频率谱作为参考。

### 重复和序列一致性

弱监督信号：

* 同一样品重复；
* 邻近温点连续性；
* 升降温匹配；
* 独立批次是否产生相同方法偏差。

只有SciTX提交的有效结果才能更新Skill。

### 拟合正确性

* **方法创新性：中高**
* **最大风险：被评审认为只是EIS工程优化**

> **Adaptive Analytical Skill：分析模型会校准、会拒绝、会主动改变测量，并将不确定度传递给自主决策。**

# 二、C³-Harness与现有SciTX的关系

## 1. 交叉部分非常明确

现有SciTX已经解决了：

* `ExecutionAttempt / PhysicalEffect / Evidence`三类ID；
* 多见证物理提交C_P；
* 按用途准入C_M；
* 按主张等级准入C_E；
* `EvidenceTransaction`；
* `ActionGate`唯一自主命令入口；
* blind retry为零；
* shadow/enforce；
* 无效观察不进入BO；
* 失效后可以触发下游重建。

这些功能回答的是：

> 一次动作是否合法、是否真的发生、测量是否可以成为证据。

而C³-Harness回答的是：

> 在已有证据、预算和不确定性下，下一步做什么，才能最快达到稳定、可复现、不过度声称的科学结论？

所以两者并不冲突：

```text
C³-Harness：选择下一动作
        ↓
SciTX：审查和执行该动作
        ↓
PC-Skills：规定怎样执行
        ↓
E-Mem：提交和维护结果
```

OpenAI和Anthropic对Harness的定义也更接近“模型之外的完整环境、工具、反馈和持久状态”，而不只是一个优化器；“快速收敛”是Harness设计可能产生的效果，但不是Harness本身的全部定义。([OpenAI][1])

---

## 2. C³-Harness实际上已部分写进当前计划

你们执行计划中已经有：

[
U=E[\Delta HV]+\lambda I-\beta C-\gamma R
]

以及：

* 概率化终止；
* 新配方与重复实验的选择；
* 延长到至少3个前瞻轮。

这和C³-Harness的核心非常接近。

因此，**C³-Harness不是一个完全新出现的方向**，而是把目前M4中一行较抽象的任务：

```text
概率化终止 + 新配方vs重复
```

正式提升成：

```text
可计算的科学收敛状态
+ 多类型实验动作
+ 信息价值策略
+ 收敛证书
```

### 它新增的部分

现有 `_eval_convergence` 只检查：

* 近5次best score改善；
* 最近配方距离；
* GP标准差。

当前代码中的具体阈值也是围绕这三项定义的。

C³需要增加：

* 复现地板是否确认；
* Rb方法不确定性；
* 主张是否会因删除一个证据而翻转；
* 留一批次后结论是否稳定；
* 当前更值得做新配方、重复、重测还是补频率；
* 是否达到“科学HOLD”而不是“优化器收敛”。

现有PC-Skills已经完成：

* 形式、统计、计量三层证书；
* Wilson置信下界；
* provisional证书；
* 运行时gate；
* 漂移；
* 撤销；
* Evidence Bundle；
* 认知账户与执行账户分离。

但是当前Rb本体仍然是确定性四策略路由：

```text
深冷：low-frequency plateau优先
其他：
zero crossing
→ valley
→ plateau
→ equivalent circuit
```

而且Rb直接用于：

[
\sigma=\frac{L}{R_bA}
]

再进入Arrhenius、T_break和Stage1目标。

因此现有PC-Skills解决的是：

> 这个Rb分析程序是否有合同、证书和适用域。

Rb-ACT要解决的是：

> Rb分析程序本身如何根据谱形和历史上下文，自适应选择模型、表达不确定性、拒绝分析并请求补测。

这是新的算法层。

## 2. 与当前Rb工作的交叉

已有工作可以直接复用：

* 四个Rb专家方法；
* `rb_method`日志；
* 方法不变性分析；
* 合成谱FPR；
* 电导率不确定度；
* Arrhenius稳健性；
* 断点不确定度；
* PC-Skills证书框架。

文档显示，主力LRS数据的Rb方法不变性风险较低，6.15_merged的全管线合成FPR约为0.06；同时between-specimen差异0.252 dex明显高于当前估计的分析不确定度约0.058。

这意味着：

> Rb-ACT大概率不会推翻主力LRS的总体趋势，但可能改变具体Rb、置信区间、弱数据集断点和线B候选排序。

## 4. 它可能影响哪些已有结论

### P1：亚零度传导区间变化

**风险：低到中。**

主力LRS方法不变性目前较好，所以“存在宽温行为变化”大概率保留。

可能变化的是：

* 精确T_break；
* 精确Ea；
* 断点置信区间；
* 个别弱数据集是否仍被纳入13/15；
* starch离群点解释；
* CHITO是否继续只是边界反例。

### P2：复现地板

**风险：中低。**

当前结论是：

[
\text{分析不确定度}\ll\text{片间复现地板}
]

如果Rb-ACT给出的区间明显比0.058 dex更宽，这个差距可能缩小，但不一定反转。

需要重新报告：

```text
片间方差
分析方法方差
几何测量方差
重复测量方差
```

而不是只报一个总值。

### P3：线B BO结果

**风险：中高。**

因为Rb影响：

```text
Rb
→ conductivity
→ Ea
→ combined_score
→ history_db
→ GP
→ Pareto排序
→ 当前最优
```

若对10个历史trial全部使用Rb-ACT重算：

* 最优trial可能改变；
* BO与random的比较可能改变；
* top-2不可区分概率可能改变；
* G1选择的最佳点可能需要重新解释。

所以Rb-ACT不能直接替换主线。

## 5. 必须采取的保护方式

文档现有的原则完全正确：

> 影响主张的修改只能产生`*_v2 + delta_report`，不能覆盖legacy。

建议分四级：

### Level 0：离线shadow

只对历史谱运行，不影响任何结果。

### Level 1：双跑

真实实验同时生成legacy和Rb-ACT结果，但主线继续使用legacy。

### Level 2：审计用途

Rb-ACT用于：

* 标记方法冲突；
* 提议补测；
* 生成不确定性；
* 影响C_E主张等级；

但不进入BO训练。

### Level 3：受控进入BO

只有完成：

* 合成真值测试；
* 历史回放；
* 专家盲评；
* 覆盖率校准；
* G1双跑；
* 预注册delta门槛；

才允许作为`train_Yvar`或主观测进入BO。

AutoEIS已经能自动提出统计上合理的等效电路模型，所以“自动选ECM”本身不够新；Rb-ACT需要证明的是**校准、拒绝和主动补测如何改变自主实验决策**。([NIST][4])

SkillsBench也显示，经过整理的Skills平均有帮助，但不同任务差异很大，自生成Skills平均收益很弱，因此动态Skill必须依靠确定性验证和真实任务评测，不能只展示Agent会切换算法。([arXiv][5])

## 判断

> **Rb-ACT是PC-Skills中的新旗舰Skill，而不是PC-Skills本身的重命名。它需要较多新代码，也是唯一可能实质影响现有科学数值链的方向。**

# 七、当前最容易出现的错误决策

## 错误一：现在把三件套改名为C³/R²/Rb-ACT

不建议。

这会造成：

* 原有创新叙事不稳定；
* 文档和代码名不一致；
* 208个测试对应的对象发生漂移；
* 审稿人难以区分“已完成”与“新提案”；
* 容易让人误以为三个新功能已经真机验证。

## 错误二：在G1之前改Stage0主线

不建议。

G1是当前A轨唯一湿实验硬门，同时也是SciTX真机shadow数据来源。

此时改Rb主线会混淆：

* G1原本验证的历史最佳点；
* 新算法对历史最优的重排；
* 复现地板变化；
* Harness真机验证。

## 错误三：继续做大量纯代码而推迟真机验证

当前执行计划已经很明确：高价值纯代码工作基本完成，决定性缺口是真机故障对照和enforce灰度。

自驱动实验室的能力也不能只用一个优化速率表示；不同实验空间的精度、噪声、成本和运行条件必须分开报告。([Nature][6])

# 最终结论

三项新方向中：

* **C³-Harness**：约一半是现有SciTX和M4计划的细化，一半是新的科学动作选择层；
* **R²-Memory**：大部分是现有E-Mem的补全，主要填补L0/L3和真实Agent运行证据；
* **Rb-ACT**：是最实质性的新算法，需要新代码，也最可能影响现有科学数值。

总体上：

> **不需要重建现有三创新和系统主干，但需要增加三个v2子模块。**

对已有结论的风险并不对称：

* C³和R²基本不会推翻现有材料结论；
* Rb-ACT可能改变Rb、σ、Ea、T_break、combined score和线B排序，所以必须采用**legacy冻结、v2双跑、delta报告、shadow→审计→受控接入**。

最稳妥的研究叙事不是“我们又提出了三个创新”，而是：

> **现有SciTX、E-Mem、PC-Skills已经建立了可信治理底座；下一阶段分别补上科学收敛决策、真实Agent记忆和动态可校准分析Skill，使系统从“不会错误接纳证据”，进一步走向“能够在受限实验中主动选择最有价值的下一步”。**

# 一、升级后的完整系统目标

建议把下一阶段系统定义为：

# **ESAS-OS 2.0：Evidence-Safe Adaptive Science Operating System**

它由六层构成：

```text
L6  文献、假设、反例、规划Agent
                    ↓ Proposal
L5  C³科学收敛策略：下一步做什么
                    ↓ ActionProposal
L4  SciTX：动作是否合法、物理上是否完成、证据能否提交
                    ↓ Certified Invocation
L3  PC-Skills / Rb-ACT：动作和分析怎样可靠完成
                    ↓ Evidence Bundle
L2  E-Mem / R²-Memory：系统能够相信什么
                    ↓ Committed Observation
L1  BO、实验设计、统计模型、主张阶梯
```

各层权限必须严格分开：

| 层          | 可以做                 | 不能做          |
| ---------- | ------------------- | ------------ |
| LLM Agent  | 提假设、候选、解释、反例        | 直接下发仪器、写权威事实 |
| C³-Harness | 选择新配方、重复、诊断或停止      | 修改原始数据       |
| SciTX      | 批准、执行、核对、提交证据       | 判断唯一微观机制     |
| Rb-ACT     | 分析谱、量化不确定性、建议补测     | 自己认证自己       |
| E-Mem      | 保存证据、冲突、撤销、上下文      | 把Agent文字当事实  |
| BO/统计      | 使用Committed观测计算下一动作 | 使用QC失败或未提交结果 |

AILA已经显示，实验Agent即使使用多Agent架构，仍会受提示格式影响、偏离指令并出现“sleepwalking”，所以关键约束必须由确定性Harness执行，而不能依靠Prompt。([Nature][1])

# 三、升级一：Rb-ACT动态分析Skill

这是最适合先做、最容易用现有数据验证、也最可能改变下游数值的升级。

当前Stage0使用四种确定性策略：

```text
深冷 → low-frequency plateau优先
其他 → zero crossing → valley → plateau → ECM
```

这一实现已经是“条件路由Skill”，但还不是会校准、会拒绝、会主动补测的动态Skill。

## 3.1 Rb-ACT的功能目标

# **Rb-ACT：Active, Calibrated and Teachable Rb Skill**

输入：

```text
单温点EIS谱
+ 当前温度
+ 前后温点谱
+ 热史
+ QA/KK
+ 样品状态
+ 仪器状态
+ 历史方法表现
```

输出不是一个Rb单值，而是：

```yaml
rb_posterior:
  mean:
  median:
  credible_interval:

method_probabilities:
  zero_crossing:
  valley:
  plateau:
  equivalent_circuit:

method_disagreement:
applicability_status:
uncertainty_decomposition:
abstained:
abstain_reason:
recommended_measurement_action:
skill_version:
certificate_id:
```

## 3.2 内部架构

```text
输入谱
  ↓
特征提取
  ├── 零交点专家
  ├── Valley专家
  ├── Plateau专家
  └── ECM/Bayesian ECM专家
            ↓
     方法适用性Gate
            ↓
  单方法选择 / 模型平均
            ↓
   Rb后验 + 方法不确定性
            ↓
接受 / 拒绝 / 主动补测
```

AutoEIS已经能够自动提出统计上合理的等效电路，所以“自动选ECM”本身不够构成创新；你们的创新必须集中在**适用性校准、拒绝和主动改变测量**。([NIST][3])

---

## 3.3 第一版算法选择

当前真实样本少，不建议一开始训练深度神经网络。

### Expert层

保留现有四种方法，不修改legacy：

```text
E1 zero_crossing
E2 valley
E3 low_frequency_plateau
E4 equivalent_circuit
```

每个Expert输出：

[
p(R_b\mid Z,m)
]

不能只输出点估计。

### Gate层

第一版推荐：

* 规则先验；
* 贝叶斯逻辑回归；
* 或层次多项逻辑回归。

输入特征：

* 温度；
* 是否存在零交点；
* 零交点邻域采样密度；
* valley prominence；
* 低频平台长度和斜率；
* 高频截距是否可见；
* KK残差；
* 量程触顶比例；
* 前后温点Rb连续性；
* 当前温点是否靠近断点；
* 升温或降温；
* 当前样品和批次。

Gate输出：

[
p(m\mid Z,c)
]

最终：

[
p(R_b\mid Z,c)
==============

\sum_m p(R_b\mid Z,m)p(m\mid Z,c)
]

---

## 3.4 拒绝机制

以下情况不得强行给出Rb：

```text
max p(method) < τ_method
方法间log10(Rb)差异 > τ_disagreement
KK或QA不满足分析用途
后验区间过宽
邻近温点出现无法解释的跳变
频率窗口无法观察关键截距
断点与方法切换高度重合
```

输出：

```yaml
status: ABSTAIN
reason: insufficient_high_frequency_information
```

而不是自动退化到ECM并继续下游分析。

---

## 3.5 主动补测策略

Rb-ACT应当能够返回实验动作：

| 诊断        | 动作                  |
| --------- | ------------------- |
| 高频截距不可见   | 扩展高频上限或增加高频点        |
| 零交点附近采样不足 | 在交点邻域加密频率           |
| 低频平台未形成   | 降低最低频率              |
| 谱随时间变化    | 相同条件短时复测            |
| KK异常      | 重新平衡后测量             |
| 接触疑似变化    | 重新装夹或同一样品复测         |
| 方法严重冲突    | 保持HOLD，不进入Arrhenius |
| 断点附近不确定   | 增加断点附近温度点           |

动作选择可采用：

[
a^*=
\arg\max_a
\frac{
\mathbb E[
\operatorname{Var}(R_b\mid D)
-----------------------------

\operatorname{Var}(R_b\mid D,y_a)
]
}{
\operatorname{cost}(a)
}
]

即每单位成本最大的Rb不确定性下降。

# 四、升级二：R²-Memory真实Agent记忆

目前E-Mem的证据图、失效传播、版本快照、根去重和BO重训链路已经完成；缺口主要是执行计划里明确列出的L0/L3，以及真实多轮Agent评测。

MemoryAgentBench指出，Agent记忆至少需要同时评估准确检索、测试时学习、长程理解和选择性遗忘；仅测试一次检索命中远远不够。([OpenReview][4])

---

## 4.1 目标定义

# **R²-Memory：Role-Isolated and Retractable Agent Memory**

新增的不是另一套数据库，而是：

1. 单Agent跨实验轮次记忆；
2. 多Agent角色隔离记忆；
3. 不同知识的使用权限；
4. 压缩后下一动作和主张等级不改变；
5. Agent能够从历史错误中调整，但不能把自己的输出写成事实。

---

## 4.2 四层结构

```text
L0 不可变事件记忆
L1 已提交证据
L2 主张、假设和冲突

```

现有E-Mem主要覆盖L1/L2。

### 补L0

记录：

* 人工override；
* 实验结果；
* 预测误差；
* Skill版本；
* 下一动作。

# 五、升级三：C³科学收敛Harness

C³不替代SciTX。它是在SciTX上方选择“下一步做什么”的策略层。

当前终止评估只基于性能、最近改善、配方距离、GP标准差、预算和异常。

这只能判断优化器状态，不能判断科学结论是否稳定。

---

## 5.1 收敛对象

定义五类不确定性：

[
S_t=
{
U_{\mathrm{physical}},
U_{\mathrm{metrological}},
U_{\mathrm{repro}},
U_{\mathrm{epistemic}},
U_{\mathrm{optimization}}
}
]

### 物理不确定性

* 事务是否完整；
* 是否存在未核对故障；
* 样品状态是否确定。

### 计量不确定性

* Rb后验；
* 方法分歧；
* QC通过概率；
* 几何误差；
* 温湿度状态。

### 复现不确定性

* 同配方片间方差；
* 当前效果相对于复现地板的大小；
* 最优是否经独立重复确认。

### 认识论不确定性

* 假设熵；
* 主张是否CONTESTED；
* 删除单条证据后是否翻转；
* Skill撤销后是否翻转；
* 留一批次后是否稳定。

### 优化不确定性

* GP后验；
* Pareto前沿稳定性；
* simple regret；
* 候选排序不确定性。

---

## 5.2 动作空间升级

当前下一动作基本是新的R/N配方。

C³动作空间应为：

```text

REPLICATE_FORMULATION

EXTEND_FREQUENCY_RANGE
ADD_TEMPERATURE_POINT
RUN_REFERENCE_CIRCUIT
REANALYZE_WITH_RB_ACT
REQUEST_HUMAN_REVIEW
HOLD
STOP
```

## 5.3 统一效用

[
U(a)=
w_O\mathbb E[\Delta HV]
+w_I\mathbb E[\Delta H_{\mathrm{hypothesis}}]
+w_M\mathbb E[\Delta U_{\mathrm{measurement}}]
+w_R\mathbb E[\Delta U_{\mathrm{repro}}]
-w_CC(a)
-w_{\mathrm{risk}}R(a)
]

其中：

| 项                                 | 含义             |
| --------------------------------- | -------------- |
| (\Delta HV)                       | Pareto性能改善     |
| (\Delta H_{\mathrm{hypothesis}})  | 假设不确定性下降       |
| (\Delta U_{\mathrm{measurement}}) | Rb/QC/计量不确定性下降 |
| (\Delta U_{\mathrm{repro}})       | 复现不确定性下降       |
| (C(a))                            | 真实实验成本         |
| (R(a))                            | 安全、证据和失效风险     |

迁移发现模式提高(w_I)；闭环优化提高(w_O)；接近当前最优但复现不足时提高(w_R)。

BoTorch适合实现概率模型和MC采集函数，但动作类型、成本、复现价值和科学停止规则仍需由你们定义。([NeurIPS 论文集][5])


| SciTX   | 诊断、参考电路、HOLD |

| 校准过期      | 测试证书失效            |
| 样品ID错配    | 注入虚拟manifest错误    |
| QC服务超时    | 断开测试服务            |
| Skill证书撤销 | 运行中标记SUSPENDED    |
| Agent越界参数 | 提交测试Proposal      |
| 旧版本写入     | 用stale snapshot提交 |

# 九、现有结论的保护策略

## 不变原则

* legacy产物永不覆盖；
* 所有新分析写`*_v2`；
* 每次产生`delta_report`；
* 历史recipe和冻结hash不变；
* S09/S10继续冻结；
* EIS-only继续封顶C4；
* `replay != real`；
* S8不能进入凹凸棒土训练。

## 影响等级

| 升级                    | 对现有科学结论                  |
| --------------------- | ------------------------ |
| 测量EvidenceTransaction | 几乎不影响数值，只影响准入和溯源         |
| R²-Memory             | 不修改历史结论，只影响Agent未来行为     |
| C³-Harness            | 不修改历史结果，只影响未来实验选择        |
| Rb-ACT                | 可能改变Rb、σ、Ea、T_break和线B排序 |

因此Rb-ACT必须拥有最严格的升级门。

# 十、验收总表

| 模块        | 软件验收                | 历史回放验收                   | 真机验收                |
| --------- | ------------------- | ------------------------ | ------------------- |
| SciTX测量路径 | 所有结果经事务             | 历史Artifact可重建事务          | G1 shadow + dummy故障 |
| Rb-ACT    | 合成覆盖和拒绝             | 不增加虚假断点                  | 在线双跑、补测有效           |

| PC-Skills | 证书与撤销               | 历史适用域验证                  | 去掉provisional       |
| 整体        | 端到端撤销               | governed优于基线             | enforce稳定           |

SkillsBench显示Skills并非总是提升Agent性能，甚至在部分任务上产生回退，因此每个Skill都必须以成对基线和确定性验收进行评价，而不能因为包装成Skill就默认有价值。([arXiv][6])


* Rb-ACT的计量不确定性；

* G1的直接复现地板；
* SciTX的真实执行可靠性。

缺少这些输入，C³只会退化成另一套人工权重停止规则。

# 十二、升级后的论文贡献结构

## A轨

继续保持：

> EIS-only、复现地板、可辨识性天花板和主张治理的真实材料案例。

完成G1即可推进，不要被B轨升级拖延。当前就绪度评估也认为A轨接近Tier B，唯一湿实验硬门是G1。

## B轨

主叙事应改为：

> **一个真实自主实验系统如何从“工具可调用”，升级为“只有经过校准分析、证据记忆和收敛决策后，结果才能影响下一实验”。**

三项方法贡献：

1. **Rb-ACT**：分析Skill会校准、拒绝和主动测量；
2. **R²-Memory**：多Agent记忆支持证据撤销、用途隔离和决策保持；
3. **C³-Harness**：选择最能降低科学不确定性的下一动作，而非只追求材料性能。

自驱动实验室的表现不能仅以优化速度衡量；实验空间、测量精度、噪声、运行寿命、吞吐和成本都应被单独报告。([Nature][7])

---

# 最终建议

当前项目下一阶段最正确的升级主线是：

> **先把真机测量变成唯一、完整、可撤销的Evidence Transaction；再把现有Rb分析升级成可校准、会拒绝、会补测的动态Skill；随后让E-Mem真正参与单Agent多轮和多Agent决策；最后由C³-Harness在新配方、重复、诊断、补测和停止之间选择最有价值的动作。**

不要优先做：

* 更多Agent角色；
* 更长Prompt；
* 更大的向量数据库；
* 让LLM直接选择Rb方法；
* 让Agent自动生成并认证Skill；
* 让C³直接控制G1；
* 为了“智能”而解冻S09/S10。

你们现在最有价值的升级不是让系统产生更多建议，而是让系统逐步具备三种能力：

1. **知道哪一个结果可以被相信；**
2. **知道自己还不知道什么；**
3. **知道下一步怎样最有效地减少这个不知道。**
