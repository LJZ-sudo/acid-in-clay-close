# M6 基线消融报告（证据约束迁移/排序 agent）

> 独立分析包，**只读** `20260607_openrouter_publication_v2` 冻结产物，不调用 LLM，不修改任何主线代码/数据/registry。
> 目的：压力测试"Nature Communications 系统创新口"所需的"agent 相对基线的增量价值"。

## 0. 输入与可复现性

- 候选实例池（S09 打分层）：**N = 5**（I1–I5，来自 3 个 family）
- 文献材料池（S08）：**31 张卡 / 28 个不同组分**；**无真实被引数**（citation 字段全为 0）
- 治理打分公式用 `ranking_robustness_v2` 的 8 维权重重算，**与冻结总分逐位吻合**（I1=0.8833 …），故留一消融完全可复现。
- 实验 ground truth：仅 **I1（藕粉/淀粉=LRS 路线）= 正验证**、**I2（壳聚糖）= 边界对照**；I3/I4/I5 无实验。

## 1. M6-A 选择器对比 — 把"实验赢家 I1"排到前列的能力（20000 次 MC）

| 选择器 | P(I1=top1) | P(I1∈top2) | P({I1,I2} 同时∈top2) |
|---|---|---|---|
| 随机 | 0.200 | 0.397 | 0.101 |
| 流行度（组分文献频次代理） | **1.000** | 1.000 | **0.000** |
| 浅层裸-LLM（仅新颖度+引用有效性） | 0.252 | 0.502 | 0.165 |
| **完整治理 agent** | **1.000** | 1.000 | **1.000** |
| （解析随机参照） | 0.200 | 0.400 | 0.100 |

**两条诚实结论：**
1. **"把 LRS 选为头号候选"不是治理 agent 独有能力**——纯组分流行度也能把 I1 顶到第一（starch+PVA+chitosan+PA 组分在文献池里都很常见）。这削弱了"agent 选中 LRS = 智能"的强主张。
2. 治理 agent 的**真正增量在 top-2 结构**：只有它能同时把"赢家 I1 + 边界 I2"精确放进前二（100% vs 流行度 0% / 随机 10% / 裸 LLM 16.5%）。即 agent 的价值不在"选第一"，而在**构造出一个可证伪的对照对（赢家+边界）**——恰好对应项目"诚实对照"的灵魂。浅层裸-LLM 几乎等于随机（无判别力）。

## 2. M6-B 权重留一消融 — 归因

逐个移除 8 个治理维度并重新归一化后，**I1 在所有留一组合中仍为 top-1**（移除 `one_minus_risk` 时 ρ=0.9，其余 ρ=1.0）。

→ I1 的领先是**多维稳健**的，不靠任何单一维度（特别地，**不是只靠 low-T 这一项**撑起来的）。
→ 反面含义：无法把"选中 LRS"归因到某个独特治理维度，它由组分基本面驱动。

## 3. M6-C 鲁棒性（复用现成 200-seed 扰动）

`top1_stability_rate = 1.00`，default_top1 = I1，Spearman→default 均值 0.95。打分排序稳定。

## 4. 客观结论（对 NC 系统创新口）

**可以支撑的（较弱、机制性主张）：**
- 治理打分**可 100% 复现**、对权重扰动稳定（200 seeds）、对留一稳健。
- 治理 agent 是**唯一**能稳定产出"赢家+边界对照对"的选择器（top2_both=100% vs 基线 0–16.5%）。

**不能支撑的（强统计主张）：**
- 由于候选池 N=5、文献池无被引、ground truth 仅 I1 正+I2 边界，且**纯组分流行度即可选中第一名**，本消融**无法**证明"agent 显著优于简单基线"。它只是机制性归因，不是有统计功效的 head-to-head 优越性证据。

**要把它升级成 NC 级证据，需要：**
1. 扩大候选池到数十个 instance（让随机/流行度基线的命中率自然降到低位）；
2. 引入真实被引/外部基准，让"流行度基线"可信且可被击败；
3. 对多个候选取得实验 ground truth（不只 I1/I2），才能算 precision@k / 富集度等带置信区间的指标。

> 一句话：M6 做出来了，正面信号是"治理打分稳健且能构造可证伪对照对"；但它**坐实了**之前的判断——现有数据规模下统计功效太弱，单凭它仍进不了 NC 的系统创新决定性证据线。

## 5. 增强尝试（不做实验）：扩大候选池 + 补被引

应"不做实验、只补文献"的要求，做了两项增强尝试，结果如下。脚本：`m6_expanded_pool.py` / `_meta.py`，产物：`m6_expanded_results.json` / `_meta_out.txt`。

### 5.1 补真实被引 —— 不需付费 API，但卡数据质量是真瓶颈

**结论先行**：补被引**不需要申请任何付费文献 API**。项目里已集成免费的 OpenAlex provider
（`literature/providers/openalex_provider.py`，无需 key、已返回 `cited_by_count`）；Crossref / Semantic Scholar 同样免费。
真正的障碍是**现有 31 张卡的元数据质量**，不是 API 可达性。

**实测（`_openalex_probe.py`，OpenAlex 现场按标题反查）**：
- 25/31 张卡有"看起来像论文标题"的字段，其中 24 张能返回某个被引数；
- **但约一半核心质子导体卡是错配**：
  - `manual_1157b11126` 标题就是期刊名 → 匹配到期刊本身（cites=2732, 1978 年），错；
  - `manual_8d58a81c9e`（"phosphoric acid retention…"）→ 匹配到"重金属废水处理综述"（cites=2062），错；
  - `manual_b9c3d1711d` / `manual_f5f9ab95ca` / `manual_f56a2b0129` 均匹配到不相关论文；
  - 6 张标题是期刊名/OCR 残片（如 `M O Acc OH…`、`= c 0,H + exp`）直接查不了（其一返回 HTTP 400）。
- 能**正确**匹配并拿到可信被引的，是少数有完整论文标题的卡（如 `…Anti-Freeze Electrolytes…` cites=65、
  `Phosphoric Acid-in-Clay…PBI…` cites=15、`…starch-chitosan blend…` cites=212）+ 8 张离题背景 W 卡。

→ **无 DOI 时按标题自动查被引不可信**（会把无关论文的高被引塞进来，反而污染 popularity 基线，违背诚实护栏）。

**可行的补法（值得做，且不用付费 API）**：由你为核心卡补**正确 DOI 或完整标题**（约十几张关键卡），
再用现成 OpenAlex/Crossref 拉被引——这样 popularity 基线才有可信输入。这正是你说的"我自行下载 / 给你正确引用"那条路，
**确实有价值**；但它治的是"基线可信度"，不改变 §6 的核心结论（流行度本来就能选中 I1）。

### 5.2 扩大候选池 N=5 → N=482（组合枚举，纯计算）

按配方语法（host × acid × clay × additive）枚举 S08 现有组分，注入真实 I1–I5 作为锚点。关键指标 = 各选择器把**实验赢家 I1** 检索到前列的能力（池中随机命中极低）。

| 选择器 | I1 检索名次（/482） | top3 命中 |
|---|---|---|
| 随机（解析） | P(top1)=0.002, P(top3)=0.006 | — |
| 流行度（组分文献频次） | **1** | ✅ |
| 确定性代理打分（**非真 agent**） | 155 | ✗ |

**三条诚实发现：**
1. **✅ 好消息（方法可行）**：扩大池子把随机基线 P(top1) 从 0.20（N=5）压到 **0.002**——这一步纯靠文献/枚举即可完成，无需任何实验。
2. **✗ 对故事不利**：纯组分流行度在大池里**仍把 I1 排第一**。说明"选中 LRS 路线"在任何池子规模下**都不是 agent 的独有能力**，简单基线即可达成。
3. **⛔ 真正的瓶颈浮现**：我手搓的确定性代理打分（mechanism 广度+冷尾证据+完整度加权）比纯流行度还差（I1 排 155）。这证明——**要在扩大池里公平评判"真治理 agent vs 基线"，必须用生产级 S10 LLM ranker 给全部 482 个候选打分**。这是一步 **LLM 调用成本**（不是物理实验），也是补文献之后剩下的唯一关键缺口。

### 5.3 结论：补文献能做到哪、做不到哪

- **能（纯文献/计算）**：扩大候选池、压低随机基线——已完成。
- **做不到（数据所限）**：补真实被引——核心卡无 DOI。
- **还需要（非实验，但要 LLM 成本）**：对扩大后的 482 候选重跑真 LLM ranker，才能得到"agent vs 基线"的公平对比。
- **不需要做的**：物理实验（用户已确认不做）。

> 净结论：你"不做实验、补文献"的方向部分有效——能把随机基线打下去；但它同时暴露了两件硬事实：①"选中 LRS"靠流行度就能做到，不是 agent 护城河；② 真正的公平对比还差"对大池跑一次真 LLM 排序"这一步（要 key、要钱，但不用做实验）。agent 的真正卖点应转向**可证伪对照对 + 可复现治理 + claim 审计**，而非"选材准"。

## 6. 用「真实生产打分函数」重做大池对比（无需 key）

**关键发现**：查 `09_ranking/ranking_generation_audit.json`，冻结发表那次的排序模式是
`generation_mode = deterministic_from_candidate_audit`——**最终把 I1 排第一的"排序器"根本不是 LLM**，
而是确定性代码 `s8_stage3/scoring/candidate_audit.py::audit_candidates()`。LLM 只在上游 S09 负责
"生成候选 + 写 element_evidence"，**最终打分是确定性的**。

→ 所以"用真排序器给 482 候选打分"**不需要 API key、不花钱、完全可复现**。脚本 `m6_real_ranker.py`
直接 import 这段生产函数（只读冻结池文件、不写主线），给真实 I1–I5（用其真 element_evidence）
和 477 个合成候选（按真实 claim pool 确定性映射 element_evidence）统一打分。

| 选择器 | I1 检索名次（/482） | top3 |
|---|---|---|
| **真实生产打分函数** `audit_candidates` | **1** | ✅ |
| 流行度（组分文献频次） | 1 | ✅ |
| 随机 | P(top1)=0.002 | — |

**比 §5.2 强的地方**：用**真函数**（不是我手搓的代理）时，实验赢家 I1 在 482 池里被排到
**第 1 名**（远超随机 0.2%）。这说明项目真实的确定性打分逻辑确实能在大池里把验证赢家顶上来。

**但仍要点破的三件事（不迎合）：**
1. **流行度也把 I1 排第一** → 即便用真函数，"top-1 检索"仍不是治理打分独有的能力。
2. **领先优势薄如纸**：I1=0.8833，紧随其后是一**整簇合成 PAAm-接枝淀粉配方=0.8825**（差 0.0008，近乎并列）。
   说明 I1 的"第一"不稳健，多个合成配方实质打平。
3. **比较本身不完美**：合成候选被赋予了"满额证据映射"（每个组分拿到其全部 descriptor+card），

**§6 净结论**：用真函数做，结果确实更好看（I1 排第 1、免费、可复现），但
①流行度也做得到、②领先只有 0.0008 且被一簇合成配方咬住——所以**这仍不能证明"治理 agent 稳健且独有地优于简单基线"**。
要拿到决定性证据，仍需"真 S09 LLM 在大池上生成候选 + 多个实验真值"，这才是天花板。

> 跨 §5/§6 的一句话总结：**你不做实验是对的，补文献也确有用（随机基线被打到 0.2%）；
> 真正的瓶颈不在"再做实验"或"再补文献"，而在"选材准"这件事本身就不是 agent 的护城河**——
> 流行度基线一直咬着它。论文叙事应把 agent 的价值锚定在它**唯一**能提供的东西上：
> 可证伪的"赢家+边界"对照、100% 可复现的治理打分、可审计的 claim 边界。

## 7. 宽池 + 干扰项：决定性对比（终于把 agent 和流行度拉开了）

§5/§6 的病根诊断：**文献池又少又"近亲"**——池里最高频/最易选的组分恰好就是赢家 I1 的成分，
所以连"哪个常见选哪个"都能命中 I1，显不出 agent。

**解法**：把池子加宽，掺入**真实存在、真实高被引、但离题**的材料当干扰（这些卡本就在 S08 池里）：
多孔材料(1391)、制氢(971)、MXene(784)、石墨烯/碳管(731)、光子晶体(715)、LDH(699)、
离子液体电池(597)、超电碳(465)…被引远超质子导体组分(2–212，均为 OpenAlex 真值)。
脚本 `m6_distractor_pool.py`，真函数打分、真被引、不调 LLM、不碰主线。

池规模 **N=752**（477 近亲 + 270 干扰 + 5 真实锚点）。

| 选择器 | 赢家 I1 名次（/752） | top10 里离题干扰占比 |
|---|---|---|
| **真被引加权流行度**（"哪个热门选哪个"） | **第 295 名** ⛔ | **100%** |
| 组分频次流行度（旧代理） | 1 | — |
| **真实生产打分 agent** `audit_candidates` | **第 1 名** ✅ | **0%** |

**这就是想要的分水岭：**
- **流行度（真被引）彻底翻车**：top-10 全被"多孔材料+磷酸/胆碱…"这类**高被引但离题**的配方占据，
  真正的赢家 I1 被挤到 295 名。即"凭热度选材"被引用噪声带跑偏了。
- **agent 稳如泰山**：I1 仍排第 1，top-10 里**零个**干扰项——因为离题材料在 claim pool 里
  没有机理/低温/证据支持，agent 的机理-证据打分**不被被引热度迷惑**。

→ **这个"流行度失败、agent 守住"的差距，才是 agent 价值的可辩护硬证据**——不是"能选中"（§6 笨办法也能），
而是"在现实的、又宽又杂、充满高被引噪声的池子里，仍只挑机理证据扎实的、抗住了热度诱惑"。

**仍要诚实点破的"但是"：**
1. 干扰候选是**我按 claim pool 如实赋了"零质子导体证据"**（因为这些离题材料本就没有 descriptor 声明）——
   这忠实于数据，但也意味着 agent 的胜利部分来自"我没给干扰项编证据"。要堵死这个质疑，
   需要**真 S09 LLM 在宽池上自己生成候选+证据**（要 key、有少量费用，仍非实验）。
2. 近亲内部，I1 领先仍只有 0.0008（一簇 PAAm-淀粉配方 0.8825 紧咬）——agent 能把"质子导体 vs 离题"分得很开，
   但"质子导体内部谁第一"依旧不稳健。
3. 实验真值仍只有 I1/I2 两点，统计功效的天花板没变。

### §7 净结论（回答"怎么解决"）
你的判断对：**就是因为文献又少又针对性太强**，导致笨办法和 agent 答案一样。
**加宽池子 + 掺真实高被引干扰项后，流行度立刻翻车（I1→295 名），而 agent 守住第一（top-10 零干扰）**——
这一步**不用做实验**，已经把 agent 和最强的笨基线拉开了。

## 8. 真 S09 LLM 抗干扰：冻结产物里的原生证据（零成本，无需 key）

§7 用的是"我构造的合成干扰候选"。更强的问题是：**真实的 LLM agent 在发表那次，面对高被引离题文献时，自己是怎么做的？**
脚本 `m6_native_robustness.py` 交叉核对冻结产物（不调 LLM、无需 key）。

**关键事实**：发表那次喂给 S09 的 31 张 S08 卡里，**有 12 张是离题卡**（无质子导体机理声明，`relevance` 标注 "OpenAlex match for…" 的检索噪声），其中被引高达 **1391 / 971 / 784 / 731 / 715 / 699 / 597 / 465**（OpenAlex 真值）。

| 指标 | 数值 |
|---|---|
| S08 池总卡数 | 31 |
| 离题高被引卡（无机理证据） | 12 |
| **真实 agent 采纳离题卡进 family/候选/registry 的数量** | **0 / 12** ✅ |
| 采纳的在题卡 | 7 / 19 |

→ **真实 LLM agent 当年就把这些高被引离题文献全部无视了**（采纳 0），只从在题质子导体卡生成候选。这是发表那次的**原生行为**，比 §7 我手工构造的更可信。

**但必须严格点破的诚实边界（这条决定了"烧 key 重跑"值不值）：**
那 12 张离题卡的"组分-描述符声明"本就是**空的**。S09/S10 的候选生成依赖"组分↔描述符"匹配，所以离题卡"没被选"
**部分是证据约束架构的必然**（结构上就难选），**不能算纯 LLM 的现场智能判断**。也就是说，这是
"**证据约束架构 + LLM**"的**联合**效果，而非 LLM 单独的功劳。

### 8.1 关于"烧 key 重跑真 S09"的结论（重要）
- 若重跑仍用**真实的、无声明的离题卡** → 结果必然仍是 0 采纳 → **等于复现 §8 已有证据，增量≈0**，白烧 key。
- 若要真正考验"LLM 单独能否识破伪装" → 必须给离题卡**伪造**质子导体机理声明再喂进去 → **这违背项目诚实护栏（伪造文献证据），坚决不做**。
- 当前机器**也没有配置 key**（`.env` 仍是占位符）。

→ **结论：在"不伪造证据"的硬约束下，§8 的冻结原生证据已经是这条线能拿到的上限；烧 key 重跑拿不到更强的东西。** 真正能再加分的，是改走"**真实扩大文献检索量**"（重跑 S08 用更宽 query 拉回更多*带真实机理声明*的相关候选源），但那是更大的工程、要 key、且仍受"真实离题文献大多本就无 D1–D7 声明"的限制。

> §8 一句话（**已被 §9 推翻，保留作记录**）：原以为"真 LLM 抗干扰"证据已存在于冻结产物。

### ⚠️ 8.2 重大更正（被 §9 发现推翻）
§8 的"0/12 = LLM 抗干扰"结论**是错的**。见 §9：发表那次 S09 候选生成模式是 `deterministic_from_d4`——

## 9. 根因（比"文献少"深刻）：发表那次 LLM 几乎没参与"发现"

读 S09/S10 源码 + 冻结审计文件，坐实了发表那次（20260607）的真实代码路径：

## 10. 可选加强（非必须）：让 LLM 真正跑一次 S09 生成

若想让消融**正面**支撑"LLM 选择并重组"的能力（把 Pillar 1 从 B+ 往 A− 推一格），
代码已留好开关：`s09_deterministic_from_d4=False`，`run_s09` 就会走 `gateway.chat_json(...)` 真正调 LLM 生成候选。
可做一套消融：**但这是"锦上添花"，不是 Pillar 1 成立的前提**。Pillar 1+2 真正的升 A 正道是"线 A 的 frozen-then-validated 实验验证"（见预注册）。下列消融设计仅供未来加强参考：

**实验 M7（真 LLM 生成 + 消融 + 盲评，用 key 现在就能跑，不做物理实验）：**
1. **真 LLM 生成**：喂入冻结的真实 S08 池（含 12 张高被引离题卡），让 LLM 在证据约束 prompt 下自己生成 S09 候选。
   核心问题：**LLM 能否独立生成出 lotus-starch / 质子导体路线，而不是被人写死？能否不碰离题高被引卡？**
2. **多 seed 稳健性**：temperature 采样 × N 次，看候选是否稳定（而非偶然）。
3. **消融变体**（每个都真调 LLM）：
   - Full（证据约束 prompt + 完整 S08 池）
   - −证据约束（裸 prompt，不给 S08 卡）→ 看它是否生成不可验证/离题候选
   - +强干扰（再灌入更多高被引离题卡）→ 看是否被带偏
   - 下界：随机 / 流行度
4. **客观评测**（缓解 ground truth 少）：
   - LLM 自主候选 vs 硬编码专家 I1–I5 的**重合度**（LLM 能否独立重现专家答案 = 迁移能力的硬证据）
   - **离题污染率**（top-k 里离题候选比例，用 §8 的 12 张离题卡当 negative）
   - 跨 seed 一致性 + 独立 LLM-judge 盲评
5. **诚实落点**：无论 LLM 是否复现 I1，都如实写。复现 → 创新点1从"声称"变"实证"；不复现 → 诚实 null，但仍可写"确定性管线 + LLM 探索的边界"。

**为什么这能到 A−/A**：它把创新点1的根基从"人把答案写死、声称是 AI 发现"（当前，致命）升级为
"**真实 LLM 在证据约束下独立生成，并经多变体消融/盲评量化其增量**"——这正是 NC 系统创新口要求的"agent 增量证据"，
且全程不需物理实验、不伪造证据。

> §9–§10 一句话：**消融上不了 A 的真因，是发表那次 LLM 没真正参与发现（候选硬编码+排序确定性）。
> 解法不是补文献，而是第一次真正让 LLM 跑 S09 生成（key 已具备），用消融+盲评证明它能独立发现/抗干扰。**
